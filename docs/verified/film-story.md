## 2b. 集成中发现的 bug：模板注释被当成内容（已修）

## 2c. 使用者摩擦 F-014：量词白名单 → 开放单位（已改机制）

来源：`films/ghost-jam/docs/friction.md` F-014（幽灵堵车，Sugiyama 2008 环形轨道实验）。
按文档写匹配词 `22辆`，旁白"二十二辆车"FAIL `"二十二"（=22）在 facts.md 里没有条目`；
使用者只能写裸数字 `22` 绕过——单位于是退出了对账范围，门的覆盖面被悄悄缩小。

**判断：换机制，不补表。** 原因：旧逻辑里量词表同时决定三件事——匹配词能不能按数值解析、
旁白里的数带什么单位、单字中文数字算不算数字。表是按交子/唐片调出来的
（`年月日…贯缗文`），补上"辆米公里分钟"之后，下一支片子会缺"兆瓦、基点、光年、集、票"。
`eval-deepsea` 的 `1000米` 也是同一个坑（旁白还空着，所以没炸）。

新机制（`scripts/factcheck.mjs`）：
- 匹配词数字开头 → 解析成 **数值 + 单位**，单位 = 数字后面的全部文字（去空白），**不查表**。
  旁白里的数要值相等，且后文（跳过空白和"多/余/来"）以这个单位开头。
- 单位因此是片子自己声明的：facts.md 里写过 `三分钟`，"分钟"就成了本片的单位。
- 量词表只剩一个作用：给**单个**中文数字字（三、五、十、两）做闸，避免"十分""四周"误报。
  闸 = 常用量词表 ∪ 本片匹配词里声明过的单位。多位中文数字和阿拉伯数字不过闸，一律抽。
- 以单独的"一"开头的词（`一圈路` `一辆`）、单位里又夹数字的（`两年一界` `8f21ac0b`）仍按原文匹配，
  和旁白侧"单独的一不当数字"保持一致。

**代价（会不会把该抓的放过）**：逐条看过，旧逻辑能抓的这里都还抓（`二月`≠`两年`、`千年`≠`1000文` 回归保留）。
新放过的只有一类：单位按前缀比较，`30公里` 同时放过"三十公里每小时"和"三十公里外"——写多长由作者定。
旧逻辑本来就放过、现在**改成在"提示"里点名**而不是静默的有两类：裸数字匹配词（`22` 放过"二十二米"）、
单字中文数字后接谁都没登记的量词（"三头大象"）。

## 2e. cnToNumber 不认口语省略末位单位（film-narration 交叉校验发现，已修）

`三百五` 得 305（应 350）、`两千三` 得 2003、`一万二` 得 10002、`四万四` 得 40004。
数值相等是 2c 那套单位匹配的地基，这里错了就是双向的：放过错数，或把对的判成错。
规则：紧跟在 百/千/万/亿 后、中间没有"零"的单个数字是下一级单位的系数；有"零"才是末位。

先写用例再改：`selftest.mjs` 的 `cn-parse` 直接从 factcheck.mjs 抽出 `CN_*` 和 `cnToNumber` 求值，26 个输入。
改前 **15/26**——11 个省略写法全红（协调方给的 4 个 + 同族 `两万五 一千二百三 十五万八 十万八 三亿五 两千三百五 三百五万`），
15 个对照（`三百零五 三百五十 两千三百 一百零五 二十二 十万 三亿五千万 一万零五百 三百五十万 五十五 十 一〇二三 六一八 一百二十五万 二百八十九`）全绿。
改后 26/26。端到端：`cn-elided-unit`（"三百五米"命中 `350米`）改前 exit 1、改后 0；
`red-cn-elided`（"三百五米"对 `305米`）改前 **exit 0 放过**、改后 exit 1，报 `"三百五米"（=350）在 facts.md 里没有条目`。
整套 32/32。五支片子退出码、错误、警告的条目与上一轮相同。

`三百五万` 我按同一规则读成 350 万。这个写法本身不规范，有人会读成 305 万——旁白里别这么写，写"三百五十万"。

  做换算要维护单位表，正是这次去掉的那种无限缺的表。
- **单位按前缀比较**：`30公里` 分不出速度和距离，`3分` 会命中"三分钟"/"三分之一"。写长一点能收紧，脚本不替你判断。

- **单字中文数字 + 没人登记的量词不对账**（"三头大象"），只在提示里列出。
- **单独的"一"永远不当数字**：要核"只有一辆车停下"这种以 1 为断言的数，只能靠原文匹配词 `一辆`。

- 中文数字解析未覆盖：分数（"三分之一"）、"成"（"三成"会抽出 3+成，需要匹配词写 `三成`）、

### 三个问题

**1. 两次产出的机制是否互不相同、也不同于网格？**

是。交子 = 力（重力），TLS = 文字（可读性），分属变量类表里的不同类，和网格无关。

但要老实说：**两次我的第一反应都是容器**——交子是地图扩散/账本格子，TLS 是时序图。

那就是 demo-grid 的同一条路。这一步是整个 skill 里改变结论最多的一步。

**2. 流程里哪一步是仪式？**

- **"能一句话说完"作为判据是仪式。** 两个主题 9 个候选，没有一个因为它被淘汰——什么都能写成一句话。
  已改：降级为"写法"（固定句式），不再列为判据。四条判据变成三刀。
- **每个候选都填"实现成本"是仪式。** 两次选定的都不是最便宜的，这一栏没改变任何结论。
  但它对 demo-grid 会改变结论（网格就是最便宜的）。已改：只在"选定的恰好最便宜"时要写一句理由。
- **凑候选数是仪式。** 两题的第 3、4 个候选（交子 D、TLS C/D）都是一刀就倒的弱候选，
  我写它们时已经知道会倒。已改：SKILL.md 不规定数量，停止条件是"再想一个只会更弱"，
  并明确说"不要为了表格好看造靶子"。
- **不是仪式的**：候选 0（见上）；刀 3 写旁白（它让交子 A 和 C 拉开差距，也让 TLS A 的"字幕本身被加密"这个想法出现——那是试写旁白时才冒出来的）；
  去名词（见下）。

**3. "换主题就不成立"好不好用？**

好用，是最锋利的一刀，但**原样直接用会被糊弄**，实测踩到三个坑，SKILL.md 已按此改：

1. **贴名词就能骗过。** "108 坊的棋盘逐格点亮"——问"换主题还成立吗"，答"不成立，只有长安有 108 坊"。
   网格靠一个名词假装专属。（唐片旧 shotlist 的第二镜正是"坊市棋盘"，墨色片里也溜进了网格。）
   修正：**先去名词**，只对骨架做换题。
2. **对照题自己挑会挑套不上的。** 修正：三个**固定**对照题（菜谱 / 融资轮次 / 一个人的一天），不许换。
3. **同类迁移被误判为容器。** 墨色兴衰对宋、罗马也成立；重力对任何货币题都成立。这不是容器。
   修正：只有**跨不相干类**都成立才算容器；并把真正的判点放在"因为"子句——
   理由来自主题自身的因果 = 机制，理由来自渲染（清楚、好排、好实现、熟悉）= 容器。

所以判据的最终形态没有换，是给它加了操作步骤：**去名词 → 固定对照题 → 看"因为"的来源**。

它查不到的：**陈词滥调**。DH 颜料混合三刀全过，但观众见过一百遍——用户骂的"没新意"它防不住。
没有加第四刀（"新意"无法判定，加了只会变成新教条），只在 references/mechanism.md 里
把"教科书比喻"列为一项**代价**：清楚、零学习成本，代价是没有记忆点。

## C. 第二轮：ghost-jam 实跑反馈（friction F-017/018/019/021/026/035、F-010/011/012）

### C1. 问题本身：断言验的是意图，不是画面

原因不在脚本 bug，在设计：`claims` 只能对 `curves`（手钉曲线、线性插值）求值。ghost-jam 的承重变量
（灯数、停车数、灯团位置）全是仿真涌现的，作者只能写一组"意图曲线"让脚本过——验的是意图自洽。

改法（设计理由见 SKILL.md 第 5 步"断言验的是意图还是画面"）：
- `curves.<名>.source` ∈ `curve`（默认）/ `scene` / `pixels`。声明在**变量**上而不是每条断言上：
  "灯数是仿真推出的"是变量的性质，按断言写会漏标。`scene`/`pixels` 的 `keys` 可省，写了就当意图验，输出标 `[意图]`。
- 分镜阶段仍然无浏览器、只用标准库：画面实测放在 film-critique `check.mjs`（有浏览器的自检阶段），
  本脚本只加两个接口：`--plan`（输出解析后的区间/来源/像素规格）、`--verdict SAMPLES.json`（用同一个 `eval_claim` 判）。
  锚点解析和判定语义各只有一份；放进 check.mjs 另写一份 JS，就是仓库 `docs/INTEGRATION.md` 第 3 条那种"两边读法不一致"。
- `rising`/`falling` 只比端点这个洞顺手标出来：区间头/尾 ≥20% 时长（且 ≥0.3s）值没动 → 警告（不判失败）。

## F. 设计来由：旧 skill 的警告为什么没起作用

（原在 SKILL.md 开头，下沉到这里。）旧的 `motion-reference` 开头就警告过"默认片"，还是失败了，
原因决定了本 skill 的形状：

1. **警告描述的是长相，默认是一个过程。** 它列了"渐变+居中标题+全员淡入+结尾 logo"。
   模型躲开了这四个长相，换了下一个最好写的（网格）。默认不是某种画面，
   是"挑实现成本最低的那个"这个动作。所以本 skill 不列默认长相，
   而是让作者**为这个主题写出它自己的默认画法**，再拿判据去砍它（第 2 步的候选 0）。
2. **警告没有落成产物。** 一段话挂在文件顶部，流程里没有任何一步要求写下
   "为什么不用别的"。本 skill 的机制选择留痕在 `docs/mechanism.md`，下游能查。
3. **示例比警告更有约束力。** 旧 `motion-reel` 的分镜示例就是"48 块错峰弹入拼成网格"，
   旧 spec 模板要求"把故事拆成 8–12 个 UI 状态"——这本身就是容器。
   模型抄示例，不抄警告。所以本 skill 的模板里**没有任何具体画面**，只有占位符；
   具体案例只出现在 `references/mechanism.md`，并且正反成对。
4. **自检按禁令打分，从不问机制。** demo-grid 的 review_log 修了"网格靠淡出退场""停留 1.5 秒"，
   没有一行问"该不该是网格"。旧家规"每 2–4 秒要有新东西"还在奖励网格——几十个格子错峰弹入，
   便宜地刷满了"变化密度"。规则让复盘看起来很忙，真问题原封不动。
   所以本 skill 把"机制是否成立"变成 film-critique 可以打分的对象（写进 style_guide）。

发散留痕（讲法、视觉方向、近作对照）后来改成片子在 film.json `checks.divergence` 声明了才查
（仓库 `docs/INTEGRATION.md` 第 43 条），原先"等第一支片子过门后把讲法整节缺失升成失败"的计划（第 27 条）随之不再执行。

## 没解决的问题

1. **两个合格机制之间怎么选**，判据不管。现在靠"哪个能演出核心变量的完整形状"，这是我的经验，不是判据。
2. **新意**防不住（见问题 3）。
3. **这次验证是我自己跑自己的流程**，我写判据时已经知道要防网格，有自证偏差。
   真正的检验是一个没读过这份 VERIFIED.md 的模型拿到新主题，是否仍会写出候选 0 并杀掉它。没测。
4. **构图与形似**只能靠关键帧剪影描述 + 人眼静帧。如果没人写剪影描述，脸照样会出现。
5. **事实**：交子、TLS 两题的事实未经 film-research 核对；交子 A 机制依赖"铁钱笨重是交子起因"这条，
   进片前必须核实。
6. ~~脚手架骨架没有 json 块~~：已统一（F-019）。但脚手架生成的 shotlist 若仍写 `pads.lead/tail` + `vo_offset`，
   现在会被交叉检查打 `[注]`；film.json 是否由脚手架写入 `narrationTail`，归 film-production，没核。
7. **改钉点测试靠自觉**：作者不标 `source`、也不写 probe 时，分镜阶段仍然全绿。机器只在 check.mjs 那边
   用"场景带 film-physics 运行时"做启发式 LOOK；不经 film-physics 的涌现（自写迭代、数据驱动、第三方库）抓不到。
8. **probe 和画面可以分歧**：probe 只证明场景算出的状态，不证明画了。ghost-jam s3 末尾 8.10s probe=0 盏灯、
   画面上 140 个饱和红像素。像素断言能补，但颜色签名要唯一，且贵（约 0.23s/帧）。
9. **趋势断言**仍只比端点；平台提醒是 LOOK 不是 FAIL。"正在发生"类旁白要靠作者补水平断言。
10. **场景自己又加一遍留白**（与 narration.js 平移叠加）：本脚本看不到场景，抓不到；film-critique 那边有 MARKS 或 scene/pixels 断言时间接能抓，见它的 VERIFIED。
11. 像素断言在逐帧截图上量，没有经过运动模糊（`sub>1` 时成片是多次采样的平均）和 H.264；ghost-jam 是 sub=1，sub>1 的片子没测。
12. **`source: anchor`**（第八轮）：本脚本只验写法（`anchor.name` 非空、`stat` ∈ cx/cy/w/h）；没用 anchor 的片子
    `--plan` 输出与改前逐字节相同（ghost-jam / demo-tls 对比过），正常输出逐字相同。锚点名是否真被登记要到 check.mjs 才知道。
13. **讲法"整节没有"只警告**（D1）：仓库里还没有一支片子做过讲法发散，直接判失败会让样板变红。要更严的片子自己声明（见 F 节末尾）。
14. **门只查留痕，不查真不同。** 两个候选只换了颜色、写得像两个方向，门照样绿；"至少差两个维度"是文档里的判据，脚本不查。
15. **siblings.png 的代表性取决于 poster 选在哪一刻**：poster 多是片头帧。weiqi-intro 的 poster 是历史段空棋盘，看不到它的签名"气泡透镜"；唐片的 poster 只有一个"唐"字。没有改成取 contact 拼图或 MARKS 中点，因为那要对每支片子渲多帧、而且仍是猜。
16. **格式宽容有边界**：候选要有编号（0 / A / 一…）且写在标题、粗体行或"- **…**"列表项上；纯正文段落写的候选认不出来。
    样板和两种模板写法都测过，别的写法没测。
17. **`role` 只数不判**：标得全是 `context` 也照样绿；"证据镜头是否真让断言在画面上成立"仍要人看或靠 `claims`。
    功能统计按 shotlist 的镜头区间算，不知道画面里实际画了什么。

# 从 skill 文档移出的实测叙事（2026-10 瘦身）

## 1. 两种失败的原话（原 SKILL.md 开头）

1. **记忆冒充事实。** 唐代片的国运曲线 11 个"年份-数值"点全是拍脑袋，没人查——它不在旁白里，也不像"事实"。
2. **管线的默认值决定画面。** 两支片子都画了网格：不是因为适合主题，是因为最好写。用户原话："一上来就是画什么格子，你就只会这一招吗"。

## 2. 调研：记忆快照与记忆错误的实例（原 SKILL.md 第 0 步、fact-check.md §3–4、tools.md）

- 记忆快照的代价约两分钟。交子主题 8 条记忆里 3 条错、2 条有不知道的分歧（明细见本文件第一部分 §1）；
  幽灵堵车 11 条里 2 条错，都不是数字本身，而是实验地点和年份归属。
- 记忆错误类型的原始实例：

| 类型 | 实例 |
|---|---|
| 制度细节被后期版本覆盖 | 记成"三年一界"；实际起初两年一界，1199 年后才是三年 |
| 数值对、归属错 | 1,256,340 记成"首界发行额"，有学者说是第二界 |
| 不知道存在第二种说法 | 改钱引记得 1105，不知道还有 1107 说 |
| "世界第一"不带限定 | "世界最早纸币"——吉尼斯算的是更早的私交子 |
| 精度错 | 准备金率"约 28%"，实为 28.65%（且是铁钱，不是铜钱） |
| 地点张冠李戴（幽灵堵车） | 实验地点记成名古屋巨蛋；论文致谢写的是中日本汽车短期大学的场地 |
| 日期的归属错（幽灵堵车） | "2008 年做的实验"——2008 是发表年，投稿在 2007-11，实验日期论文没给 |

  对应的 `否决` 匹配词：`名古屋巨蛋`、`2008年做`。
- 转录误差：Wikipedia 写 1,255,340，两位中文学者都是 1,256,340，差恰好 1000，按转录误差处理。
- 精度上限的原始例子：幽灵堵车论文只给"开始后 3 分钟的快照里堵已成形"，没给堵第一次出现的时刻；
  片子想说"三分钟就堵了"超出了来源。处理：状态 `已核` + `精度上限:`，片中措辞"没过几分钟"，匹配词 `几分钟`，另列 `否决`（`三分钟就堵`）。
- WebSearch 摘要混入搜索模型自己的记忆（2026-10，搜"交子改钱引 崇宁四年"）：摘要里出现
  "据我所知，机构改名通常被记为崇宁四年，但这一说法并未得到本次搜索的支持"，这句话没有任何来源。

## 3. 讲法 / 视觉方向 / 近作对照的来历（原 divergence.md 开头与 §0）

- 正面样板 `films/weiqi-intro/docs/style_guide.md`（"视觉概念：三个方向，选了一个""和前两支片子拉开的距离"）是编排方在任务说明里手动要求的，
  套件当时没要求；用户评价"还行"；它之前的 ghost-jam、demo-tls 都没做。divergence.md 把这个做法提炼成方法。
- 方法借自 Anthropic 的 frontend-design（Design Thinking：Purpose / Tone / Differentiation，*intentionality, not intensity*，"跨次生成不要收敛"）
  和 canvas-design（先给美学方向起名、写宣言）。吸收方法、不依赖它们，理由在 `docs/oss-borrowings.md` 第 6 节。
- 改写的地方：frontend-design 附带的禁令清单（某几种字体、某种渐变配色）没有搬进套件——那只是"上一代模型最常收敛到的长相"，
  换一代模型或题材就过期，且会像旧家规一样把人推向"清单外最顺手的下一个"。所以方法改成"不规定选什么，只要求知道自己在重复什么"。
  "跨次生成不要收敛"靠自觉做不到（模型不记得上一次生成），所以变成了工具 `siblings.mjs` 和一条记录（近作对照）。
- 案例：weiqi-intro 的"棋子的视角"落选，输在第一人称里演不出"两颗子共享气"（brief 点名的那一条）；demo-tls 用等宽字是有意重复，因为画面主体就是 HTTP 明文。

## 4. 唐片分镜层四个问题的原因与修法（原 mechanism.md §6）

机制（墨的浓度 = 国运，完整度 = 疆域，宫阙从墨里挖出）本身过三刀，问题全在分镜层：

- **三座殿宇读成一张脸**：`carveHalls` 布局是中下一个大殿（宽 0.30），左上、右上各一个小殿（宽 0.175），倒品字 = 两眼一嘴。
  静帧 `films/tang-dynasty/out/still-10p1s.png`（七四零年，开元顶点）：两个殿顶是眼睛、下方大殿是口鼻、深色墨团是头、锯齿边缘是毛发。
- **安史之乱 0.11 秒**：`yearAt()` 在 s3 开口（755）到 s5 开口（907）之间按年线性，8.366s / 152 年 × 2 年 = 0.110s；
  `check_shotlist.py` 实测 0.111s。修法钉点 `["s3@裂痕",755],["s3.end",757]`，两年拿到 2.217s。
- **"只剩一点余墨"时画面已空**：`FORTUNE[907]=0`，907 钉在 s5 开口（19.526s），旁白念到 23.706s。

## 5. `curves.source` 的实测对照（原 claims.md）

- ghost-jam（22 辆车跟车仿真）：check_shotlist 全绿，真实仿真里 s3 末尾灯全灭 0.07s、s4"一辆传一辆"开头 0.6–0.9s 一盏灯都没有。
- 代价（ghost-jam 1920×1080）：`scene` 708 帧一次取完 0.02s；`pixels` 截图 187ms + 数像素 44ms ≈ 0.23s/帧，6 条断言 450 帧 83s；
  `anchor` 只 draw 不截图 286 帧 4.7s（16ms/帧），再倒序一遍查纯函数。
- `anchor` 与 `pixels` 并行（s6 同一区间、同 286 帧）：黄车 r=1.000、恒差 7px（框中心 vs 黄色像素质心）；
  灯团端点位移一致（+0.428 vs +0.417），但逐帧方向只有 63% 一致——成组锚点的外包框中心随成员进出团跳变，还算进了出画的车。
- probe 与像素分歧：s3 末尾 8.10s probe 说 0 盏灯（亮度 >0.5 才算），画面上还有 140 个饱和红像素（绘制从亮度 0.01 起就画）。

## 7. 旧家规禁令逐条改写（原 vocabulary.md §4）

旧仓库根 `CLAUDE.md` 里的"画面禁令/正令"。每条背后都有真实意图，但写成法律后把模型推向了"满足所有规则的最便宜画法"——网格。
改写后的手法与代价已并入 vocabulary.md 的转场 / 节奏 / 构图三张表，这张对照表留作来历：

| 旧条文 | 真实意图 | 改写为"手法 + 代价" |
|---|---|---|
| 禁止渐变背景上的居中标题 | 防"默认片"——没有想法时的长相 | 渐变+居中标题：零成本、零记忆点，适合片尾署名或需要极度中性的场合。它出现在主体位置时，通常说明机制还没找到 |
| 所有元素都淡入（要变形不要淡入） | 让元素之间有因果，而不是各自出现 | 淡入：成本低、无因果、无记忆点，适合衬托性的次要元素。主体元素若都淡入，片子读成一组独立幻灯片 |
| 禁止停在四角的标签、画框边框 | 防 UI 模板感 | 见构图表"四角标签""画中画/边框"——数据片里它们是正当语汇 |
| 禁止 UI 发光、辉光 | 防廉价科技感 | 辉光：一秒钟就"像科技"，代价是像所有科技片；霓虹/赛博题材里它是材质本身 |
| 禁止通用粒子爆散 | 防无意义的热闹 | 粒子爆散：高能量、零语义。粒子若是机制的一部分（墨点飞溅=碎裂）就不是"通用"的 |
| 任何一拍什么都没发生 | 防死拍 | 见节奏"静止留白"：代价取决于画面里还有没有缓慢变化的东西 |
| 超过 1 秒的静止停留 | 同上 | 同上。重要时刻后的停留恰恰是让它落地的方法；1 秒是一个片种的口味，不是物理 |
| 两款字体、一个强调色 | 防视觉噪声 | 字体和颜色的数量是本片 style_guide 的决定。限制越少，越需要机制来提供统一感 |
| 每 2–4 秒必须有新东西 | 防注意力流失 | 见节奏"固定变化密度"：它奖励廉价变化，是网格片能"达标"的原因 |
| 镜头一次只做一个动作 | 防眼睛不知道看哪 | 单动作镜头：清楚；代价是慢。多个动作若都由同一个机制驱动，观众读成一个动作 |
| 场景之间靠共享元素交棒，不靠切和叠化 | 让片子连贯 | 见转场表。硬切用在主题断点上比任何交棒都有力 |
| 落地要有一点回弹 | 让物体有质量感 | 回弹：物理感、俏皮；代价是轻。墨、烟、光这类无质量的材料回弹会显得假 |
| 首帧 = 末帧 | 循环播放平台 | 本片要求循环时是技术约束（seamcheck 第 3 门）；不循环的片子没必要 |
