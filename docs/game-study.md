# 游戏拆解：一个单文件 3D 射击游戏为什么好看

调研记录，不随 skill 安装。对象是一个由模型一次生成的单文件 WebGL 第一人称射击游戏（约 6200 行，打包了 three.js，没有任何外部贴图、模型和音频文件）。
三个子代理分区只读拆解，下面是它们的原始报告，行号指那个游戏文件（仓库根 `fps-game.html`，已 gitignore 不入库；1,423,569 字节，sha256 前缀 `f34e6debbfa7526b`，行号只对这一份成立）。提炼进套件的部分见各 skill 的 references 与 `docs/verified/`。

状态注（2026-11-12）：下文“已有/缺”的判断是迁移前的研究快照；本轮实装范围、验证和保留边界见 `docs/INTEGRATION.md` 的“游戏技法迁入”节。

读法：每节先是技法清单（做了什么、怎么做、为什么好看、迁移到 seek(t) 要改什么），最后是方法论。里面的色值、调色参数是那个游戏自己的审美，进 skill 时只作为带代价的配方，不是默认值。

# 一、天空、大气与后期管线（第 4180–4800 行）

下面是第 4180–4800 行的分析。行号指文件行；第 4180 和 4733 两行是超长行，用"行号@字符偏移"标位置。压缩常量已对回 three.js 的值：`ys=NoToneMapping`、`xc=ACESFilmic`、`js=HalfFloat`、`yi=UnsignedByte`、`as=Float`、`J0=RedFormat`、`Zt=Linear`、`Gn=Nearest`。

## 一、技法清单（按重要性排序）

#### 1. 全局只有一套"太阳 + 天空调色板"，所有东西都从它取色
- **位置**：4180@51450。`Mn={dir:(.916,.225,.331), color:(1,.72,.42), intensity:9}`，`en={zenith:(.055,.085,.13), horizon:(.95,.55,.28), horizonAway:(.16,.22,.3), fog:(.42,.47,.52)}`。GLSL 片段 `Ng`（4186–4194）定义了 `skyToSun()` 和 `horizonColor()`。
- **做法**：
  - 太阳仰角约 13°，是低角度的金色时刻。
  - `horizonColor(d)`：`ts = dot(d.xz 归一, sun.xz 归一)*.5+.5`，即背阳 0 到向阳 1。颜色分三层混合：
    - 背阳色 `uHorAway`；
    - `mix` 到 `uHorAway*1.25+(.05,.03,.02)`，权重 `smoothstep(.2,.75,ts)`；
    - 再 `mix` 到 `uHor*(1.9,1.55,1.2)`，权重 `ts^6`；
    - 最后 `mix` 到 `(1,.6,.24)*3.4`，权重 `ts^34`。
  - 同一段 `Ng` 被 `#include` 进两处：天空（4202）和体积雾远景（4395）。`en.fog` 用作雾的环境光（4733@≈7400 `uAmb=en.fog*0.2`）。环境贴图 PMREM 也从同一个天空生成。区域外 1174022 处还能看到别的模块用 `en.zenith*.6+en.horizonAway*.5+en.fog*.25` 拼环境色。
- **为什么好看**：远景雾、天空、反射、阴影里的环境光颜色同源，画面"色相统一"。最常见的廉价感就是雾是灰的、天是蓝的、反射是另一张 HDRI，这里从根上避免了。
- **迁移**：纯数据，无状态。建议在套件里做成一个"光照预设对象"：太阳方向、色、强度加 3–4 个天空色，供天空、雾、环境光、阴影共用。目前缺。
- **成本**：约 20 行，几乎零开销。

#### 2. 线性 HDR 场景，后期全程线性，只在调色那一步色调映射一次
- **位置**：4733@≈14700 函数 `j()`：`renderer.toneMapping = NoToneMapping`，场景渲染到 `m = RGBA HalfFloat` 目标，带深度纹理，`samples = quality.msaa`（0/2/4）。sRGB 编码在 grade 末尾手写 `toSRGB()`（4629、4700）。所有后期材质都设 `toneMapped:false`、`NoBlending`。
- 完整顺序见第二节的总图。
- **为什么好看**：泛光、雾、运动模糊都在线性能量域里叠加，高光叠加不会发灰发脏；色调映射之后再做 FXAA、锐化、颗粒，这些操作作用在显示值上，强度可控。
- **迁移**：套件已有这套结构（多 pass FBO）。要核对的一点是：泛光、雾、色差是否都在色调映射之前。

#### 3. 程序化天空与云层（SALTLINE_SKY，4196–4283）
- **几何**：2×2×2 立方体，`BackSide`。顶点着色器写 `vDir=position; gl_Position = (P*mat3(V)*pos).xyww`（4285），也就是只取相机旋转、深度钉在远平面。`depthWrite:false`、`renderOrder:-1000`、`fog:false`、`toneMapped:false`。输出 HDR 线性值。
- **噪声底**：`Oy()`（4195）生成 256² RGBA8 白噪声纹理，用 xorshift，种子 `2654435769`，完全确定。`n2()` 是对这张纹理做 smoothstep 插值的值噪声。`fbm5`、`fbm3` 每个八度用 `mat2(1.6,1.2,-1.2,1.6)`（旋转约 36.87°、缩放 2）再加 17.3 偏移，结果除以几何级数之和归一化（4182–4184）。
- **晴空**（4212–4217）：
  - 地平线色 `hc`；
  - 中段色 `mix((.15,.24,.36),(.72,.5,.34), ts^3)`，权重 `smoothstep(0,.17,h)`；
  - 天顶 `(.085,.145,.24)`，权重 `smoothstep(.1,.5,h)`。注意 uniform `uZen` 声明了但没用。
  - 日晕（Mie）：`sunCol*(1,.86,.68)*(s^8*.14 + s^64*.55 + s^600*2.2 + s^6000*14)`，其中 `s=max(dot(d,sun),0)`。四个幂次从宽晕叠到窄核。
- **云层**（4220–4241）：
  - 平面投影 `cuv = d.xz/(h+0.10)*(0.62,0.95)`，各向异性拉成东西向的云卷。风 `(-0.012,0.004)*uTime`。
  - 域扭曲：`warp=fbm3(q*.45+7.1)`，`qq=q+(warp-.5)*1.3`，`dens=fbm5(qq)`。
  - 脊状细节：`ridg = 1-|2fbm3(qq*3.1+5)-1|`，乘 `smoothstep(.03,.25,h)`，靠近地平线淡出防锯齿。
  - 大尺度起伏 `big=n2(q*.19+3.7)`。`body=dens*.74+big*.36`，覆盖度 `cov=smoothstep(.31,.50,body)`。
  - 构图控制：云底边缘仰角 `edge=mix(.03,.285,ts^1.7)`，向阳方向留出一条燃烧的缝。边缘用噪声 `rag` 撕碎。
  - 太阳周围强制开洞：`hole=smoothstep(.972,.9985,mu+…)`，`cov*=1-.93*hole`，注释写"太阳永远不被实心云挡住"。
  - 缝里飘碎云 scud。
- **云的受光**（4244–4262）：
  - 自阴影用"朝太阳方向的密度差"近似：`densS=fbm5(qq+sunXZ*0.22)`，`relief=clamp((dens-densS)*4.5+.5)`。
  - 冷色基底：`mix((.155,.195,.255),(.03,.042,.064),thick)*(0.55+0.9*relief²)`，薄处透冷光 `+(.07,.1,.15)*(1-thick)^3`。
  - 暖色侧光：`uHor*(1.3,.66,.4)*nearSun*(0.05+2.2*relief³)*1.15`，其中 `nearSun=ts^5*exp(-4.5*max(h-edge,0))*.9+s^7*.9`。
  - 边缘燃烧亮边：`rim=cov(1-cov)*4`，乘 `sunCol*ts^4`。
  - 云内片状闪电：`uFlash`、`uFlashDir`。
  - 云的大气透视：`mix(cloud, hc*.55+cloud*.45, exp(-11h))`。
- **太阳圆盘**：`smoothstep(.999905,.999955,mu)*110*veil*(1-uEnv)`，大约 0.5–0.8° 视径，强度 110。HDR 值足够大，后面的泛光、眩光才"烧"得起来。
- **地平线以下**：海雾和地面反弹色。
- **环境捕获模式 uEnv=1**：去掉太阳圆盘（直射光已经是太阳），下半球改成暗灰，整体 `min(col,6)` 防萤火虫（4280）。
- **为什么好看**：天空有亮度层次（地平线比天顶亮 10 倍以上）、有方向性（向阳暖、背阳冷）、云有受光体积感（冷暗主体 + 暖色侧光 + 亮边），并且 HDR 太阳给后期链提供了真实的高光源。
- **迁移**：`uTime` 只驱动风，是 t 的纯函数，可直接用。噪声纹理用固定种子，确定。离线可以把 `fbm5` 提到 6–7 个八度，把 `densS` 自阴影改成 3–4 步小步进，质量更好。这个面板不分天空/云层的话，套件里整块缺。
- **成本**：GLSL 约 90 行加 JS 约 30 行。每像素约 20 次纹理采样，1080p GPU 上约 0.3 ms（估计）。

#### 4. 环境光 / IBL 由程序化天空生成 PMREM；室内另做探针
- **位置**：`Vy()`（4285 末）、`K()`（4733@≈20500）。
- **做法**：
  - 克隆天空材质并设 `uEnv=1`，单独放进一个场景，`new PMREMGenerator(r).fromScene(scene, sigma 0, near .1, far 100)`，结果赋给 `scene.environment`，`environmentIntensity = 2`。
  - 室内：在 interiorBox 中心、离地 `min(2.4, 高×0.4)` 处放 CubeCamera（128²、HalfFloat、只渲世界层），拍真实场景再 `pmrem.fromCubemap`。只赋给 `userData.interior` 的材质，强度 1；玩家在室内时，枪模也切到这张贴图。
  - 枪模环境强度另乘 `viewFill 1.35`。
- **为什么好看**：金属和粗糙表面的反射跟天空一致，没有"贴了一张无关 HDRI"的违和感。室内不会被室外天空照亮成发光盒子。太阳只算一次：天空图里没有太阳盘，太阳由平行光加阴影负责，所以不会出现双重高光或漏光。
- **迁移**：只在初始化时生成一次，确定。拍摄时 `uTime=0`；云在动时环境贴图不动，误差可以忽略。离线可以每个镜头或每 N 秒重新生成。缺（套件没有 HDR 环境加载器，但用这招根本不需要它）。
- **成本**：约 20 行。PMREM 生成一次十几毫秒；软件渲染下可能要秒级（估计）。

#### 5. 半分辨率光线步进体积雾 / 体积光，并做解析远景延续（4389–4444）
- **输入**：半分辨率线性深度 `tDepthHalf`、太阳阴影图 `tShadow` 与 `uShadowMatrix`、`uSunRad = sunColor*9*0.85`、`uAmb = en.fog*0.2*(1+thunder*1.5)`。
- **步进**：
  - `VOL_STEPS` 由画质档决定：test 10、low 12、medium 16、high 24、ultra 40，最少 6。
  - 步长分布 `t1=maxD*f*(0.35+0.65f)`，近处更密。每像素用 IGN 抖动采样位置：`p = cam + rd*(tPrev + ds*j)`。
  - `maxD = min(距离, 170m)`；天空像素只走 `170*0.55 m`。
- **介质**：`σ = 0.0034 /m * shape(y)`，`shape(h) = 0.30+0.70*exp(-h/5.5)`，即高度雾，标高 5.5 m，带 30% 的底。室内盒子里 `σ*(1+6)`，营造"有灰的棚子"。
- **相位函数**：双瓣 Henyey-Greenstein，`min(HG(μ,.78)*.55 + HG(μ,.25)*.45, 1.15)`。紧瓣给逆光金辉，宽瓣让侧光下的光柱也能看见。
- **太阳可见性**：每步查一次阴影图，`step(sc.z-0.0006, unpackRGBA(depth))`。
- **散射累积**：`src = sunRad*ph*sh*nearW + amb*(0.4+0.6sh)`，室内环境光 ×0.22。`acc += T*src*(1-Ti)`，`T *= Ti=exp(-σds)`。其中 `(1-Ti)` 是能量守恒的分段积分。
- **美术权重**：`nearW = mix(2.3, 0.55, smoothstep(4,85,t))`，近处光柱读得清楚，远处只是克制的薄纱。注释里明确写了 "art direction"。
- **远景解析延续**（4435–4442）：几何体超过 170 m 时，用梯形积分 `τ = σ*0.42*(dist-170)*avg(shape(h1),shape(h2))`，散射色取 `horizonColor(rd)*0.5 + amb*0.6`。这就是"雾和天空颜色一致"的连接点：远处的船和吊机会融进它所在方向的地平线色。
- **输出与后处理**：`vec4(inscatter, T)` 写入半分辨率 HalfFloat，再做一次 7-tap 深度感知可分离模糊（`BLUR_TOL 0.30`）。合成公式 `col = col*T + inscatter`。
- **为什么好看**：有阴影遮挡的真实体积光柱、高度雾、空气透视三合一，解决"平光"和"没有空间深度"。
- **迁移**：
  - 无帧间状态。IGN 是静态逐像素噪声，靠模糊抹平。
  - 离线可以全分辨率、64–128 步，阴影查找做 PCF，甚至去掉模糊。
  - 套件现有的"径向模糊体积光"是屏幕空间假光柱，**没有**高度雾和阴影步进。这块缺。
- **成本**：GLSL 约 60 行，JS 喂参约 15 行。半分辨率 16 步在 1080p GPU 上约 0.5–1 ms；SwiftShader 下 40 步可能每帧数百毫秒到秒级（估计）。

#### 6. 曝光：手动曝光 × 受限自动曝光
- **测光**（`eA`，4552–4577）：
  - 在泛光链最小一级 `down[5]` 上取 7×5 网格，约等于 1/128 分辨率。
  - 中心加权 `w = 1-0.75*smoothstep(.1,.55,|c|)`。
  - 对数平均 `avg = exp(Σw·ln(luma)/Σw)`，钳到 `[0.002, 40]`。
- **曝光公式**（`Og`，4344–4345）：`exposure = uExposure * mix(1, clamp((key/avg)^0.85, 0.6, 2.0), uAuto)`，`key = 0.12`。指数 0.85 表示只做部分补偿，暗场景仍然偏暗；范围只有 ±1 stop。
- **时间适应**：1×1 HalfFloat 双缓冲 ping-pong，`rate = 1-exp(-dt/1.5s)`。前 2 帧 rate 取 1；`shot` 截图模式下取 0.6。
- **太阳可见度**也存在同一个纹理的 g 通道：太阳屏幕位置周围 12 个 Vogel 采样点，统计深度≥0.99999（是天空）的比例，`τ = 0.12 s`。
- **其他用途**：泛光阈值、AO 的"受光"判断也读同一个曝光值。
- **迁移**（要改）：
  - 方案 A：每个镜头固定曝光，最简单。
  - 方案 B：两遍渲染。第一遍低分辨率渲全片，把每帧的 avg 存进 JSON；对 t 做因果指数滤波，生成 `exposure(t)` 表；第二遍按表渲染。
  - 太阳可见度直接取当帧值，不做平滑。
  - 套件里没有自动曝光，缺。
- **成本**：约 40 行，开销可以忽略。

#### 7. 泛光：能量守恒的 mip 链，无阈值，首级做 Karis 平均
- **下采样**（`J6`，4511–4529）：6 级，`down[0]` 是半分辨率，依次到 1/64。采用 COD 式 13-tap：中心 0.125、四角 0.03125、四边 0.0625、内菱形 0.125。采样值先钳到 `[0,400]`。
  - 只有第一级用部分 Karis 平均：5 个 2×2 组，权重 `1/(1+luma*0.08)`，分配比例 0.125×4 + 0.5。系数 0.08 很温和，压住萤火虫但不把太阳压死。
- **上采样**（`K6`）：3×3 tent（4/2/1 权重 /16），`up[i] = mix(down[i], tent(up[i+1]), 0.62)`。等效每级权重：0.38、0.236、0.146、0.091、0.056、0.092，总和为 1。
- **合成**：`col = mix(col, bloom, 0.065)`，能量守恒的混合，不是加法，所以不会整体发白。
- **镜头脏污**：`col += bloom*dirt*0.1`。dirt 是初始化时程序化生成的 512×288 纹理（`tA`，4578–4596）：70 个哈希圆斑，带亮边环 + fbm 污渍 + 竖向条痕，越往边缘越强。
- **变形镜头拉丝**（`Q6`）：取 `down[2]`（1/8 分辨率），15-tap 水平高斯 `exp(-x²/18)`。第一遍阈值 `2.2/exposure`、步距 1.5 texel，第二遍无阈值、步距 5 texel。颜色乘 `(0.45,0.62,1.0)*0.03`。
- **为什么好看**：没有阈值，所有亮度都按比例发光，所以过渡自然，不会出现"只有某个亮度以上才发光"的硬边光斑。权重小（6.5%）但半径大，形成一层空气感的光晕。
- **迁移**：无状态。套件已有 mip 链泛光，可以对照补上三点：Karis 首级、mix 而非 add、无阈值。镜头脏污和拉丝套件缺。
- **成本**：约 50 行，11 个 pass，GPU 约 0.3 ms（估计）。

#### 8. 色调映射：ACES(Hill) 与 AgX(punchy) 按 0.25 混合，之后在显示线性域调色
- **位置**：4604–4628、4677–4701。
- **AgX**：沿用 three.js 的 Filament/Blender 拟合。
  - 先 sRGB→Rec2020，再乘 inset 矩阵；`log2` 后归一到 EV `[-12.47393, 4.026069]`；然后 6 次多项式对比度曲线。
  - look 阶段：`pow(LOOK_POWER=1.18)`，以 luma 为中心的饱和度 `LOOK_SAT=1.22`（Blender 的 punchy 约为 1.35 / 1.4，这里温和一些）。
  - 最后 outset 矩阵、`pow 2.2`、Rec2020→sRGB。
- **ACES**：Hill 拟合（RRT+ODT 有理式），输入先乘 1.3。
- **混合**：`mix(ACES, AgX, 0.25)`。注释：ACES 提供冲击力和燃烧的橙色，往 AgX 拉是为了让高光滚到白色而不是偏色饱和。
- **调色**（色调映射后、编码前，作用在 0–1 显示线性值上）：
  1. 分离色调：`col *= mix(暗部(0.80,1.01,1.13), 亮部(1.07,1.0,0.90), smoothstep(.03,.55,luma))`，暗部青、亮部暖。
  2. S 曲线：`mix(col, smoothstep 多项式(col), 0.22)`。
  3. 抬黑：`col*0.988 + (0.006,0.0085,0.011)`，黑位略带青。
  4. 饱和度：`uSaturation*(1-.65*lowHealth)*(1-.5*damage)`。
  5. 暗角：`vig = 0.3 (+0.55 低血量, +0.22 开镜)`；`vr = smoothstep(0.15, 1.05, r2)`，其中 r2 归一到角落为 1；`col *= 1-vig*smoothstep(vr)`。
  6. 受伤红边、淡出。
  7. `toSRGB` 用的是分段精确公式，不是简单 `pow`。
- 没有色温参数，冷暖倾向全靠分离色调。没有 LUT。
- **为什么好看**：混合曲线同时拿到 ACES 的对比和 AgX 的高光去饱和，避免"橙色变荧光"和"白色过曝发黄"。青暗/暖亮的分离色调和低角度金色太阳互补。抬起的青色黑位去掉了数码死黑。
- **迁移**：全部是常数，可直接写成套件里的一个"调色配方"示例（只能作为菜单，不能当默认值）。套件已有 AgX、ACES、lift/gamma/gain；缺"两条曲线混合"和"按亮度分离色调"。
- **成本**：约 60 行，开销可以忽略。

#### 9. 屏幕空间 AO：半分辨率、距离加权、只压环境光区域
- **深度**：`X6` 用 `texelFetch(depth, 2*px)` 点采样转线性深度，存成 R32F 半分辨率。注释解释了原因：在 texel 角上采样会挑错行，导致掠射地面上 AO 出现条带。
- **AO**（`Y6`，4357–4388）：
  - 法线由深度重建，左右、上下各选深度差较小的一侧，避免跨边缘。
  - 半径 `R = 0.9m*(0.6+0.4*clamp(z/12))`，换算到 UV 后钳到 `[3 texel, 0.14]`。
  - 采样 `AO_TAPS`：low 8、默认 12、ultra 16，按 3 圈螺旋排布，起始角用 IGN 旋转。
  - 每个采样的贡献 `(R²-|v|²)³ * max((v·n - (0.015+0.004z))/(|v|²+0.004), 0)`。
  - `ao = 1 - 1.6*sum*5/(R⁶·N)`；70–140 m 之间淡出。
- **模糊**：深度感知 7-tap 可分离模糊（`BLUR_TOL 0.04`）。
- **合成**（`Z6`，4458–4489）：
  - 半分辨率到全分辨率用联合双边上采样：双线性权重 × `1/(0.015 + |Δz|/z)`。
  - 关键是只压暗部：`lit = smoothstep(.16,.85, luma*exposure)`，`a = mix(1, ao, 0.95*(1-0.8*lit))`。注释：遮蔽属于环境光，被阳光照亮的面不该有脏光晕。
  - 遮蔽带一点冷色：`col *= mix(a, 1, (0,.03,.07))`。
- **为什么好看**：解决"物体飘着没接地"的塑料感，同时避免 SSAO 典型的脏黑光环。
- **迁移**：无状态。离线可以全分辨率、32 taps。缺。
- **成本**：约 70 行，4 个 pass，约 0.3 ms（估计）。

#### 10. PCSS 接触硬化软阴影（4285–4338，替换 three.js 的 `getShadow`）
- **做法**：
  - 阴影相机正交视锥按关卡包围盒拟合（`Gy`）。shader 里拿到 `SL_FRUSTUM`（米）和 `SL_DEPTH`（米）常量，**半径用米表示**。
  - 接收面深度偏移：由 `dFdx`/`dFdy` 求接收面在阴影图 UV 空间的深度梯度 `dz`，钳到 `0.003/texel`；`zr = z + bias - (|dz|·texel)*0.35`。
  - 采样旋转角用 IGN；Vogel 盘 `r=√((i+.5)/n)`、`θ = i*2.39996 + φ`。
  - 遮挡物搜索：8 tap，半径 `0.55*shadowRadius m`。
  - 半影宽度：`clamp(dist*0.022*radius, 0.012r, 0.6r)` 米。注释写明 0.022 是"把太阳半角放大以求好看"；真实太阳约 0.0047，相当于放大约 4.7 倍。
  - 过滤：16 tap（low 档 10），最小 1.25 texel。
  - 阴影图边缘 2% 渐变为受光，看不到视锥边界。
- **参数**：shadowMap 4096（high），`bias -1.2e-4`，`normalBias .02`，`radius 1`。
- **为什么好看**：接触处锐利、远处柔和，是"真实感"的关键线索；没有 shadow acne，也没有 peter-panning。
- **迁移**：游戏为了省开销隔帧更新阴影（`(T&1)===0`，ultra 和截图模式除外），离线必须每帧更新。这里没有时间性，可以把采样数提到 32/64。套件写"有软阴影"，需要对照是否是 PCSS（估计是 PCF）。
- **成本**：约 50 行，开销中等。

#### 11. 太阳镜头眩光与幽灵（`flare`，4631–4652）
- **做法**：
  - 遮罩眩光：`sunCol*(0.02/(9r²+0.01) + 0.1*exp(-3.2r))`。
  - 衍射芒：`|cos(3θ+.4)|^24 + 0.6|cos(4θ-1.1)|^40`，乘 `0.3*exp(-5.5r)`。
  - 4 个幽灵沿"太阳→画面中心"轴分布，位置系数 -0.38、-0.82、-1.35、+0.45，各带颜色和软边圆盘。
  - 一个对侧光环，半径 0.52。
  - 总强度 0.16，乘遮挡可见度；脏污区域 ×(1+1.5·dirt)。
  - 太阳投影坐标超出 NDC 1.0–1.3 时线性淡出；相机背向太阳时关闭。
- **为什么好看**：给画面"有一个真实镜头在拍"的物理感，逆光镜头特别加分。
- **迁移**：可见度改成取当帧值。缺。
- **成本**：约 30 行。

#### 12. 收尾 pass：FXAA、锐化、颗粒、去色带抖动（`iA`，4703–4732）
- **FXAA**：grade 把 Rec.601 luma 写进 alpha，这里做简化版 FXAA 3.11（对比度阈值 `max(.0312, lMax*.1)`，方向钳 8 texel）。
- **锐化**：unsharp mask，`0.3*(M - 四角均值)`，在强边缘上退让（`1-smoothstep(.04,.22,contrast)`，强边缘交给 FXAA）。
- **颗粒**：三角分布 `hash+hash-1`，种子 `gl_FragCoord + fract(uTime*(7.31,3.17))*(311.7,173.3)`，幅度 0.02。亮部减到 30%、极暗处减到 35%（按 luma 加权）。
- **去色带抖动**：静态三角分布 ±1/255。
- **抗锯齿方案总结**：HDR 场景 MSAA（0/2/4）+ 色调映射后 FXAA，**没有 TAA**。
- **分辨率**：内部分辨率 = 画布 × min(DPR,2) × 画质档 scale × 动态分辨率，再受像素预算封顶（low 1.0M、medium 1.5M、high 2.3M、ultra 3.7M）。最后这一 pass 直接画到画布，顺带完成双线性放大。
- **迁移**：
  - 颗粒种子用 t，是纯函数。按帧号播种更好，避免大 t 时的浮点精度问题，套件已经这么做。
  - 离线做法：用 2× 超采样渲染再缩小，替代 FXAA；MSAA 开到 4。
  - 注意 h264 yuv420 会抹掉 1/255 抖动和 0.02 颗粒。要么提高码率或用 10-bit，要么在编码前适当加大幅度。
- **成本**：约 30 行。

#### 13. 相机运动模糊（`j6`，4490–4510）
- **做法**：
  - 用深度重建世界坐标，`uPrevViewProj` 重投影得到速度。只处理相机运动。
  - 快门 `uShutter = min(0.5, (1/190 s)/dt)`，即固定 1/190 s 曝光时间折算成帧间比例。
  - 速度上限 0.018 UV；小于 0.75 px 时跳过。
  - 9 个采样，IGN 抖动；枪模像素（d<0.05）不参与。
  - 位置在合成之后、泛光之前，只在 high/ultra 档开启。
- **迁移**：`prevViewProj` 是帧间状态。改法是用 `camera(t - 1/fps)` 解析求出；`dt` 固定为 1/fps。更好的做法是套件已有的子帧平均运动模糊，物体运动也能糊。
- **成本**：约 25 行。

#### 14. 枪模 / 前景层：`gl.depthRange(0, 0.05)`
- **做法**：世界渲完后不清深度，换一个 FOV 54°、near 0.01、far 10 的相机，把深度压进 [0, 0.05] 再渲枪模。枪模永远在最前，又仍然写深度。后期各 pass 用 `d < 0.05` 识别枪模：不做 AO、不加雾、不做运动模糊。
- **迁移**："前景道具或产品永远在最前、且不吃雾"的需求可以直接用这招。缺。

#### 15. 程序化 PBR 贴图烘焙器开头（4734–4800+，后面还有，超出本区）
- **输出**：WebGL2 MRT 三个输出。
  - `o0`：albedo 存成 `sqrt(c)`，相当于 gamma 2 编码，提高 8-bit 暗部精度，A 通道为 alpha。
  - `o1`：AO、粗糙度（≥0.03）、金属度。
  - `o2`：16-bit 高度拆成两个 8-bit 通道。
- **噪声**：`pcg3` 整数哈希加 `mod(c, per)` 得到可平铺的周期噪声；梯度噪声用五次插值；`fbm` 归一到"约 0..1、均值 0.5、标准差约 0.18"；还有 voronoi F1/F2、随机划痕 `scr`、锈斑 `rustMask`。颜色用 `L()` 从 sRGB 作者值 `pow 2.2` 转线性。
- **paintDmg**：
  - 先用 `zone = smoothstep(.58,.82, fbm)` 圈出损伤聚集区，注释写"大部分面板是干净的"。
  - 剥落密度 `(0.012+0.085*zone)*(0.5+amt)`。
  - 剥落片用 `(20,11)` 频率的 voronoi，纵向拉长。
- **为什么好看**：损伤是"聚集 + 稀疏"分布，而不是均匀撒噪声，这是破除程序化材质塑料感和重复感的关键。确定性种子，适合 seek。

#### 区域内看到的"有 / 无"
- **有**：体积光（真步进）、SSAO、相机运动模糊、泛光、拉丝、眩光、脏污、色差、暗角、颗粒、FXAA、锐化、自动曝光。
- **色差**：径向，`off = c*r2*(0.0013 + damage*0.006)`，在 HDR 场景上分别采 R/B 通道，属于第一步。
- **开镜 ADS**：外围混入 `down[1]`（1/4 分辨率模糊），这是"外围虚化"，不是景深。
- **无**：景深（`post.focusDist` 字段存在但本区没有使用）、SSR、TAA。画质档里有 `planar`（平面反射）和 `rain`，实现在本区之外。

**移植到 seek(t) 要改的东西汇总**：
- 曝光：去掉帧间积分，改成固定值或预算好的 `exposure(t)` 表。
- 太阳可见度平滑：改为当帧值。
- 运动模糊：`prevViewProj` 由 `camera(t - 1/fps)` 求，或者用子帧平均。
- 阴影：每帧更新。
- 动态分辨率：关掉。它用 `performance.now` 计时。
- 雷击：方向用了 `Math.random`，改成按事件序号播种；强度已经是"距事件时间"的闭式 `exp(-5t)·sin·sin`，可直接用。
- 光源池：TTL 随 dt 递减，改成按事件时刻求闭式。

游戏本身有 `shot` 截图模式，会关动态分辨率、强制每帧更新阴影、加快适应；参考价值有，但仍不是纯函数。

**离线可以做得更贵的地方**：
- 体积雾全分辨率、64 步以上；
- AO 全分辨率、32 taps；
- PCSS 32/64 taps；
- 2× 超采样替代 FXAA；
- 云的自阴影改为多步步进。

**成本**（估计）：后期 JS 约 200 行，着色器约 400 行；天空约 120 行；PCSS 约 50 行。1080p 独显上整条链约 2–3 ms。注意套件的环境是 SwiftShader 软件渲染，体积和 AO 每帧可能要数百毫秒到数秒。

**对照套件现状**：
- 已有：mip 链泛光（缺 Karis、mix 混合、无阈值）、色差、暗角、颗粒、AgX/ACES、lift/gamma/gain、子帧运动模糊。
- 缺：程序化天空与云、高度雾、阴影步进体积光、天空生成 PMREM、SSAO、自动曝光（及其可 seek 的替代）、眩光、镜头脏污、拉丝、FXAA/锐化、双边上采样、两条曲线混合、按亮度分离色调。PCSS 需要对照现有软阴影才能确定。

## 三、方法论（只列有代码证据的）

1. **先把物理正确的线性 HDR 管线搭好，再做美术调整**。HDR16F 目标、渲染器 `NoToneMapping`（4733@≈14700）、全部后期 `toneMapped:false`；色调映射只出现一次（4677），之后才调色（4679 注释 "grade (display-linear)"），最后手写 sRGB（4700）；FXAA、颗粒放在编码之后（4703+）。
2. **一个光照和天空模型供全场共用**。`Mn`/`en` 全局常量（4180@51450）→ 天空 uniform（`W6`）、体积雾 uniform（`v()`）、雾环境光 `en.fog`、平行光 `W0(Mn.color, Mn.intensity)`；`Ng` 片段同时被天空和雾 include（4202、4395），远雾颜色就是 `horizonColor(rd)`（4439）；PMREM 从同一个天空生成（`Vy`）。
3. **每份能量只算一次**。注释 "sun disk (not in the environment capture: the directional light is the sun there)"（4268）；"keep the PMREM free of fireflies"（4280）；AO 只作用于环境光那部分（4481 注释）。
4. **参数用有物理意义的单位，并且与帧率无关**。阴影半径用米（4287 "metres across the shadow map"、4311 "metres -> uv"）；`σ = 0.0034/m`、标高 5.5 m、AO 半径 0.9 m；快门 1/190 s；适应用 `1-exp(-dt/τ)`，τ 以秒计（4733@≈9500）。
5. **从物理模型出发，偏离时明确标注为美术决定**。"sun half-angle scaled up for look"（4321）、"art direction: beams near the eye read strongly"（4428）、双瓣相位函数的理由（4414）、"punchy-style look"（4615）、"ACES … pulled toward AgX"（4676）。每个魔法数字旁边都写了意图。
6. **用 shader 做构图**。云层边缘按太阳方向留出燃烧的缝（4232）；"the sun always burns through a ragged hole … never sits behind solid cloud"（4237）；损伤是"most of the panel is clean"（4798）。画面的视觉焦点是写进算法里的，不靠运气。
7. **细节分层叠加，每层各管一个尺度**。云：域扭曲 → fbm5 → 脊状细节（随距离淡出）→ 大尺度起伏 → 覆盖度 → 云底边缘 / 太阳洞 / 碎云。受光：冷色基底 → 自阴影起伏 → 薄处透光 → 暖色侧光 → 亮边 → 闪电 → 大气透视（4220–4262）。日晕用四个幂次叠加（4217）。
8. **主动逐个消灭廉价伪影，并写明原因**：
   - 色带：4729 抖动；4351 用 texelFetch 防 AO 条带。
   - 地平线锯齿：4226。
   - 萤火虫：4521 Karis 平均、4280 钳值。
   - 阴影 acne：4301 接收面偏移。
   - 视锥边界：4332。
   - 脏 AO 光晕：4481。
   - NaN：4573。
   - 低采样噪声：IGN 加深度感知模糊或双边上采样。
9. **外观参数集中管理，与画质档分离**。`TUNE` 表 `g` 只管外观；`Pr` 画质档（4180@52000）只改采样数、分辨率、MSAA，不改外观。
10. **有标定场景，也有验证手段**。`sA` showcase（4733 末）：两排球，粗糙度 0.06→0.96，一排金属一排电介质，外加各材质块、自发光条、室内棚。相机 y 坐标的毫米位编码切换受伤 / 低血量 / 开镜 / 闪光 / 淡出状态，用于截图对比后期。`shot` 模式和 `window.__setShot` 用于确定性截图，`stats()` 能读回曝光。启动时还会自测，着色器失败就逐级回退（4733@≈21500）。

# 二、材质、表面与建模（第 4772–5660 行）

## fps-game.html 第 4772–5660 行技法分析（只读）

我按字符切片把整段读完了，包括超长行 5283、5442（18 万字符，含材质系统、全部道具建模、关卡布置）、5449、5463、5650。没有运行这个 HTML，也没有修改任何文件。

**先说结论**：
- 这个游戏的质感来自三层，全部不用外部文件：
  1. **加载期在 GPU 上一次性烘焙的程序化 PBR 贴图**，约 30 种表面。
  2. **运行时注入 MeshStandardMaterial 的世界空间效果**：宏观变化、雨湿、积垢。
  3. **建模期写进顶点色的风化**：底部脏、朝上亮、凹痕生锈。
- 地面是单独写的一套"大尺度唯一遮罩 + 双尺度平铺细节 + 连续水位斜坡 + 平面反射"着色器。

**两点要先知道**：
- **太阳光、阴影、曝光不在我这段**。设置在第 4733 行，那段我只用 grep 看到几个值：bias=-1.2e-4，normalBias=0.02，mapSize 默认 2048，阴影采样 16 taps、8 search taps（看起来像 PCSS 一类的软阴影），另有"室内探针"会改写 envMap。具体强度和颜色要看负责那段的分析。
- **烘焙对 SwiftShader 不友好**。我们的 WebGL 是软件渲染，而单个表面的烘焙着色器每个像素要算几百次噪声（`paintDmg` 里有约 10 次多倍频 fbm，外加一个 4 次循环）。以下耗时是我的估计：硬件 GPU 上全套 0.1–1 秒，SwiftShader 上 1024² 可能要几十秒到分钟级。迁移时应降分辨率，或者把烘焙结果缓存成 PNG。

### 一、技法清单（按重要性排序）

#### T1. GPU 烘焙程序化 PBR 贴图，一个着色器出三张图（最核心，套件缺）

**1. 在哪里**
- 噪声库和输出函数：第 4736–4820 行，标识符 `pcg3`、`h3`、`gn`、`fbm`、`vor`、`scr`、`emit`。
- 30 个表面函数：4822–5269 行，表 `Tn.*`。
- 由高度导出法线：5270–5280 行，`i3`。
- 调度：5442 行开头的 `Gg()` 和 `A()`。
- 参数表：5283 行末尾的 `c3`。

**2. 怎么做**
- **哈希**：`pcg3(uvec3)` 整数哈希，再除以 2³²，结果跨机器一致。
- **可平铺的梯度噪声** `gn(p, per, s)`：格点坐标先 `mod(c, per)` 再哈希，所以噪声天然无缝；插值用五次曲线 `u = f³(f(6f−15)+10)`。
- **fbm**：倍频每层 `f *= 2`、`a *= 0.5`，每层种子 +7，最后 `sat(v/t*1.8+0.5)` 归一到 0..1，均值 0.5，注释写标准差约 0.18。
- **Worley** `vor`：返回 F1、F2、本格随机值、第二随机值，同样做了周期化。
- **随机划痕** `scr`：每格一条线段，角度为 `ang ± spread`，长度 0.15–0.95 格，半宽 w，用 `step(r2.y, dens)` 控制密度，强度 0.35–1。
- **一次 pass 写三张图（MRT，`count:3`）**：
  - `o0 = (sqrt(albedo), a)`：用 sqrt 近似伽马，保住 8 位精度。
  - `o1 = (ao, clamp(rough, 0.03, 1), metal)`，即 ORM。
  - `o2 = 16 位高度`，拆成 `floor(h*255)/255` 和小数部分两个通道。
- **后处理拷贝**：albedo 平方还原成线性，写进 sRGB 格式的 RT；生成 mipmap，各向异性 ≤8，Repeat。
- **法线**：在 16 位高度上做 3×3 Sobel：`gx = (r−l)*0.5 + (ru+rd−lu−ld)*0.25`，`n = normalize(−gx*K, −gy*K, 1)`，其中 `K = bump*0.001*D/tile`。
  - D 是像素边长，tile 是这张贴图在世界里的边长（米）。
  - **物理含义**：高度 0..1 对应 `bump` 毫米的起伏，所以 `bump` 直接就是真实凹凸幅度。
- **分辨率**：`1024*size`（size 取 0.25–1）；主角表面沥青在画质够时用 2048。
- **参数表 `c3`（size / 平铺米数 / 凹凸毫米）**，节选：

  | 表面 | size | 平铺 (m) | 凹凸 (mm) |
  |---|---|---|---|
  | asphalt | 1 | 2 | 1.6 |
  | concrete | 1 | 3 | 2.5 |
  | brick | 0.5 | 1.8 | 6 |
  | epoxy | 0.5 | 4 | 3 |
  | paint | 1 | 2.5 | 2.5 |
  | hull | 0.5 | 4 | 12 |
  | galv | 0.5 | 1 | 0.8 |
  | brushed | 0.5 | 0.5 | 0.4 |
  | rust | 0.5 | 1.2 | 3 |
  | corrugated | 0.5 | 0.762×2.286 | 19 |
  | gunmetal | 0.5 | 0.25 | 0.3 |
  | polymer | 0.25 | 0.1 | 0.4 |
  | carbon | 0.25 | 0.05 | 0.5 |
  | wood | 0.5 | 1.2 | 2.6 |
  | tarp | 0.5 | 1.5 | 20 |
  | tire | 0.5 | 0.5×0.3 | 7 |
  | water | 0.25 | 4 | 30 |

  - 同一函数换种子出变体：`anodized` 用 gunmetal + seed 11，`glass_dirty` 用 seed 40。
- **每种表面的写法都是"真实分层"**（4822–5269 行）。各层用 `smoothstep` 阈值化 fbm 或 Worley 做遮罩，依次改反照率、粗糙度、高度、AO。例子：
  - **沥青**：两层 Worley 骨料（110、230 格/片）+ 3/24/300 三尺度 fbm；反照率是 0.13 的黑色基体，骨料 0.26–0.45 带暖色；有填缝带和油斑。粗糙度：基体 0.93，露骨料 0.74，填缝 0.36。
  - **混凝土**：两层气孔（Worley 70 与 260 格）；裂缝是扭曲域上 Worley 的 `F2−F1 < 0.0045`；有缺损露骨料、边缘接缝、风化泛白（efflorescence）。
  - **砖**：24 行 × 8 列错缝；每块砖用 `h3(cell)` 取三个随机值调色；砂浆宽度带噪声；有烟熏和泛白。
  - **木头**：Worley 节疤推动年轮 `fract(uv.y*44 + 扰动 + knot²*4)`；有早材/晚材两色、锯痕、风化发灰、干裂。

**3. 为什么不假**
- 每张图都有 3–5 个尺度的变化，而且粗糙度、高度、AO 跟颜色出自同一组遮罩，是相关的。所以在"颜色变了"的地方，"高光也变了"。
- 塑料感主要来自粗糙度均匀；这里粗糙度在 0.1–0.95 之间按成因变化。

**4. 迁移到逐帧离线**
- 全部在加载期执行一次，seek 时不重算，对我们最友好。
- 噪声是 pcg 整数哈希，确定性好。
- 离线可以开 2048 以上，各向异性拉满。
- SwiftShader 下要降分辨率，或者烘焙一次存 PNG 放进片子目录。
- 如果片子不跑 WebGL2，MRT 要改成三次单输出 pass。

**5. 成本（估计）**
- 框架加噪声库约 150 行 GLSL + 80 行 JS；每种表面 15–40 行 GLSL。
- 运行时只是普通三张贴图采样，几乎零开销。

#### T2. 共享的油漆破损模型 + 叠层 + "色板与贴图分离"（套件缺）

**1. 在哪里**
- `chipsF` / `paintDmg`：4791–4820 行。
- 共享叠层代码 `n3`：4914–4942 行。
- 用到它的表面：`Tn.paint`（4943）、`Tn.hazard`（4949）、`Tn.armor`（5153）。
- 叠层宏 `OV`：4742 行。
- 着色模式 `SL_TINT`：5381–5390 行。
- 预设：5283 行的 `Xa()`，以及 `l1.paint_*`。

**2. 怎么做**
- **破损聚簇**：`zone = smoothstep(0.58, 0.82, fbm(uv, 2, 3oct))`，注释写"damage clusters; most of the panel is clean"。密度 `dn = (0.012 + 0.085*zone)*(0.5+amt)`。
- **剥落片 c1**：Worley 20×11 格（纵向拉长，注释"vertically stretched flakes"），半径 `rmax*(0.25+0.75*rand)`。边缘用 fbm 抖动：`smoothstep(r, 0.55r, F1 + e*0.6)`。
- **细剥落 c2**：64×40 格，密度 ×1.6。
- **大面积磨穿 c3**：`smoothstep(th, th+0.03, wearN + 细噪声*0.12)`，其中 `th = 0.925 − 0.06*amt`，`wearN` 是 6 倍频 fbm。
- **划痕**：两组（5 格横向、16 格纵向），乘断续遮罩 `sbreak`。
- **合成**：`chip = max(...)`，0 表示漆完好，1 表示露出基材。
- **stain（氧化晕）**：剥落周围半径 0.42 的晕圈 × fbm。
- **run（锈流挂）**：向下取 4 次 `uv + (0, i*0.034)`，权重 `1 − i/5`，乘竖向条纹 `fbm(120×1)`。注释"−V is down"，即锈从破损处往下流。
- **叠层顺序就是真实形成顺序**（`OV(D,k)`：`nt = mix(nt, D, k)`，`ta = mix(ta, 0, k)`）：
  1. 粉化 chalk：0.075
  2. 污膜：`L(.24,.22,.19)×0.42`
  3. 锈渍：`×0.5`
  4. 底漆：`smoothstep(.15, .4, chip)`，偏红灰
  5. 锈：`smoothstep(.55, .8, chip)`
  6. 新鲜钢：`steel × smoothstep(.78, .86, fbm25)`，反照率 0.55，金属度 0.95，粗糙度 0.35
- **对应的粗糙度**：漆面 `baseR` 0.40（警示条纹 0.5），粉化 +0.26，污膜 +0.3，雨水冲刷 −0.06，底漆 0.75，锈 0.92，新鲜钢 0.35，锈渍 0.72。
- **色板分离**：贴图里只存"覆盖层颜色 nt"（rgb）和"原漆还剩多少 ta"（a）。运行时 `SL_TINT==1`：`diffuse = tex.rgb + uColor*tex.a`。
  - 结果：**一套烘焙贴图服务 8 种漆色**，红 #7D2219、蓝 #1F3F66、绿 #2C5A44、黄 #B98A1C、橙 #B3521A、白 #B9BBB6、灰 #5A6068、青 #1F5D63。全场破损在统计上同一个"手笔"，颜色由道具参数决定。
- **复用者**：钢构（`n3` 共用）、警示条纹（`amt=1.4`）、护甲（`amt=0.5`，露出的是复合材料基底，不是钢）。

**3. 为什么不假**
- 解决"太干净"：画面大部分干净，破损成簇，而且有方向（锈往下流）。
- 全场一个模型，保证风格统一；不同漆色共用破损纹样，又不会每个道具一模一样，因为 UV 位置和种子不同。

**4. 迁移**
- 加载期烘焙。`amt`（`uP.x`）是烘焙参数；如果要"随时间生锈"，可以把 `amt` 改成运行时 uniform，但那就得改成实时计算。
- 色板分离对我们很有价值：片子换配色不用重新烘焙。

**5. 成本（估计）**：约 60 行 GLSL。烘焙较贵（每像素约 300 次噪声），运行时零开销。

#### T3. 注入标准材质：世界空间宏观变化 + 积垢 + 雨湿（套件有接法、缺模型）

**1. 在哪里**
- 顶点部分：5284–5306 行（`vSlPos`）。
- 片元声明：5307–5321 行（`slN3` 是 3D 值噪声）。
- 替换 `map_fragment`：5322–5407 行。
- 替换 `roughnessmap_fragment`：5408–5419 行。
- 替换 `metalnessmap` / `normal_fragment_maps` / `aomap`：5420–5439 行。
- 注入函数 `h3()`：5439–5442 行；材质工厂 `w()`：5442 行。
- uniform：`uSlWet`（全局雨量）、`uSlWetP`、`uSlMacro`、`uSlUv`、`uSlX`。

**2. 怎么做**
- **宏观变化**：`slMac = slN3(worldPos*macro.z)`，`slMac2 = slN3(p*3.7+11.3)`。
  - 反照率乘 `1 + macro.x*(0.65*mac + 0.35*mac2 − 0.5)*2`。
  - 粗糙度加 `macro.y*((mac2−0.5)*1.4 + (mac−0.5)*0.8)`。
  - 噪声在**世界空间**，跟贴图的平铺周期互不相关，所以能打散重复。
- **积垢 grime**：`smoothstep(0.5, 0.85, mac*0.6 + mac2*0.4 + (1−AO)*0.3)*macro.w`，反照率 ×(1−0.35·gr)。污垢沉进烘焙 AO 低的缝里。
- **雨湿**：
  - 朝向：`up = smoothstep(.15, .85, N_world.y)`；`expo = smoothstep(−.4, −.05, N.y)`，即朝下的面不湿（注释"strongest on up-facing faces, streaky on verticals, none underneath"）。
  - 竖面条纹：`slN3(vec3((x+z)*9, y*0.55, ...)) * slN3((x+z)*29, y*1.1)`，再取阈值。
  - 湿度：`wetK = uSlWet*interior*expo*mix(wetP.z*(0.55+0.9*streak), 0.75+0.5*mac, up)`。室内材质的 `uSlX.x = 0.12`，只湿 12%。
  - 地面溅湿带：`slLow = smoothstep(0.5, 0, y)*(1−up)*expo`，离地 0.5 m 以内湿度 +0.6，并按 grime 压暗最多 0.45×min(grime, 0.5)。
  - 水珠：只在像素足迹小时出现，`slBf = 1 − |fwidth(pos)|*120`（大约每像素 8 mm 以下）。水珠噪声 170/m 和 410/m 两层，阈值 0.6–0.68；有水珠处粗糙度直接压到 0.05。
- **湿的光学效果**（5391–5395 行）：
  - 饱和度提高 `+25%*wetK*darken*2`，反照率 ×(1 − darken*wetK)。
  - 粗糙度 `mix(r, r*wetP.y, wetK)`。
  - 朝上的湿面法线压平 45%：`mapN.xy *= 1 − 0.45*wetK*up`。
- **wetP 各分量的含义**：x = 变暗量，y = 粗糙度倍率，z = 竖面湿量，w = 水珠量。
  - 多孔材料变暗大：默认 0.42，沥青 0.45，木头 0.4，纸板 0.4。
  - 封闭材料和金属几乎不变暗、但有水珠：漆 [.05, .62, .65, .7]，金属 [0, .7, .55, .5]，塑料 [.08, .62, .6, .5]。
  - 玻璃、铁丝网、水为 [0, 1, 0, 0]，不参与。

**3. 为什么不假**
- 解决平铺重复：世界空间宏观噪声。
- 解决"每块都一样干净"：积垢沉在缝里。
- 解决"湿了只是变黑"：同时改了饱和度、粗糙度、法线；朝向逻辑正确（顶湿、底干、竖面有流痕、贴地有溅湿带）。

**4. 迁移**
- 没有时钟依赖，雨量是 uniform，可以随 t 变化。
- 水珠的 fwidth 门槛和分辨率有关；离线超采样时阈值要按实际像素尺寸调。

**5. 成本（估计）**：约 130 行 GLSL。每像素增加 4–6 次 3D 值噪声，便宜。

#### T4. 地面：大尺度唯一遮罩 + 双尺度平铺细节 + 连续水位斜坡（套件缺，价值最高）

**1. 在哪里**
- 遮罩生成：5463 行末尾，CPU 上的 `SR()` 和 `Rb()`，参数 `Li = {x0:−44, z0:−40, size:80}`，积水坑表 `Sb`。

- 着色器：`TR` 在 5464–5502 行，`AR` 在 5504–5615 行，`RR` 在 5617–5642 行。
- 材质：`Ib()`，5643–5650 行。

**2. 分层组织和各层世界尺度**

- 遮罩外缘 5% 平滑过渡到默认值 (0.66, 0.5, 0, 0.5)，没有硬边。

**3. 湿润的全部斜坡**（5568–5594 行），先算一个水深：

`depth = 0.5 − mk.r + (sn−0.5)*0.11 + (d1.g−0.5)*0.03 + (grain−0.5)*0.012 + groove*0.04 + crack*0.02 − paint*0.01`

意思是切槽和裂缝里先积水，标线因为凸起所以后积。各层权重：
- 积水（镜面）：`puddle = smoothstep(0, 0.035, depth)`，注释"约 5 cm 过渡"。
- 深度：`deep = smoothstep(0, 0.22, depth)`，坑边露出湿床，深处浑暗。
- 浸湿带：宽 `bandW = 0.05 + 0.15*sn1² + 0.05*d1.g`（约 10–30 cm，沿岸变化），`soak = smoothstep(−bandW, 0, depth)`。
- 潮湿晕：`fringe = smoothstep(−0.65, −0.02, depth)`，约 1 m。
- 局部干斑：`dryP = 1 − smoothstep(0.2, 0.42, mk.g + fringe*0.55 + ...)`，`damp = 1 − dryP`。
- 水膜：`film` = 浸湿带里颗粒低的地方 + 切槽 × 0.5，标线处 ×0.6。

反照率：
- `×mix(0.95, mix(0.7, 0.54, 1−paint), damp)`，潮湿时沥青压到 0.54，标线压到 0.7。
- 再 `×mix(1, 0.5, soak)`。
- 积水处：`alb*mix(0.85, 0.4, deep) + (0.004, 0.006, 0.0065)*deep`。注释"never a black cut-out"。

粗糙度：
- 干 0.74 → 潮 0.42（颗粒 ±0.12、中频 ±0.08）
- 浸湿 `0.2 ± 0.07`（权重 0.9）
- 水膜 0.13
- 积水 0.055
- 另外：磨亮车道 −0.07，油污 −0.16，填缝 −0.1，远处 `+smoothstep(10, 80, dist)*0.04`。

**4. 积水怎么反射**
- **平面反射**：`zb()`，5650 行。镜像相机，用 Lengyel 斜近平面裁掉 y=0.01 以下；RT 尺寸 = 分辨率 × `quality.planar`，带 mip；`uReflLod = log2(h/270)`，让模糊程度和分辨率无关。
- 着色器在 `lights_fragment_maps` 之后**替换 `radiance`**（IBL 镜面项），所以菲涅耳和 BRDF 仍由 three 计算。
- 积水处 `material.specularColor → 0.075`。注意：水的物理 F0 是 0.02，这里是美术上故意加强。
- 模糊：
  - 积水：`lod = clamp(r*9.5 − 0.45, 0, 6.5) + 0.9`（注释"a touch soft, never razor sharp"）。
  - 潮湿面：`lod = clamp(3 + r*6.5 − 3.4*pow(1−V.y, 5), 2, 7.5)`，掠射角时变清晰。
  - 竖直方向三次采样拉长：偏移 `(0, r*0.11 + (1−puddle)*0.05)`，权重 0.5/0.25/0.25，模仿湿路面上被拉长的倒影。注释"reads as a sheen, not as a second mirror"。
- 扰动：法线斜率 × `dk = (puddle + film*0.15 + 0.03)/(1 + dist*0.07)`，限制在 ±0.12。
- 混合权重：`pw = mix(1 − smoothstep(.55, .9, r), 1, max(puddle, soak))`。

**5. 涟漪和雨滴**：有，都是 t 的纯函数。
- `gRipple`（5485 行）：每个格子每个周期 `floor(tt)` 换一个新雨滴（位置、大小、强度），`life = fract(tt)`。
- 环剖面 `x*exp(−x²)*2.3`（高斯的导数），`x = (d − life*rmax*cell)/(0.005 + 0.02*life)`，振幅 `(1−life)²`；出现概率 `0.16 + 0.5*uRain`。
- 三层：格子 0.83 m、1.31 m（旋转 36.87°）、0.57 m，速度各不相同；10–34 m 外淡出。
- 风纹：`uDetailN` 按 `uTime*(0.031, 0.017)` 和 `−(0.043, 0.027)` 滚动两层。

**6. 法线**
- 地面直接写世界空间斜率：`normal = view(normalize(−nx, 1, −nz))`。
- 积水处颗粒法线归零，只留涟漪；浸湿或水膜处颗粒法线从 ×2.1 降到 ×0.7。

**7. 为什么不假**
- 唯一遮罩让整片地面没有重复，两个不整比例的细节层补足近景。
- 水是连续渐变：积水 → 浸湿带 → 潮 → 干斑，没有硬边。
- 粗糙度跨度 0.055–0.74 比颜色变化大得多。
- 标线有真实厚度（−0.01）、会磨损、颜色不是纯白。

**8. 迁移**
- 遮罩、细节贴图、标线画布都在加载期生成（遮罩是 CPU 循环，80 m 上 1024² 约几百毫秒，估计）。
- 涟漪和风纹只依赖 `uTime`，把 `uTime` 设成 t 即可，可任意 seek。
- 平面反射每帧多渲染一遍场景；离线可以给 `quality.planar = 1`。
- 遮罩的 `uMaskRes` 是外部参数；离线可以提高。

**9. 成本（估计）**
- JS 约 120 行，GLSL 约 150 行。
- 每像素约 15 次纹理采样（两次双三次各 4 次）+ 约 12 次值噪声 + 3 层涟漪。
- 平面反射让总渲染耗时增加 60–100%。

#### T5. 高光抗闪烁 / 抗走样（套件缺 specular AA）

- **法线长度修正粗糙度（Toksvig 式）**，5414–5417 行。mip 之后法线变短，粗糙度随之变大：

  ```glsl
  float slNl = length(texture2D(normalMap, slUv).xyz * 2.0 - 1.0);
  roughnessFactor = sqrt(roughnessFactor*roughnessFactor + clamp(1.0 - slNl, 0.0, 1.0) * 0.6);
  roughnessFactor = clamp(roughnessFactor, 0.045, 1.0);
  ```

- **钳制**：
  - 地面直接高光 `min(directSpecular, 40.0)`（5650 行）。
  - 反射样本 `min(pr, 48.0)`。
  - 烘焙时粗糙度 ≥0.03，运行时 ≥0.045，积水 0.055。
- **按距离降细节**：
  - 标线碎边：第 2/3 层噪声在 6–18 m 和 2.5–7 m 淡出。
  - 水岸噪声在 25–60 m 和 8–22 m 淡出。
  - 涟漪在 10–34 m 淡出，远处改为粗糙度 +0.03。
  - 地面远处粗糙度 +0.04。
  - 水珠用 fwidth 门控。
- **解析线宽用 fwidth 做抗锯齿**：伸缩缝 `jaa = fwidth(jd)`；线太细时 `clamp(tarW/jaa)` 让对比度衰减而不是闪烁；裂缝宽度 `fwidth(d1.b)*1.5`。
- **数据贴图放大时用双三次**：遮罩始终双三次；标线在像素足迹小于 1 texel 时切到双三次（注释"no texel edge of a data map can ever show"）。
- **铁丝网 alpha 测试**（`SL_ACUT`，5396–5406 行）：
  - 阈值随 mip 级降低：`0.5*exp2(−clamp(lod−1, 0, 4))`，让铁丝始终约 1 像素宽。
  - lod 在 3.5–5.5 之间过渡到 Interleaved Gradient Noise 抖动，覆盖率约 1/3。
  - 亚像素铁丝亮度 ×0.45（注释"no white sheets in the sun"）。
- **迁移**：全部无状态。IGN 抖动是屏幕坐标的函数，逐帧稳定，不闪；离线超采样下效果更好。
- **成本（估计）**：约 30 行，几乎零开销。**建议进套件，作为 PBR 注入的默认片段。**

#### T6. 程序化建模：真实尺寸 + 微倒角 + 按材质合批（套件缺建模辅助）

**1. 在哪里**（都在 5442 行）
- 倒角盒 `p3` / `Ge`：字符偏移约 17173 / 72194。
- 圆角细分盒 `eo`：约 73299。
- 剖面扫掠 `la`：约 19093；集装箱瓦楞剖面 `Uc` / `CA`：约 20303。
- 车床体 `us`（弧长 UV）：约 71419；软法线挤出 `Mo`：约 75902。
- 构建器 `jn` / `Kn` / `io`：约 21800 / 78900 / 178000。
- 合批：`Ii`（mergeGeometries）、`By`（全关卡按材质合并）。

**2. 怎么做**
- **倒角盒 `p3`**：只有 24 个顶点（每个角 3 个，各带所属面的法线）、44 个三角形。倒角斜面在两个不同法线之间插值，于是棱上出现一条圆滑的高光带。
  - 默认倒角 `min(0.012, 最小边*0.25)`，即 **12 mm**；小件 3–8 mm；关卡板材用 `Wi` 圆角 15 mm。
- **全部用真实尺寸建模**：
  - 集装箱宽 2.438 m；20 尺长 6.06 m，40 尺 12.19 m；高 2.59 / 2.9 m。
  - 瓦楞节距 0.278 m、深 0.036、平段 0.072、斜段 0.068（ISO 实物数据）。
  - 门上有锁杆、铰链、角件、铭牌。
- **UV 以米为单位**：`c1` / `Nc` / `MA` 把 uv 乘以尺寸，材质用 `repeat = 1/tile`，所以全场纹素密度一致。
- **扫掠**：二维剖面 × 截面列表 × 映射函数 `(px, py, s, idx) → xyz`。凹痕直接在映射里减去 `H(x, y, side)`（多个 `(1−d²)²` 坑叠加）。贴花也用同一个映射生成网格，所以会贴合瓦楞和凹痕（函数 `F()`）。
- **车床体**：油桶剖面 `OA` 带两道滚箍；凹痕按 cos 衰减往里推；接缝处法线取平均。
- **合批**：每个构建器按材质分桶，`mergeGeometries` 合并；最后整个关卡再 `By()` 合一次；标签画布打包进一张图集（`rb`，4 px 出血）。

**3. 为什么不假**
- 现实里没有完美的棱，12 mm 倒角让每条边都能接到高光，这是"塑料 CG 感"的主要解药之一。
- 真实尺寸和细节密度（螺栓、焊缝、锁杆）提供可信的尺度线索。

**4. 迁移**：全部是加载期构建，确定性取决于 `$a(seed)` 这类种子随机，适合我们。

**5. 成本（估计）**：倒角盒约 40 行，扫掠约 50 行，构建器约 60 行；每个道具 50–300 行。合批后每帧开销低。

#### T7. 顶点色风化 = 烘焙 AO + 接触污垢（套件缺）

**1. 在哪里**（5442 行）
- 全道具通用的 `Kn.finish`：约 78900。
- 集装箱专用 `z()` / `H()`：约 25500。
- 背景物体 `hv()`：约 178500；天际线 `Mb.l()`：5449 行。

**2. 怎么做**
- **`Kn.finish`**，所有道具都过一遍，顶点色乘数为：

  ```
  m = (0.82 + 0.18*noise(p*1.9)) * (0.92 + 0.08*noise(p*9)) * (0.76 + 0.24*clamp(N.y*0.6 + 0.62))
  M = clamp(1 − y/0.2)                      // 离地 20 cm 的接触带
  m *= 1 − 0.42*M²*(0.55 + 0.45*fineNoise)
  G *= (1 − 0.05*M);  B *= (1 − 0.12*M)     // 偏暖的泥色
  ```

  - 第三项是"朝下面暗、朝上面亮"的半球 AO：朝下 ×0.76，朝上 ×1。
  - 第二段是**接触污垢带**。代码里**没有 SSAO，也没有接触阴影 pass**，贴地的暗是靠这个顶点色加阴影贴图做出来的。
- **集装箱 `z()`**：
  - 低频亮度 ±8%×(0.5 + wear)。
  - 0.62 m 以下渐变到暖暗色 E = [.5, .44, .38]。
  - 瓦楞边缘距离 8–34 mm 内压暗 17–18%（假 AO）。
  - 顶边往下的锈流挂 w = [.62, .38, .24]。
  - 凹痕深于 4 mm 处染锈色 [.66, .46, .36]。
- **背景 `hv()`**：
  - `1 − s*(0.3 − 0.36*noise(约 3–4 m))`。
  - 锈斑噪声高于 0.68 时（尺度约 0.6 m）：R ×(1+0.45h)，G ×(1−0.3h)，B ×(1−0.6h)。
  - 起重机各部件另乘冷暖色 `wn = [.82, .95, 1.12]`、`En = [1, .95, .85]`，模拟不同批次的漆。
- **最终颜色** = 贴图 × 漆色 × 顶点色。同一个物体上，贴图负责厘米级，顶点色负责米级和接触。

**3. 为什么不假**：解决"物体浮在地上"和"整件同一亮度"，相当于零成本的 AO 和泥土。

**4. 迁移**：加载期一次性计算。需要几何体有足够的顶点密度；大平面得先细分。

**5. 成本（估计）**：约 30 行，运行时零开销。

#### T8. 贴花、标线、文字：Canvas 2D 程序化绘制 + "做旧"擦除（套件已有 CanvasTexture，缺做旧库）

**1. 在哪里**
- 5283 行：`Ks()` 做旧、`ra()` 抖动多边形、`qa()` 模板字体文字、`l3()` 贴花库（约 20 种：危险标志、公司标志、锈流挂、油斑、弹孔、焦痕、裂纹、涂鸦、CSC 铭牌、数字）。
- 地面标线 `Pb()`：5463 行。

**2. 怎么做**
- **`Ks(ctx, w, h, amount, rng)`**：在 `destination-out` 模式下擦掉：
  - 随机抖动 7 边形，数量约 `n*w*h/700`，尺寸 `rand³*h*0.09`；
  - 划痕线 `n*16` 条；
  - 斑点 `n*w*h/60` 个；
  - 径向渐变擦拭 `n*6` 处。
- **`qa()` 模板字**：每个字形中间用 `destination-out` 切一条宽 `0.064*字号` 的竖缝，模拟镂空喷漆模板的"桥"；字体是 Big Shoulders、Barlow 等加回退列表；`document.fonts.load` 完成后重画。
- **出血 `bleed`**：整张画布先铺目标色、alpha 0.012，防止 mip 混进黑边。
- **贴花材质**：
  - MeshStandard，`transparent`，`depthWrite: false`，`polygonOffset −2/−2`。
  - 每种有自己的粗糙度和金属度：油斑 0.12、锈流挂 0.9、弹孔金属 rough 0.4 / metal 0.8、焦痕 0.95、文字 0.65。
  - 曲面贴花用 `UA()` 生成圆柱条带；瓦楞面用前面说的扫掠贴合。
- **地面标线**：
  - 画布坐标直接设成世界米（`setTransform(s, 0, 0, o, ...)`），`lighter` 叠加；R/G/B 分别表示黄线、白线、轮胎印。
  - 轮胎印是 46 条成对二次曲线，alpha 0.1–0.32，外加刹车短痕。
  - 着色器里的阈值、碎边、磨损见 T4。黄色反照率 (0.52, 0.34, 0.035)、白色 0.47，再 ×(0.72–1) 褪色。**白漆不是 1.0。**
- **没有 SDF 字体**，都是光栅画布；地面在 1 texel 以下改用双三次，再加世界空间噪声补边缘细节。

**3. 为什么不假**：每个贴花都是"旧的"，而且有自己的粗糙度，比如油斑比地面更光滑。

**4. 迁移**
- 需要 `await document.fonts.ready` 后再画；它原来用 `setTimeout(120ms)` 重画，这是异步状态，离线必须先等字体再 seek。
- 做旧用种子随机 `aA(lA(name)+17)`，确定。

**5. 成本（估计）**：做旧约 20 行，文字约 30 行，每个贴花 5–30 行；零运行时开销。

#### T9. 三平面映射（武器和小件）+ UDN 式法线混合（套件缺）

- **在哪里**：5285–5305 行（顶点）、5322–5326 行、5422–5433 行（法线）；使用者为 `_A` 集合里的材质（gunmetal、polymer、carbon、armor 等）。

#### T10. 无状态的顶点动画与"属性驱动的实例化"（套件有 InstancedMesh；这里用的写法更适合 seek）

- **闪灯**（5442–5449 行，`pb()`，标识符 `vBlink`）：
  - 合并网格，每顶点属性 `blink = (周期, 相位, 占空比)`：
    `bph = fract(uTime/period + phase)`，`vBlink = mix(0.02, 1, smoothstep(0, 0.06, bph)*(1 − smoothstep(duty, duty+0.12, bph)))`。
  - 灯体是 HDR 红色 [9, .5, .25] 的八面体，周期 2.6 s，占空比 0.45。
- **海鸥**（5450–5463 行）：一个 BufferGeometry 装 12 只，每只 6 个顶点；属性 `aOrbit = (中心, 半径)`、`aPar = (角速度, 相位, 扑翼频率, 是否翼尖)`。
  - 位置 = 绕圈 + 上下起伏 `sin(ga*0.7)*2.2 + sin(t*0.23)*1.5`。
  - 滑翔/扑翼切换：`glide = smoothstep(−.2, .5, sin(t*.31 + ph*3))`；翼尖抬高 `gflap*|z|`。
  - 你提到的 `transformed = gc + gfw*gl.x + grt*gl.z + ...` 就是用"前方向 / 右方向"基矢重建世界坐标，不需要实例矩阵。
- **CPU 端摆动**（5463 行 `Eb.update`）：吊具 `0.012*sin(x*.52) + 0.004*sin(x*1.31+1)`，船 `0.05*sin(x*1.15) + 0.025*sin(...)`，雷达 `x*1.9`。全是闭式函数，**但 x 是 `x += dt` 累加出来的**；关卡风扇也是 `rotation.x += L*1.7`。迁移时直接用 t 替换。
- **海浪**（5650 行）：深水色散 Gerstner。4 个大波 `B1 = [dirx, dirz, 波长 9.5/5.7/3.3/2 m, 振幅 .06/.04/.026/.016]`，`k = 2π/λ`，`ω = sqrt(9.81k)`，另有 7 个细波 `Db`。JS 端 `Lb()` 用同一套公式供物理查询，再往后的海面着色器不在我这段。
- **迁移**：都是 t 的纯函数，几乎可以直接用。草、旗帜在这段里没有出现。

### 三、方法论（只写代码里有证据的）

1. **先列出真实世界里这块表面有哪些层，按形成的时间顺序叠上去。** `n3` 的 OV 顺序是：粉化 → 污膜 → 锈渍 → 底漆 → 锈 → 新鲜钢（4931–4936 行）。地面注释逐层列出：遮罩 → 细节 → 伸缩缝和填缝 → 裂缝（部分已封）→ 基底 → 标线 → 水 → 粗糙度 → 法线（5507–5595 行）。
2. **每个噪声都写明物理成因，并带方向性。** 注释里有："traffic lanes worn matt"（4898）、"sealer still intact"（4897）、"rain-washed lighter streaks"（4928）、"drip end of the upper sheet"（5074）、"−V is down"（4795）、"traffic-polished lanes"（5538）。磨损遮罩故意做成各向异性，22 m × 0.9 m 顺车道（5463 行 `Rb`）。
3. **用物理单位思考。** 凹凸以毫米计（`K = bump*0.001*D/tile`）；平铺以米计；UV 以米计；集装箱用 ISO 尺寸；注释写"~5 cm ramp""roughly 10–30 cm""about a metre""40 / 15 / 5 cm"（5569–5578 行）。
4. **粗糙度的变化比颜色更重要。** 环氧地坪的颜色只随磨损变 10%，粗糙度却从 0.1 到 0.52（4899–4910 行）；地面颜色变化温和，粗糙度跨 0.055–0.74 并单独写注释（5588 行）；湿润时优先改粗糙度和法线（5411、5436 行）。
5. **用连续斜坡，不用硬阈值。** "water: one continuous gradient"（5568）、"never a black cut-out"（5585）；几乎所有遮罩都是 `smoothstep`，带 0.03–0.14 的过渡宽度；遮罩边缘也做了 5% 淡出（5509 行）。
6. **大部分干净，破损成簇、少量出现。** "damage clusters; most of the panel is clean"（4798）、`rustMask` 注释"higher = rarer"（4785）、裂缝只在部分板上（5529 行）。
7. **全场共用一套模型，保证统一。** `paintDmg` 被漆面、警示条纹、护甲共用（4944/4950/5154 行）；`SL_TINT` 让一套贴图服务 8 种漆色；`Kn.finish` 给所有道具加同一种接触污垢；全局一个 `wet` uniform 同时驱动所有材质和地面（`uWetG = mats.uniforms.wet`，5643 行）。
8. **环境逻辑由几何决定。** 朝上的面湿、朝下的面不湿、竖面有流痕（5352 行）；贴地 0.5 m 有溅湿带（5364）；污垢沉进 AO 缝里（5347）；室内只湿 12%（`uSlX`）；锈从破损处往下流（4814–4819 行）。
9. **把抗走样当成设计约束写在注释里。** "no texel edge of a data map can ever show"（5473）、"never the texels of a map"（5550）、"wires stay ~1 px wide through the mips"（5397）、"no white sheets in the sun"（5404）、"a touch soft, never razor sharp"（5631）；细节按距离逐层淡出（5553、5570、5602 行）。
10. **大尺度唯一 + 小尺度平铺 + 世界空间宏观噪声，三者互不相关。** 唯一遮罩 80 m；细节两层 4.76 m 和 0.73 m，比例不整；材质再叠世界空间 3D 噪声（0.35–6 每米）。重复周期在任何距离上都对不齐。

### 二、技法清单（按重要性排序）

#### 1. 一个事件驱动所有通道的事件总线
- **做了什么**：武器只负责 `emit("weapon:fire")` / `emit("impact")`，特效、音频、HUD、AI 各自订阅。特效的订阅在 5928@32524，音频在 @81795–86396，HUD 在 6076@11696，AI 在 6076@6080。每个订阅者自己带节流和优先级。
- **为什么有冲击力**：同一帧里光、粒子、声音、镜头、HUD 一起响应，但各自的时间常数不同：光 50ms、火光约 45ms、枪模弹簧约 60ms 到峰、相机回正 154ms、烟 0.5–4s、尾音 1.5–2.3s。这就形成了"一个瞬间加一串余韵"。
- **迁移到 seek(t)**：做一张事件时刻表 `[{t, type, id, pos, dir, surface…}]`，每个通道写成 `channel(t) = Σ_{事件 e, t_e ≤ t} f(t − t_e, hash(e.id))`。节流（光至少隔 0.09s、声音至少隔 22ms、尾音的连射结束规则）对整张表一次性预计算即可，结果只依赖事件表，仍是纯函数。
- **套件**：缺。约 150 行（编排器加节流预计算）。

#### 2. 不对称的相机与枪模运动
后坐、屏震、着陆、晃动、摆动的参数集中在 5928@100641 的 `Mt` 表，相机合成在 @106631。

**后坐**
- 见上表：约 29ms 起、保持 90ms、154ms 时间常数收；35/65 拆成"准星真实偏移"和"可恢复的视觉偏移"。
- 枪模（6054@8645）用欠阻尼弹簧，ζ 在 0.55–0.71，会有一点过冲。

**屏震**
- 创伤值线性衰减（每秒 1.7），振幅取创伤值的平方。
- 不用噪声，用两个正弦相加：
  - 俯仰：0.03rad·(sin43.1t + 0.6sin(71.7t+1.3))
  - 偏航：0.03·(sin(37.3t+2.1) + 0.6sin83.9t)
  - 滚转：0.045·(sin(29.7t+0.7) + 0.5sin(61.3t+4))
- 频率 4.7–13.4Hz，滚转幅度最大。由于取平方，小创伤几乎看不出来，大创伤很猛。

**着陆**
- 二阶弹簧 x″ = −150x − 17v（ω=12.2，ζ=.69）。冲量 min(下落速度×0.36, 3.2)，位移限制在 [−0.2, 0.05]m。同时带动俯仰 x·0.12rad。
- 下落速度 >7.5 加屏震，>13 扣血。

**头部晃动**
- 相位 = 累计移动距离 / 步幅（走 1.55m、跑 2.1m、蹲 1.05m）。
- 垂直 −cos(2πh)·0.024，水平 sin(πh)·0.013（频率减半，左右脚交替）。水平分量再 ×0.35 计入滚转。
- 晃动幅度以速率 9 跟随，冲刺 ×1.9，瞄准 ×0.22。停下时相位以速率 8 吸附到最近的整数步，落在一只脚上。

**横移倾斜**：目标 −横向速度/6.4×0.02rad（约 1.1°），速率 8 跟随，瞄准时 ×0.4。

**枪模晃动**（6054@12872）
- 垂直：`sin2φ·0.0042 − (0.5+0.5cos(2φ+0.6))⁴·0.0048`。四次方项让每一步有一个尖锐的下沉，相当于落脚重音。
- 水平 sin φ·0.006；滚转 sin φ·0.014。

**呼吸**：只作用在枪模上，周期很长（0.85/1.7/0.6/0.5 rad/s），振幅 1–4mm 或 0.002–0.004rad，瞄准时 ×0.3。相机本身没有呼吸。

**枪模延迟跟随（sway）**：鼠标增量作为冲量（每帧限 ±0.2rad，×3.2/×2.6），弹簧 k110 c15（1.67Hz，ζ=.71），限 ±0.09/±0.07。相机本身没有惯性，直接跟鼠标。

**跳跃与落地**：起跳 jY −0.22、jP +0.7；落地冲量 clamp(−vy·0.06, 0, 0.6)，jP 乘 3.2；空中偏移随竖直速度变化。

**死亡镜头**：Z = smoothstep(0, 0.85s)。眼高按 Z² 降到 0.22m，滚转 1.15·Z²（66°），俯仰 −0.25Z + 0.12sin(πZ)。

**迁移**
- 弹簧和指数逼近都是线性系统，冲量响应可以叠加：x(t) = Σ v_k·h(t−t_k)，h 是阻尼正弦闭式解（套件已有弹簧）。
- 后坐的"保持 90ms"每发都会重置，严格说不能叠加。近似办法：保持到连射最后一发 +90ms，再按指数回正。或者从连射开头起定步重放（连射通常不到 3s）。
- 创伤值是分段线性，扫一遍事件表就能求出来；屏震取绝对时间 t 的正弦，天然纯函数。
- 晃动相位 = 相机样条的弧长 / 步幅，是闭式解。
- **套件**：hitShake、弹簧、手持抖动已有；"创伤值平方 + 多正弦"、后坐 35/65 拆分、着陆弹簧、步幅相位晃动缺。约 120 行，计算开销可忽略。

#### 3. 受光的程序化烟（不像圆球的关键）
**贴图**：程序生成 4×2 序列帧图集，每帧 128px（5814@6115 `Bb`）
- 帧 0–5：fbm 域扭曲（偏移幅度 0.6）后取径向衰减；半径本身用 fbm 扰动；内部叠 5 个八度的细节。
- A 通道 = 透明度，B = 厚度，RG = 由透明度高度场求梯度得到的法线。
- 帧 6 是向上收窄的火舌，帧 7 是较密的烟团（扭曲幅度 0.3）。边缘留遮罩防止相邻帧串色。

**着色**（VR，5888–5920）
- 侵蚀阈值随寿命上升：`er = 年龄·0.45`，`a = smoothstep(er, er+0.6, tex.a)`。越老越碎成丝，不是整团变淡。
- 法线 = 图集法线 + 0.55 倍的球面法线。
- 包裹光照 `((N·L+0.45)/1.45)²`；逆光前向散射 `pow(dot(−V,L),5)·(0.15+1.3·薄度)`。
- 半球环境光（低/高两色按 N.y 混合，乘 (1−0.35·厚度)）。
- "阴影"用一次射线检测：向太阳方向打不通时 shade=0.2。

**火焰**：火焰团特意用 alpha 混合，不用加色。源码注释原话："overlapping lobes keep their shape and smoke in front can occlude them"（重叠的火团保持形状，前面的烟能挡住它们）。

**软粒子**：读深度，淡出距离 = clamp(尺寸×0.4, 0.04, 0.7)；离镜头 0.2–0.9m 内再淡出一次。

**混合**：输出预乘 alpha，混合因子 One / OneMinusSrcAlpha，在色调映射之后再预乘（5919）；alpha 通道 Zero/One，不破坏目标 alpha。

**烟的运动**（5928@18152）
- 尺寸 = s0 + (s1−s0)·(1−(1−年龄)^2.5)：一开始猛涨，之后慢慢变大。
- 透明度：前 6% 线性淡入，30% 之后 smoothstep 淡出。
- 初始旋转随机，旋转速度 ±0.6rad/s；扰动 0.5；向上浮力和受风比例逐团设置。

**迁移**
- 图集用 Canvas 或 Node 预烘焙一次，固定种子。
- 阻力 + 重力 + 风的闭式解：
  - 速度 v(τ) = (w − g/k) + (v0 − w + g/k)e^(−kτ)
  - 位置 x(τ) = x0 + (w − g/k)τ + (v0 − w + g/k)(1 − e^(−kτ))/k
- 原代码的扰动是 sin(位置·k + t)，有位置反馈。改成只依赖时间的正弦速度，积分后得到闭式位移 Σ A·(1−cos ωτ)/ω。
- 每帧排序是无状态的，不影响纯函数。
- **套件**：图集粒子已有；程序化烟图集、法线受光、寿命侵蚀缺。约 250 行（图集 120 + 着色器 80）。成本估计：近处大烟团会造成整屏多层重绘；在 SwiftShader 软件渲染下，1080p 每帧可能要几十到上百毫秒（估计值），需要限制同屏烟团数。

#### 4. 速度方向拉伸的火花和曳光
- **顶点着色器**（HR 5815–5865）有三种模式：0 面向相机；1 沿速度拉伸；2 贴在表面上。
- **模式 1**：拉伸轴 = 速度 × stretch（火花 0.03s，即"拉成 30ms 走过的距离"），宽度方向取 cross(方向, 指向相机)。宽度至少 1.4 像素（`uPx` 是距离 1 处一个像素的世界尺寸，每帧由投影矩阵算出），同时把亮度乘以 尺寸/实际宽度 来补偿。效果是细线不闪、不断续，总能量不变。加色粒子再限制屏幕宽度上限（曳光贴近镜头时不会糊满屏）。
- **颜色随寿命冷却**（5928@4746）
  - 色带 1（火花），E=1−年龄：r·E^0.5，g·E^1.4，b·E^3。白黄 → 橙 → 红。
  - 色带 2（火焰），Q=1−年龄^1.6，K=Q^1.5：r·K，g·(0.22+0.78Q^1.3)K，b·(0.04+0.96Q^3.5)K。
  - 色带 3：闪烁 0.55+0.45sin(17t + 种子×9)。
- **HDR 亮度**：火花 30–40，枪口星芒 34，曳光 16，配合泛光。
- **火花图集**（5814@7641 `Ob`）：软点（三次衰减 + 高斯核）、条纹、两种星芒（7–10 条随机射线 + fbm + 热核 exp(−70d²)）、冲击环、尘团、圆盘、泪滴火焰。全部灰度，颜色由粒子自身的 HDR 值提供。
- **迁移**：拉伸方向直接用闭式速度 v(τ)，无需状态。
- **套件**：缺。约 80 行着色器，开销很低。

#### 5. 动态光的闪烁写法
- 预分配 6 盏点光源（4733 `x`），全程不增减。这样着色器排列组合不变，不会触发重新编译。
- `flash(位置, 颜色, 强度, 半径, 时长)`：强度 = 峰值 × 剩余/总时长（线性）。没有空闲光时，抢剩余时间最短的那盏。
- 持续火源 `acquire()`：强度 (14 + 6sin23t + 4sin37.7t)×缩放，色 0xFF8A3A，半径 9m（5928@31761）。
- 各事件的数值见第一节。
- **迁移**：光强 I(t) = Σ_e 峰值·max(0, 1 − (t−t_e)/时长)。
- **注意采样**：50ms 的闪光在 30fps 下只覆盖约 1.5 帧，可能落在两帧之间。办法二选一：把事件对齐到帧，保证峰值落在某一帧上；或者用套件的运动模糊做时间超采样。曳光同理，要保证至少可见 2 帧，原代码就是这么做的。
- **套件**：缺。约 40 行。

#### 6. 弹孔贴花、碎块、弹壳（"余韵"层）
- **贴花**（5814@9515 `Hb`）：Canvas 程序绘制 4×2 图集，每格 256px：金属/混凝土/木/玻璃弹孔、焦痕、烟熏。每张都同时画颜色和高度，再用 Sobel 从高度生成法线贴图，另有 ORM 贴图。
- 贴花环形缓冲 160 个（5928@13643），用多边形偏移 −4 防止 z 冲突，木纹弹孔的随机角度只有 ±0.15rad（顺着木纹）。缓冲满了以后，最老的 14 个按序号逐渐变透明。
- **碎块**：256 个实例化的扰动立方体，弹跳恢复系数 0.32，最后 0.5s 缩没。**弹壳**：60 个实例，见第一节。
- **迁移**：贴花是累积状态，但第 n 个贴花的透明度只取决于"t 之前一共发生了多少次命中"，从事件表算得出来，仍是纯函数。弹壳翻滚每一段角速度恒定，四元数 = exp(ω·τ)，闭式解；弹跳套件已有。
- **套件**：弹跳已有；贴花缺。约 300 行。

**混音链**（5928@72651–73534）
- 总线增益：world 1、near 0.95、amb 0.55、dry 1、music 0.62。
- 主链：压缩器（阈值 −10dB，拐点 6，比率 6，起 2ms，释 140ms）→ ×0.45 → 软削波（0.6 以内线性，以上走 tanh，2 倍过采样）→ 主音量。
- 混响送量：world 0.9，near 0.32；音乐 0.2 送室内混响。按"人在室内的程度"在室外/室内两个卷积器之间交叉。
- 空间化：反比距离模型，参考距离 3，衰减系数 0.6，等功率声像；只有敌人的循环音用 HRTF。
- 复音：world 22、near 12、dry 8、music 3 个声部，按优先级抢占。
- 每次播放：音高 ±3.5%、增益 −0~8% 随机；变体轮换，30% 概率跳过一个。
- 闷音：全局低通 20k·0.03^Z（见受击、爆炸两节）。

**为什么枪声不廉价**
1. 分层：瞬态、身体、爆压、空气、机械各管一段频带和时间。
2. 尾音和枪声分开：随场景切换室内外，全自动时在连射结束才补尾。
3. 软削波加压缩，响但不破音。
4. 4 个变体加音高抖动，避免机关枪般的重复感。
5. 弹壳声、混响、音乐压低作为余韵和对比。
6. 受击和爆炸后的低通闷音，造成"耳朵被震到"的主观感。

**迁移**：这些配方本身就是"缓冲区 = f(采样率, 种子)"，可以几乎原样搬进 film-narration 的合成器（Node 端，Float32Array）。卷积、压缩、声像在离线混音里实现简化版即可，也可以用 OfflineAudioContext。原作者已经写了一个 OfflineAudioContext 自测（5928@88917）：按脚本跑 10s 场景，统计峰值、过载、NaN 和每 0.5s 的 RMS。这个可以直接作为音频门的思路。

**套件**：现有 7 种简单音色加 Freeverb；分层枪声、爆炸、模态金属、碎响颗粒、IR 生成、闷音、音乐压低、变体轮换都缺。DSP 基元约 120 行，每个配方 5–20 行，混音器约 200 行。

### 四、主循环与性能预算

- **可变步长**：dt 限制在 50ms 以内；URL 参数 `?dt=` 可以强制固定步长（6182@22172），这是为截图和录制留的钩子。没有固定步长的累加器，也没有 hitstop 或 timeScale。
- **预算**：
  - 特效总共 5 次绘制调用；受光粒子上限 1400，加色上限 3200，曳光 48，碎块 256，弹壳 60，贴花 160。
  - 远处粒子减半；光池固定 6 盏。
  - 音频合成按每 6ms 切一片异步进行，启动时只先合成必需的音效。
  - render 模块（4733 行）有动态分辨率对象，不在我的区域，没有细读。
- **随机性**：特效用 `Math.random`，不确定；音频、敌人、武器用带种子的 fork。迁移时把特效的随机统一换成 `hash(事件id, 粒子序号, 通道)`。

### 五、方法论（只列在代码里找得到证据的）

1. **按模块分工、契约式拼装**
   - CSS 头注释写明 "game/ui.css — owned by the Game agent"（行 8）。
   - 每个模块都有降级占位 `dr.*`，加载失败就换成占位继续跑（6182@19240）。
   - 武器、敌人、特效之间只通过事件总线和少量接口（`addRecoil` / `addShake` / `fx.*`）交互。
2. **每个模块都做了独立展示场景，用参数冻结画面来自查**
   - `showcase` 加 URL 参数：`fxshow` 选效果，`fxt` 以 1/30s 定步预跑，`fxage` 把爆炸以 1/60s 定步重放到指定年龄后截图（5928@33931、@36479）。
   - 敌人有 `epre` 预跑 60Hz 和 `efreeze` 冻结（6076@8118）。
   - 后期效果有展示场景，按相机高度切换 damage/ads/flash/fade（4733）。
   - 这就是"定步重放后截静帧检查"。
3. **集中的数值表，参数有名有单位**：`Mt`（5928@100641）、`Zv`/`Kv`/`Ui`（6054@32651、@60533）、`Yi`（6182@4883）。手感参数和逻辑分开存放。
4. **注释写物理理由，而不是口味**："real sights tilt the glass a few degrees"、"forward scatter through thin edges"、"NOT additive… smoke in front can occlude them"、"premultiply after the output transform"、"cap on-screen width (tracers near the lens)"、"denser near the player"（5936、5902、5909、5919、5845、5781）。
5. **可量化的自检工具**：音频离线自测（峰值、过载、NaN、RMS）在 5928@88917；性能基准模式在相机样条上跑，输出 p99 帧时间（6182@23355）；`window.__errors` 和 `__frames` 供外部采集（6182@17784）。
6. **可读性和公平优先于随机性**：攻击令牌制、预警时长与音高绑定、波次警告提示来向、远处粒子减半、各类节流（6076@146，5928@84939）。
7. **用"时间不对称"做冲击，而不是加大幅度**：所有冲击都写成"快速冲量 + 慢速指数或欠阻尼回落"（kn 的速率 34 对 6.5、弹簧 ζ 0.55–0.7），多个通道用不同的时间常数响应同一事件，余韵（烟、尾音、弹壳、贴花）的时长是冲击本身的 10–100 倍。

### 六、给套件的补齐建议（按收益排序）

1. **事件编排器**：一张事件时刻表，配上各通道的"自事件起经过时间 → 响应"函数，再加节流预计算。这是第一节那张表的直接落地。
2. **动态光闪**加**帧对齐 / 最短可见帧数规则**（必须解决 50ms 闪光与 33ms 帧间隔的采样问题）。
3. **速度拉伸火花**：像素宽度下限 + 亮度补偿 + 三种冷却色带。
4. **程序化烟图集**：法线、厚度、寿命侵蚀、包裹光照加逆光散射；火焰用 alpha 混合。
5. **film-narration 的分层配方**：枪声（瞬态、身体、爆压、空气、机械 + 室内外尾音）、爆炸、模态金属、碎响颗粒、IR 生成、闷音和音乐压低。
6. **相机手感菜单**：创伤值平方 + 多正弦屏震、后坐 35/65 拆分、着陆弹簧、步幅相位晃动。
