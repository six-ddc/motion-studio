# 先看后写：参考锚、风格帧比稿、粗剪预演，以及画面先行配方

目录：0. 这几步在换什么 · 1. 参考锚 · 2. 风格帧比稿 · 3. 粗剪预演 · 4. 两个便宜的确认点 · 5. 画面先行配方 `visual`

## 0. 这几步在换什么

长相和节奏如果只在文字里定，要等整片渲出来才第一次被看见，那时改结构的成本最高：时间轴、分镜断言、音效都已经挂在上面。下面三步把判断挪到更便宜的时刻，**都是可选的**，各自写了跳过的代价。它们不规定选什么长相，只规定"在像素上选"。

| 判断 | 最便宜的时刻 | 那时改的成本 | 拖到成片再改的成本 |
|---|---|---|---|
| 长相 | 风格帧（一个方向一页、一帧） | 重写几十行 | 全片每一镜的绘制代码 |
| 节奏、镜头长度、顶点位置 | 粗剪预演（占位形状） | 改一张镜头表 | 精修好的镜头要重排、重对声音 |

## 1. 参考锚：审美从哪来

本片的审美判据只在 style_guide 里，但 style_guide 自己要有来源。四种来源，代价不同：

| 来源 | 怎么用 | 代价 |
|---|---|---|
| 用户给的参考（片子、图、网站、品牌手册） | 拆解它（`deconstruct.md`，运动手感用 `motionprint.mjs`，取色用 film-assets 的 `media.mjs tiles`），写下取哪几个维度 | 要花一轮拆解；参考只能当判据，它的素材能不能用另由 film-assets 判断 |
| 外部设计 skill | 整体采用它的方向（`divergence.md` §0） | 它的取舍一并带进来；动起来的部分多半要自己补 |
| 仓库里的近作 | 有意重复（`divergence.md` §3） | 系列感换来的是和上一支撞脸 |
| 无锚，只从机制和 brief 推 | 照 `divergence.md` §2 发散 | 候选都出自同一个模型的文字想象，容易落回它最顺手的那一种；这时风格帧比稿（§2）最值得做 |

写在 style_guide 的「参考锚」一节：是谁、**取什么**（调子、材质、镜头、字的身份、色、运动节奏里的哪几项，尽量换算成数：色值、t80、镜头平均时长）、**不取什么**。把一个参考的所有维度都取走就是复刻，代价是撞脸和版权风险；通常取两三项就够定调。brief 没给参考、用户又在意长相时，开工前问一句"有没有想要像的片子或页面"，比事后改便宜。

## 2. 风格帧比稿：在像素上挑方向

`divergence.md` §2 的视觉方向候选写完后，活下来的两三个各画一帧，再挑。

1. 每个方向写一页 `films/<slug>/look/<名>.html`：和正式场景同一份契约（`#stage`、`window.seek`、`window.DURATION`、`ready`），但只画**承重那一刻**的画面，用真的文案和真的字体。`DURATION` 可以只有 1 秒；想同时看"动之前"和"动之后"就让 seek 在两个状态间插值。
2. 拼成一张图：

```bash
node <film-critique>/scripts/stills.mjs --film <slug> --entries look/a.html,look/b.html,look/c.html          # 每个入口一行，取各自时长的中点
node <film-critique>/scripts/stills.mjs --film <slug> --entries look/a.html,look/b.html --at 0.1,0.9          # 每个方向看两个状态
```

3. 用 Read 打开 `out/lookdev.png`，按 `divergence.md` §2 的五条判据在图上判，然后**交给用户挑**（§4）。选定的方向和落选的输在哪照常写进 style_guide「视觉方向」，并写上比稿图的路径。

选定的那一页是 scene.html 的起点。落选的页面不是入口，门不会去渲它们；但片子目录里的文件都算收据的输入，交付之后再改或删它们，accept 会报红，所以不想留就在 deliver 之前删掉。代价：每个方向几十行绘制代码。值得做的情况：新片、没有参考锚、候选之间差在材质或镜头这类文字说不清的维度。可以不做的情况：系列片沿用、brief 已经指定长相、候选只差在讲法上。

## 3. 粗剪预演：先把时间跑通，再精修

时间的数据来源定下来之后（旁白时间戳、节拍栅格或一张具名时刻表）、精修任何一镜之前，先让全片以最低保真跑一遍：

- scene.html 里写全镜头表，每一镜只画**占位**：色块、轮廓、一行镜头名。**时刻、镜头运动、转场用真的**（它们正是这一步要看的东西）。
- 出小样并拼接触表：`render.mjs --scale 0.25 --sub 1 --preset veryfast`，再跑 film-critique 的 `contact.sh`。声明了 `rhythm` 的片子这时就可以跑 `check.mjs`，它只报疑点。
- 看节奏，不看长相：哪一镜太长、顶点落在哪、连续几镜是不是同一景别和同一强度、镜头运动有没有动机、开头几秒有没有东西可看。

代价是多一轮小样渲染，占位的绘制代码之后会被替换（镜头表、时刻、相机留下）。值得做的情况：多镜头、十五秒以上、节奏跟着音乐走。可以不做的情况：单镜头片、循环动图、只改已有片子的几秒。

## 4. 两个便宜的确认点

模型看不到运动、听不到声音，主观判断最后都要落到人身上。成片之后再请人看，改动最贵，也最容易变成一条长期挂着的"未经人眼确认"。更便宜的两个时刻：

- **风格帧选向**：给用户一张 `out/lookdev.png`，问选哪个方向、哪里要调。
- **粗剪定节奏**：给用户一条小样，问哪里拖、哪里赶。

用户明说"直接出"时两处都跳过，在 review_log 记一句"长相和节奏未经人确认"。确认过的内容写进 style_guide（长相）和 beats.md 或 shotlist.md（节奏），之后的改动要对着它解释。

## 5. 画面先行配方 `visual`

```bash
node <film-core>/scripts/new-film.mjs <slug> --recipe visual
```

适合宣传片、片头、MV、logo 演绎、界面演示这类**镜头节奏比台词重要**的片子。顺序是：brief（含参考锚、时间从哪来）→ 风格帧比稿 → 节奏骨架 `docs/beats.md` → 粗剪预演 → 逐镜精修 → 声音贴画 → 自检 → deliver。它和解说片配方的差别只在时间的数据来源：

| | 解说片 `explainer` | 画面先行 `visual` |
|---|---|---|
| 镜头边界读谁 | 旁白的字级时间戳 | 配乐的节拍栅格，或 scene.html 里唯一的一张具名时刻表 |
| 代价 | 镜头长度跟着句子走，画面容易变成台词的配图 | 旁白（如果有）要按镜头时长去写，句子可能要删改；没有分镜断言对账 |
| 文档 | facts、mechanism、shotlist | brief、beats、style_guide |

- **有配乐**：先定曲子再排镜头（节拍栅格见 film-narration），beats.md 的起止写拍号和段落名。
- **没有配乐也没有旁白**：在 scene.html 开头写一张具名时刻表（`const T = { open: 0, turn: 2.4, … }`），全片只引用名字。秒数只出现在这一处，改节奏时不用满文件找数字。
- **有旁白但它是从属的**：镜头定了再写词、再合成，合成之后**字词触发的事件仍然读实测时间戳**（音频对齐的规则不变，变的只是谁迁就谁）。句子比镜头长时，改词、调语速或给那一镜加时长，三选一写进 beats.md。
- **机制**：这类片子未必有一个撑起整片的变量，mechanism.md 不在配方里；有的话照常写。视觉方向和近作对照仍然留痕（配方声明了 `divergence`）。

配方声明的检查：`divergence`（视觉方向与近作对照的留痕）、`page` `mp4` `readability` `contrast` `style-guide` `laws` `still` `cover`，以及只报疑点的 `rhythm` `continuity`（镜头长度分布、静止占比、镜头交接）和 `motion` `variety` `hook` `beatsync`（起停突变、同时运动区域、匀速段、镜头间构图变化、开头几秒、事件与拍点的偏差；没有节拍文件时 beatsync 跳过），见 film-critique `references/checks.md`。不想要哪项就从 film.json 的 `checks` 里删掉。
