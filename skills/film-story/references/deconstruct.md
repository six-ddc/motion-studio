# 参考影片拆解：拆机制和节奏，不抄画面

目录：借什么 · 找参考 · 拆解表 · 拆节奏的方法 · 量运动手感（`motionprint.mjs`）· 拆风格参考：取规则，不取帧 · 产出给谁

## 借什么

拆解的对象是**决策**，不是**结果**：它为什么第 2 秒就给出数字，高潮为什么放在 70% 处，旁白为什么比画面慢半拍。

| 借 | 代价 | 什么时候值得 |
|---|---|---|
| 机制（核心变量到视觉量的映射） | 需要自己重新找视觉实现 | 几乎总是值得 |
| 节奏结构（钩子位置、信息密度曲线） | 几乎没有 | 总是可以借 |
| 具体画面、构图、配色、字体 | 导致同质化并带来版权风险，片子会被认出"像 XX" | 明确做致敬或戏仿时，并且在 brief 里写明 |

## 找参考

同题材的参考搜"<主题> 动画 / explainer"，同机制的参考直接搜机制本身（"kinetic typography history"）；优先选有口碑的。x.com 上的短片用 browser-cli 打开（WebFetch 会返回 402），下载交给 film-assets。看不了成片时，就拆解官方分镜、幕后资料或字幕稿，并标注"未看成片"。

## 拆解表

每支参考片写一张，写进 `docs/references.md`（或 facts.md 末尾的 `## 参考`）：

```markdown
### R1 <片名> — <作者/频道>，<时长>，<URL>
- 核心变量: 它在讲什么东西在变
- 映射: 核心变量 → 哪个视觉量（位置/面积/浓淡/速度/数量/颜色）
- 钩子: 第几秒、靠什么（反常识数字？悬念？视觉奇观？）
- 节奏: 按秒列关键拍，标信息密度（每拍新增几条信息）
    0.0-2.0  钩子：…
- 高潮: 第几秒（占全片百分比）、是什么
- 旁白与画面: 谁领谁？差多少
- 画面系统 × 绑定的词: 反复出现的画面系统各在哪些词被念到时出现（"计数器跳动 ← 每个数字词"）
- 运动手感: motionprint 的数字：t80 中位、峰值速度（% 短边/s）、静止帧占比、能量峰在哪几秒。只记数
- 事实密度: 全片几个数字/年份？观众能记住几个？
- 失败点: 哪里看不懂/拖/信息过载
- 可借: 只写机制和节奏层面的
- 不借: 明确写出不要带进来的画面元素
```

## 拆节奏的方法

1. 逐秒（或按镜头切点）记下每一拍"屏幕上新出现了什么信息"。可以用帧网格辅助：film-assets 的 `media.mjs tiles` 均匀抽帧，`--cuts` 每个镜头一格，`--words` 标出那一刻念到的词，拆解表的"画面系统 × 绑定的词"一栏就对着它填。
   参考片的转写用 film-narration 的 `align.py --from <视频>` 反推。它会写入 `--film` 所指目录的 `narration.json`，所以要给参考片单独建一个目录，不要指向正在做的片子。
2. 画出信息密度曲线（横轴是秒，纵轴是新增信息条数），看它是前重后轻、均匀分布，还是有一个峰。
3. 标出叙事权重最高的那一拍分到了多少物理时长，facts.md 的叙事骨架要做的正是这件事。
4. 和本片 facts.md 的承重列表对比：两边承重事件不一致的地方，往往就是机会。

## 量运动手感（`scripts/motionprint.mjs`，只测量，不设阈值、不判 FAIL）

```bash
node <film-story>/scripts/motionprint.mjs <参考片.mp4> --out <目录>     # 参考片或自己的成片 out/*.mp4
node <film-story>/scripts/motionprint.mjs --film <slug> [--from s --to s] # 自己的场景：用 window.anchors(t) 的轨迹，逐锚点
node <film-story>/scripts/motionprint.mjs --curves                        # 运行时每条缓动 / 弹簧预设的 t80，对着它挑
node <film-story>/scripts/motionprint.mjs --film <slug> --probe [--from s --to s] [--keys a,b] [--table]
```

`--probe` 逐帧读场景的 `window.probe(t)`（`{名: 数}`，film-critique 分镜断言用的同一个可选钩子；镜头偏移、震动、亮度……），倒序再取一遍查纯度，
标出"前后都顺、唯独这一帧速度突变"的帧（位置跳、震动带偏移起拍；`--jump x` 改成绝对阈值）。只是读数，不是门；怀疑"那一刻镜头跳了"时用它代替手写重算脚本。

| 数 | 含义 | 怎么读 |
|---|---|---|
| t80 | 一段运动走完 80% 行程所用的时长占总时长的比例 | 0.23 约等于 `expo.out`（一下到位），0.42 约等于 `cubic.out`，0.63 约等于 `cubic.inOut`，0.8 相当于匀速 |
| 峰值 / 中位速度 | 单位是 px/帧（源分辨率），另外给出"% 短边/秒" | 跨画幅比较时用后者；视频模式下取的是主导运动的中位数，不区分单个物体 |
| 静止帧占比、最长安静 | 帧差小于 0.5 的帧所占比例 | 片子在哪里"停下来让人看" |
| 能量图 | 每 1/12 s 一个字符，每行 4 s | 动作集中在哪里，高潮那一拍有没有对应的能量峰 |

视频模式（ffmpeg 帧差加金字塔 Lucas-Kanade）有几个盲区：淡入淡出和物体的出现、消失不计入速度；多个物体反向运动时，中位数会互相抵消；大位移的第一帧读数偏低。精度要紧时，对自己的片子改用 `--film`。参考片和自己的片子各量一次，并排比较；改不改由本片 style_guide 决定。实测记录见仓库 `docs/verified/film-story.md` §2f。

## 拆风格参考：取规则，不取帧

用户拿一支片子说"要这个感觉"时，要拆的是**这种长相是从哪条规则长出来的**。把参考片的镜头顺序换个题材重走一遍，得到的是复刻，不是风格。拆三样东西，写进拆解表的 `可借`：

1. **所有物体都遵守的那一条规则**（"每个字都装在一个机加工零件上"、"一切都是同一种纸剪出来的"）。配色、网格、字体往往从这条规则推出来。方法是随机抽 5 帧，对每个物体问"它为什么长这样"，直到答案收敛成一句话；收敛不了，就只借单项手段。这样做的代价是每个物体都要重新设计；只抄零件、不带上规则，成片看起来会像剪贴画。
2. **做出这种长相的工具或手段**（Cavalry、AE、Blender、手绘逐帧），以及在那个工具里什么做起来便宜（用路径偏移做同心描边、用复制器做回声……）。这样能分清哪些是"作者的签名"，哪些只是"那个工具里顺手"。查不到就标"推测"。
3. **量成数字，不凭印象**：色值从全分辨率帧里取，网格间距从一行像素量，字号按 1080p 下大写字母的字高量，圆角和铆钉记成占零件尺寸的比例；运动用 motionprint 量。

参考片里的硬切不算它的风格（常常只是剪辑上图省事）。节拍和镜头顺序要从本片自己的核心变量和叙事骨架来，`不借` 一栏写明"参考片的镜头顺序"。

**产出给谁**：机制候选写进 `docs/mechanism.md`；节奏结构写进 `docs/shotlist.md`；参考片里的事实**不能直接进 facts.md**（参考片不是来源，要另外核查）。
