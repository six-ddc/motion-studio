# 运镜与镜头设计

目录：1 质量门槛 · 2 候选 0：平铺 · 3 运镜词汇（带代价）· 4 在本套件里怎么实现 · 5 DOM + CSS 3D 世界与它的坑

这里不给默认运镜，只要求**每个镜头都经过设计，并写出动机**。用哪种运镜由机制和本片 style_guide 决定。这条要求来自一支产品宣传片：第一版把所有元素正面摆满、镜头不动，被评为"简陋"；第二版内容没变，只改了镜头：先用微距特写贴着一个数字，再拉远揭示全景；需要"深入"时转到俯视 3/4，让上层抬起、露出下层；关键时刻加震动和闪白，最后镜头回正、各层合拢。两版的差别全在镜头上。

## 1. 质量门槛：每个镜头写出镜头设计

镜头设计写进 shotlist.md 的「镜头设计」一节（也可以写在 `shots[]` 的可选字段 `camera` 里，一句话即可；`check_shotlist.py` 不校验它），每镜写六项：

| 项 | 写什么 | 写不出来意味着 |
|---|---|---|
| 景别 | 微距 / 特写 / 中景 / 全景 / 大远景 | 整片只有一个景别，就是平铺（第 2 节） |
| 机位与角度 | 正面、俯视 3/4、仰视、侧面、主观 | 一直是默认的正面，没有选过 |
| 运动 | 推、拉、环绕、升降、静止……（第 3 节），并写明起止时刻与时长 | — |
| **动机** | 这次运动要**揭示**、**强调**、**跟随**或**对比**什么 | 运动只是装饰：删掉，或换成有动机的运动 |
| 焦点 | 这一镜观众该看哪一个东西，靠什么引导（景深、亮度、运动、构图） | 焦点有两个以上时观众要自己挑，多半会挑错 |
| 交棒 | 镜头的结束状态怎么变成下一镜的初始状态（机位延续、匹配剪辑、在主题断点上硬切……，见 `vocabulary.md` §1） | 每镜都从零开始，看起来就像幻灯片 |

判据：遮住旁白，只看镜头设计这一栏，能复述出这一段在**强调**什么吗？静止也是一种设计，写"静止，因为这一刻要读数"就合格；如果每一镜都在动，就等于没有一镜在强调。

## 2. 候选 0：平铺

写法和机制的候选 0 相同（`SKILL.md` §3C）：**所有元素正面摆满、镜头不动、只有一个景别**，这是最省事的画法，并不是中性的选择。要用它，就在 style_guide 里写一句理由，并指回本片目标或 brief；写不出"因为"，说明是默认值在决定画面。

它的代价是：观众第一秒就看完了全部内容，之后新信息没有新的进入方式；层级只能靠大小和颜色来撑；片子和任何一支网格片都长得一样。值得付这个代价的场合有：纯排版片、刻意的平面设计风格（海报、瑞士风）、需要对照全貌的信息图，以及读数的那一刻（镜头一动就读不清）。

## 3. 运镜词汇（菜单，每条带代价）

先弄清机制需要什么，再来这里挑；反过来从这里挑（"我想用个环绕"），片子会退回成手法拼盘。

| 手法 | 适合表达 | 代价 | 不值得的时候 |
|---|---|---|---|
| **推**（push-in） | 收紧注意力、表达"就是这个"、加重情绪 | 慢推几乎没有代价；快推会抢戏，而且推到终点后画面要有足够的细节撑住放大 | 终点没有东西可看 |
| **拉远揭示**（pull-back reveal） | 从局部到全貌，表达"原来它是这个的一部分" | 开场需要一个**没有上下文也好看**的局部；揭示后的全景必须比局部提供更多信息 | 全景和局部说的是同一件事 |
| **微距转全景** | 尺度对比；从一个数字或一个像素进入整体 | 微距段要有材质（字体边缘、像素、纹理），矢量图放大后是空的；跨度大时要在 log 空间插值，否则前段快、后段几乎停住 | 素材在微距下没有细节 |
| **环绕**（orbit） | 立体感、表达"从各个角度都成立"、展示结构 | 容易让人晕；转到侧面时平面元素会变成一条线；三维实现成本最高 | 主体本身是平面 |
| **升降 / 俯仰**（crane/tilt） | 换视角讲层级：俯视表达结构，仰视表达分量 | 俯视时小字读不清（字高按倾角的 cos 压缩）；要读的字先回正 | 那一刻观众需要读字 |
| **焦点转移**（rack focus） | 不动机位，把注意力从 A 交给 B | 模糊有渲染成本（film-webfx 实测大半径模糊每帧 13–16 ms）；前景和后景要真正分层 | 画面只有一层 |
| **甩镜**（whip pan + 运动模糊） | 能量感、"与此同时"、强行转场 | 容易晕；模糊段读不清；没有运动模糊时看起来像卡帧 | 节奏本来就慢的片子 |
| **匹配剪辑**（match cut） | 两件事形状相似，且这种相似有意义 | 要专门设计两镜相同形状的构图；为了接而接会显得刻意 | 形似只是巧合 |
| **滑动变焦**（dolly zoom） | 眩晕、认知翻转、表达"世界变了" | 很容易让人晕，也很容易被看成炫技；整片最多用一次才有力度 | 没有需要表达的翻转 |
| **多层视差** | 纵深和空间感，二维素材也能用 | 层与层要拉开足够距离才看得出来；层数多了焦点会分散 | 素材只有一层 |
| **爆炸视图**（exploded view） | 表达"里面是什么"和层与层的关系 | 俯视 3/4 时层上的字会变扁变小；层间要留出能看清的缝隙；合拢时要回到原位 | 层之间没有关系可讲 |
| **震动**（camera shake） | 冲击、落地、关键的一拍 | 容易晕；会抢走冲击之后的读数；必须是 t 的纯函数（第 4 节） | 不是关键时刻（用多了就不再有强调作用） |
| **整段一条连续运镜**（一镜到底） | 空间连续、"这些都在同一个地方"、沉浸 | 机位只能在相邻角度间平滑移动，长度一长，景别、角度、焦段都挤在一个窄区间里，观众读作"一直同一个角度"；慢速匀滑没有强调点（本仓库样例 xa-agent v2：每段一条 3/4 斜俯慢滑、fov 30–46，被评"不够有镜头变换"） | 一段要讲好几件事、每件都要被强调 |
| **多镜硬切**（每段几个短镜头） | 节奏、强调、同一件事从几个角度成立 | 硬切没有过程，靠前后两帧的关系撑：相邻两镜景别/角度/焦段差得不够就像跳帧，差太多又会迷失空间；切点要挂在旁白字上；镜头数多，设计和实现成本成倍 | 需要观众持续追踪一个空间关系（路径、位置变化） |
| **主观镜头**（POV） | 用户视角、表达"你会看到什么" | 观众要先知道"这是谁的眼睛"；手持感会和界面的整齐感冲突 | 画面里没有一个"谁" |

## 4. 在本套件里怎么实现（只指路）

| 需要 | 用什么 |
|---|---|
| 2D canvas 的推、拉、移 | film-core `motion.js` 的 `camera(t, keys)` + `applyCamera(ctx, cam, w, h)`（keys 的格式是 `[t, zoom, x, y]`，zoom 在 log 空间插值） |
| 任意镜头参数的关键帧 | film-core `follow(t, stops, spring)`：**每个参数一条曲线**，钉点取旁白锚点；弹簧时长用 `spring({duration})` 反推参数 |
| 斜看一个平面 | film-motion `camera3d.js`（透视）与 `tiltcheck`（压扁扫描） |
| 镜头之间的甩镜、匹配剪辑、穿越缩放 | film-motion `timeline` + `transitions.js` |
| 真三维、环绕、景深 | film-webfx 的 three（`stage3d.js`）与 `camrig.js`（`orbit` `dolly` `shake` …）；景深在 `post3d.js` 里；多镜硬切镜头表用 `shots()` → `track()` |
| 震动 | 三维场景用 `camrig.shake`；2D/DOM 用 film-core 的 `hash01(floor(t·频率), 轴)`，在整数格点之间插值。**不要用 `seeded()` 顺序流**，因为它的结果依赖调用历史，乱序 seek 时门 2 会报红 |

## 5. DOM + CSS 3D 世界与它的坑

产品片的界面本来就是 DOM 时，可以不用 three：给 `#view` 设 `perspective`，给 `#world` 开 `transform-style: preserve-3d`，镜头就是对 world 施加的一串变换，每个参数对应一条 follow 曲线：

```js
const v = (k) => follow(t, CAM[k], SPRING.default);   // CAM = { z: [[t0, 900], [tReveal, 0]], rx: …, rz: …, x: …, y: … }
world.style.transform = `translateZ(${v('z')}px) rotateX(${v('rx')}deg) rotateZ(${v('rz')}deg) translate(${v('x')}px, ${v('y')}px)`;
```

实测遇到的坑：

- **确定性**：Chromium 给变换层选择光栅缩放比例时存在滞回，结果取决于此前求过哪些 t，seamcheck 的 1a/2/5 都会报红。原因、实测数字和修法只写在 film-core `references/nondeterminism.md` 门 1a 表的「CSS 3D 变换层」一行，以那里为准。
- **黑块**：平面（卡片底板）自己也开 `preserve-3d` 时，子元素和平面底色会发生深度冲突，出现黑块。只给 world 开，平面本身不开。
- **代码缩进丢失**：flex 容器会吞掉只含空格的文本节点。代码行改用块级元素加 `white-space: pre`。
- **可读性**：倾斜后字高被压缩，要读的字在被读的那一刻回正。film-critique 的 `readability` 量的是 DOM 字号，量不到倾斜造成的压缩，需要人看静帧确认。
