# 机制判据详解与案例

目录：1. 定义 · 2. 三刀的操作细节 · 3. 四种"不是机制"的东西 · 4. 正反案例（成对）· 5. 机制的代价 · 6. 唐片：分镜层的四个问题

## 1. 定义

**机制 = 一条把主题的核心变量映射到一个视觉变量的规则，整片靠它承重。** 其中三个词的含义：
- **核心变量**：主题里会变化的那个量（国运、可读性、价值的承载者）。它不是主题名，也不是名词。
- **视觉变量**：画面上一个可以连续变化的属性（浓度、重量、可读度、距离），不是一个物件。
- **承重**：关掉旁白只看画面，观众仍能看出核心变量在怎么变化。

## 2. 三刀的操作细节

**刀 1 · 换题测试**

| 步骤 | 做什么 | 防的是什么 |
|---|---|---|
| 去名词 | 把候选里所有主题专有名词替换成 [X] | 贴个标签就假装是主题专属（"108 坊棋盘"） |
| 套固定对照题 | 套用一道菜的做法、一家公司的融资轮次、一个人的一天 | 自己挑一道套不上的对照题 |
| 读"因为" | 看理由来自主题的因果，还是来自渲染效果 | 骨架碰巧套得上、但理由确实属于主题的情况被误判 |

"因为"子句里如果出现清楚、整齐、好排、一目了然、观众熟悉、好实现、可扩展、能放下 N 个，说的都是**画面**的好处，基本可以判为容器。能迁移到同类主题不算失败（墨色兴衰对任何王朝都成立）；连不相干的类别都成立，才是容器。

**刀 2 · 自己会演化**：规则定好后，第 3 镜的画面能从规则推出来吗？推得出，就是机制；需要另想，那只是一组镜头。常见的假演化有三种：一次性变形（演完就没了）、二值图标（只有开和关）、每镜换一个比喻。

**刀 3 · 旁白同构**：好的同构旁白**去掉画面就不完整**。"它一点点晕开，让出宫阙的轮廓"，没有画面，听众不知道"它"是什么；"唐朝是中国最强盛的朝代之一"，没有画面也完整，说明画面只是配图。

## 3. 四种"不是机制"的东西

| 类型 | 长什么样 | 死在哪刀 | 可以怎么用 |
|---|---|---|---|
| **容器** | 网格、卡片列表、时间轴、柱状图、地图打点、时序图、节点连线图、分屏 | 刀 1 | 承载附属信息（年份刻度、数据表），但不承重 |
| **装饰** | 风格对了但没有映射：水墨风的标题淡入、赛博风的 UI 卡片 | 刀 1（骨架能套任何题） | 属于 style_guide 的事，不是机制 |
| **图标** | 锁、灯泡、齿轮、对勾、箭头 | 刀 2 | 局部标注 |
| **一次性变形** | 一堆东西塌缩成一个、A 变成 B | 刀 2 | 开场钩子、终场收束 |

容器的问题在于**什么都能装**，所以它不会让这支片子和上一支有所不同；机制则是每个主题各自独有的。

## 4. 正反案例（成对：同一主题下，一个容器/装饰 vs 一个机制）

- **唐 · 兴衰**　✗ 108 坊棋盘逐条画出线，中心格长出牡丹（去掉名词后套在菜谱上也成立）。✓ 墨的浓度与完整度 = 国运，宫阙从墨里挖出；因为兴衰就是有过、散开、淡去。
- **交子 · 货币从物到信用**　✗ 地图上的流通范围扩散，或账本格子被填满。✓ 价值 = 重力：铁钱压塌桌面，交子开始变重，超发后纸变轻、飘散；因为交子本来就是因铁钱太重而产生的。
- **TLS 握手**　✗ 客户端和服务器两条竖线、箭头往返的时序图。✓ 安全状态 = 画面文字的可读性，从窃听者的视角看；密钥建立后，连字幕都变成乱码。
- **融资轮次**　✗ A/B/C 轮次卡片依次弹入，金额滚动。✓ 所有权 = 一块面积，每一轮都把创始人那块切薄；面积守恒，因为稀释就是同一块蛋糕被分。
- **菜谱**　✗ 步骤 1-2-3-4 的卡片。✓ 时间 = 颜色：食材的颜色变化就是进度条，旁白念"到这个颜色就出锅"。

## 5. 机制的代价（过了判据之后还要想的事）

判据只回答"是不是机制"，不回答"好不好"。选定之前，把下面几项写进 mechanism.md：

| 代价 | 说明 |
|---|---|
| **教科书比喻** | 主题的标准比喻（DH 的颜料混合、电流的水管）。清楚，没有学习成本；代价是观众见过，没有记忆点。判据防不住它，只能自己权衡 |
| **覆盖不全** | 机制只能演出核心变量的一段。代价是另一段要换手法，承重会出现断档 |
| **需要教** | 映射不直观（重量 = 价值），开头要花一镜讲清规则；好处是观众学会之后，后面的镜头不用再解释 |
| **实现成本** | 机制往往比容器难写。如果选中的恰好是最便宜的那个，写一句"除了好写之外，主题为什么需要它" |
| **事实依赖** | 机制的"因为"依赖某条事实（铁钱笨重），这条事实必须在 facts.md 里有出处 |

## 6. 唐片：分镜层的四个问题

机制（墨的浓度 = 国运）本身通过了三刀，问题全出在从机制到分镜这一层。下表每条是一类可复现的问题，以及它应该在哪个环节被发现（每条的原因、静帧路径和数字见仓库 `docs/verified/film-story.md`）：

| 问题 | 该在哪发现 | 修法 / 通用判据 |
|---|---|---|
| 三座殿宇（中下方大，左上和右上小）被看成一张**脸** | 写关键帧剪影描述时：写出位置关系的那一刻就该看出来 | 三元对称排列、两点加一条横线会触发空想性错视。这是形似风险，不是禁令：想要脸的片子正好可以用它 |
| 安史之乱按年份线性映射，只分到 **0.111s** | 分镜声明 `segments`，由 `check_shotlist.py` 实测 | 钉点对齐到旁白锚点（`["s3@裂痕",755],["s3.end",757]`，这两年分到 2.2s）。任何"把 X 线性映射到秒"的做法，都要问最重要的那段 X 分到了几秒 |
| 旁白念到"只剩一点余墨"时，**画面已经空了** | 写旁白时遵守"断言在念它的整个区间内为真"；分镜里写 `claims` 逐毫秒验证 | 曲线末值的钉点放在 `s5.end` 且值大于 0，归零的过程放到 tail 里。旁白里每个描述状态的词（只剩、还在、已经、开始）都是带区间的断言 |
| 墨团轮廓像**齿轮** | 分镜里给关键元素写"要像 / 不能像"（要像宣纸洇开；不能像齿轮、星形、爆炸贴纸） | 均匀间隔的独立尖刺就会被看成齿轮。修法归实现方（film-webfx / film-physics）；没有写下来的目标，实现方只能按最熟悉的写法交差 |

另一个旁证：旧版 shotlist 的旁白先写了"一百零八坊，像棋盘一样铺开"，网格就又回到了画面里。**先写旁白、再让画面去配图**，容器就会从旁白里溜进来。第 4 步"旁白按机制写"要防的就是这种情况。
