# facts.md：出处判据、状态、格式与对账

目录：1. 出处判据 · 2. 状态与可信度 · 3. 总表与详情段的格式 · 4. 匹配词：数值 + 单位 · 5. factcheck.mjs · 6. 产品 UI 类主题

`docs/facts.md` 是片子的事实账本：`factcheck.mjs` 只解析总表和详情段，其余部分可以随意写。核查步骤，以及争议和建构的写法，见 `fact-check.md`。

## 1. 出处判据：哪些要、哪些不要

判据是：**"较真的评论区能不能指着它说你错了"**，以及**错了代价有多大**。

| 类型 | 要出处？ | 例 | 为什么 |
|---|---|---|---|
| **数字** | 要 | 发行 125 万缗、3.5 英寸、28.7% | 记忆最容易记错位数和归属；错了一眼就能被证伪 |
| **日期** | 要 | 1023 年、天圣二年二月 | 年份差一两年是最常见的记忆错误 |
| **专名** | 要（在片中首次出现时） | 张咏、益州交子务、iPhone OS 1.0 | 容易张冠李戴；繁简、译名、型号容易写错 |
| **因果断言** | 要，而且要找到提出这个因果的人 | "因为铁钱太重所以有了交子" | 因果是解释，常有分歧；"最早/第一/最大/唯一"一律归入这一类 |
| **界面** | 要真实截图，只有 URL 不够 | 按钮位置、菜单文字、图标形状 | 凭记忆画的界面一定不像（第 6 节） |
| **建构** | 不要"出处"，要**锚点** | 国运曲线、影响力热度 | 属于作者的解释，见 `fact-check.md` 第 5 节 |
| **背景** | 不要 | 唐朝在中国、纸是平的 | 没人会争。带具体数量的就不算背景（"唐朝人口 5000 万"是数字） |

- **只有进入画面或旁白的才算**（facts.md 是账本，不是读书笔记）；拿不准属于哪一类时，按需要出处的那一类处理。**精度跟着片子走**（片中说"一百二十五万"，就核到万位）。
- **推导出来的数也是事实**：单独登记一条，写 `推导: F02, F07`。**代码里的数据数组**同样要对应到一条 id（`fact-check.md` 第 6 节）。

## 2. 状态与可信度

| 状态 | 含义 | 能上片？ |
|---|---|---|
| `已核` | 读过原页，并且有至少 2 个独立来源一致，或有 1 个一手来源 | 能 |
| `单源` | 只有一个二手来源 | 能，对账时给警告；承重事实不建议用 |
| `争议` | 来源之间有分歧，详情段写了两边的说法和"片中措辞" | 能，但必须使用定好的措辞 |
| `待核` | 还没有查 | **不能** |
| `否决` | 查过，是错的 | **不能**（条目保留，匹配词写那句错话，一旦再被写进旁白，factcheck 直接报错） |
| `免核` | 按判据不需要出处，但数字会出现在旁白里（如"一个人"） | 能，要写理由 |

可信度（高/中/低）是对**该说法本身**的判断：两个来源如果互相转抄，仍然算低。来源达不到片子想要的精度不算争议，这时写 `精度上限:` 和 `片中措辞:`（`fact-check.md` 第 4 节）。

## 3. 总表与详情段的格式

```markdown
## 事实总表

| id | 说法 | 匹配 | 类型 | 承重 | 状态 | 可信度 |
|---|---|---|---|---|---|---|
| F03 | 每界发行额 1,256,340 缗 | 1256340缗; 125万6340缗; 125万缗 | 数字 | 承重 | 争议 | 中 |
| C01 | 信用随时间下滑的曲线 |  | 建构 | 点缀 | 免核 | 低 |

### F03 每界发行额
- 来源: [作者《标题》，刊物 日期](https://...) — "原文句子"
- 来源: [...](https://...) — "原文句子"
- 记忆值: 1,256,340，记成首界 —— 数字对，归属有分歧
- 分歧: …
- 片中措辞: "每一界，一百二十五万缗"
```

- **id**：`F01` 表示事实，`C01` 表示建构，前缀可以随意，后面接数字；详情段标题 `### <id>` 必须和它对上。**类型**取 数字 / 日期 / 专名 / 因果 / 界面 / 建构 / 背景 之一。**承重**列取 承重 / 支撑 / 点缀 之一。
- 详情段里脚本会检查的关键字：`来源:` 行要带 URL；`推导: F02, F07`；`片中措辞:`（争议条目必填）；`锚点:` 和 `呈现:`（建构条目必填）；`理由:`（免核条目）。
- 另外两节供分镜使用：`## 核心变量`（一段话）和 `## 叙事骨架`（节点 / 事实 id / 物理跨度 / 叙事权重 / 为什么承重）。
- 只在搜索摘要里见到、没有打开原页的来源，写成"旁证（只见于搜索摘要，未打开原页，不计入）"。`<!-- -->` 注释（包括跨行注释）会在解析前剥掉，所以模板里的示例不会被当成条目。

脚本校验的结构规则：已核、单源、争议条目必须有 URL 或推导；争议条目至少有 2 个 URL，并且写了片中措辞；建构条目必须有锚点，且锚点有出处；承重条目不能是单源或待核（默认给警告，`--strict` 下报错）。

完整模板：`assets/facts.template.md`。真实样例（交子调研）：`tests/fixtures/_test-research/docs/facts.md`。

## 4. 匹配词：数值 + 单位

**匹配**列写这条事实在旁白里可能出现的写法，用 `;` 分隔，**带上单位**：`22辆`、`230米`、`44 米`、`30 km/h`、`三分钟`、`两年`、`1000文`、`28.65%`。

- **以数字开头的词按"数值 + 单位"匹配**：要求值相等（中文数字和阿拉伯数字互通，"二十二辆"能命中 `22辆`），并且旁白里数字后面的文字以这个单位开头（中间的空格和"多/余/来"会跳过，如"四十四 米""八十多年"）。
  单位指数字后面的全部文字，**不查任何量词表**，兆瓦、基点、光年、集、票都一样处理。单位不同就不命中："二十二米"不命中 `22辆`，"二月"不命中 `两年`，"千年"不命中 `1000文`。
- **不带单位的裸数字**（`22`、`125万`）会命中任何单位的同值数。能写单位就写；脚本会在提示里列出这类裸数字匹配词。
- **其余的词按原文子串匹配**：数字不在开头的（`天圣二年`、`钱引`）；以单独的"一"开头的（`一圈路`、`一辆`，旁白里单独的"一"从不当作数字抽取）；单位里又夹着数字的（`两年一界`）。
- 单位按**前缀**比较，写得越长匹配越严：`30公里` 会同时命中"三十公里每小时"和"三十公里外"，要区分就写 `30公里每小时`；`3分` 会命中"三分钟"，所以要写全 `3分钟`。同一个数在片中有两种写法（`230米`、`230 m`）时，就登记两个词。

## 5. factcheck.mjs：对账什么、退出码

命令见 SKILL.md 第 7 步。`--also <文本文件>` 会把画面文字（标题卡、数据标签）一起纳入对账（film-critique `check.mjs` 截取到的画面文字在 `out/critique/onscreen.txt`）；`--strict` 把承重条目处于单源或待核的情况升级为错误。

旁白每一行里的每个数字（阿拉伯数字、中文数字、逐位读的"六一八年"、"125万6340"）都必须命中一条状态允许上片的事实；匹配词写了单位的，单位也要一致。建构条目被念成精确数字、否决条目被写回旁白，都会直接报错。
旁白还空着时只验证 facts.md 的结构（写完 facts.md 那一步跑一次，检查格式）。"提示"部分列出脚本**没覆盖到**的东西：裸数字匹配词，以及单字中文数字后面接了没人登记过的量词（如"三头"）。这些不报错，但也不会被悄悄放过。

退出码：0 表示通过，1 表示有错，2 表示前置条件缺失。`--json` 输出供程序读取。film.json 的 `checks` 声明了 `facts.script` 时，accept --deep 和 deliver 会运行它；画面数字的宽松筛查由 film-critique 的 `facts.screen` 负责，两者结论不同时以 factcheck 为准。修改脚本后跑回归：`node dev/film-story/selftest.mjs --dir <工作目录>`（加 `--real films/<slug>` 会把真实片子只读拷贝后纳入测试）。

## 6. 产品 UI 类主题

画面里要出现某个产品的界面（App、网站、系统、硬件屏幕）时，**界面必须以真实截图为依据，不能凭记忆画**。有了截图，上片有两条路：

| 路线 | 做法 | 代价 | 什么时候值得 |
|---|---|---|---|
| 裁切 | 对真实截图做裁切、缩放、平移 | 像素有上限（推近就糊）；字和数据改不了；换语言要重新截图；截图里的账号名要另外遮挡 | 只出现一两个状态、不推近、单一语言；历史界面 |
| 重建 | 按截图的像素坐标，用 HTML/canvas 绝对定位复刻；文字集中放进一张表，状态由纯函数 `set(state)` 写出 | 每屏几百行代码；要逐个状态和参考截图 1:1 对照；原生控件的抗锯齿永远差一点 | 需要推近读字、多语言、状态多、要从 DOM 量出高亮框位置 |

重建做法见 film-motion 的 `references/ui-rebuild.md`。**两条路的事实边界相同**：界面上显示的数据、文件名、数字只能来自产品的真实输出。这类条目登记为 `类型=界面`：来源写截图路径、来源 URL 或版本号、截取日期；重建时每个要演示的状态各截一张。怎么拿截图见 `tools.md`；授权与存放归 film-assets。
