# 讲法、长相、近作：机制之外的两次发散

目录：0. 采用外部设计 skill 的方向 · 1. 讲法 · 2. 视觉方向 · 3. 近作对照 · 4. 什么时候可以跳过 · 5. 门：`check_shotlist.py` 查什么

SKILL.md 第 2 步只回答"什么在变、映射到哪个视觉变量"。另外还有三处会自动退回默认：**讲法**（写成百科顺序，承重那一刻落在中段，见 §1）；**长相**（style_guide 直接写出最顺手的那一种，见 §2）；**片子之间互不知道**（不知不觉复刻了上一支，见 §3）。本方法**不规定选什么，只要求知道自己在重复什么**。正面样板（本仓库样例）：`films/weiqi-intro/docs/style_guide.md`。

## 0. 采用外部设计 skill 的方向

片子可以整体采用一个外部设计 skill（frontend-design、canvas-design、algorithmic-art、theme-factory……）的方向，连同它的取舍一起采用。做法是在本片 `style_guide.md` 的「视觉方向」里写"跳过发散：采用 <skill 名> 的 <哪部分>"，再写一行"选定：…"，门会按 §4 的带理由跳过来认可。接入它的技术部分时要遵守 film-core 的 `references/kernel.md`（例如 CSS 动效要声明 `USES_WAAPI` 并在 seek 里设置 `currentTime`；字体随片打包）。可参考的外部能力列在 film-core 的 `references/style-menu.md`。

## 1. 讲法：脚本结构的发散

**时机**：机制选定之后、写旁白草稿之前（两刀都要参照机制；旁白草稿按选定的讲法写）。结果写在 mechanism.md 的「讲法」一节。

**候选 0 是本题的默认讲法**：写下"如果不多想，会按什么顺序讲"（多半是百科顺序，或者按时间、按步骤）。候选 0 要交给判据去淘汰，不能回避不写；它也可能留下来。然后再发散出 2–3 个**骨架类别不同**的讲法。下面的类表用于查重，不是菜单：

| 类 | 骨架 | 承重那一刻通常落在 |
|---|---|---|
| 顺序 | 定义、历史、规则、总结依次展开；或按时间、按步骤 | 取决于主题本身的时间，常在中段 |
| 问题 | 先抛出一个观众答不上的问题或悖论，最后解开 | 解开的那一下 |
| 反转 | 先立起一个常识或误解，再推翻它 | 推翻的那一下 |
| 跟随 | 跟着一个对象走完一遍（一笔钱、一颗子、一个数据包） | 它遭遇事件的那一刻 |
| 倒叙 | 先给出结局或最反常的状态，再回溯 | 开头；之后都是解释 |
| 加码 | 同一条规则一层层加条件，直到发生质变 | 质变的那一层 |
| 对照 | 两种情形并排（有/无、快/慢），差别就是答案 | 两边分岔的那一刻 |
| 预测 | 先让观众猜，再给答案 | 揭晓 |

**刀 1 · 承重那一刻是不是高潮？** 承重那一刻指核心变量形状最陡的那一下。如果它是全片顶点，之后只剩余波，就通过；如果它埋在中段，后面还有新信息，或者有总结把它再说一遍，就不通过；如果它出现时观众还不知道该期待什么（规则还没讲到），也不通过。
**刀 2 · 复述测试。** 写下观众看完能复述的那一句话，检查讲法是否一路走向它，并在画面证明它的那一刻把它说出一次。如果这句话不看片子也能复述（比如百科第一行），讲法就只是在陈列它。

**两刀都过时的代价**：顺序类没有学习成本，但没有顶点（片子用来查阅时值得）；问题类和预测类开头几秒都在设问（设问足够具体才值得）；倒叙类的结局要演两次；加码类和对照类要把同一条规则演好几遍（15 秒通常只放得下一遍）。不承重的讲法可以**吸收**（例如拿一个设问当开场钩子），写明它进入哪一句。

写法照 `assets/mechanism.md` 模板：每个候选写出段落（一句话一段，段落之间用 → 连接）、承重那一刻落在哪、观众能复述的那一句、结果。

## 2. 视觉方向：长相的发散

**时机**：机制（和讲法）选定之后、排分镜之前，因为关键帧剪影描述依赖长相。结果写在 style_guide.md 顶部的「视觉方向」，其余各节都从它推出。

长相有这几个维度（用于查重）：**调子**（光、明暗、冷暖）、**材质**（平涂、写实、纸墨、像素、实物微距）、**镜头**（远近、角度、谁在看）、**字的身份**（UI 层、字幕条、印在物体上、字即物体）、**色**（用几种、哪种承载机制变量）。只在"色"上不同，就是换皮；真正不同的长相至少差两个维度。

**候选 0 是默认长相**，两个来源都要写：这个机制最省事的画法，以及**上一支片子的长相**（先跑 §3 的 `siblings.mjs` 才写得出来）。每个候选写五样：**名字**（两到四个字，起不出名字说明是效果拼盘）、**宣言**（这个长相对主题持什么看法）、**核心手法**（用哪些能力实现）、**最难忘的那一个东西**、**输在哪**（落选时写）或**代价**（选定时写）。

判据：
1. **机制读得出来吗？** 核心变量在这个长相里看不看得见、数不数得清，这是硬性的一刀。
2. **最难忘的那个东西是不是承重的那个？** 如果它是状态变量，观众记住它就记住了道理；如果它是装饰，观众记住的只是效果。
3. **故意，不是用力**：每个选择都有一个指回机制或 brief 的"因为"；效果更多不等于更不同。
4. **和近作的距离**（§3）。
5. **代价**：实现成本、小字可读性、形似风险。

写法照 `assets/style_guide.md` 模板（在 `### 0 · <名字>（默认长相）` 下写宣言、核心手法、最难忘的那一个东西、结果）。门只看实质（至少 2 个候选、标出了选定、落选的写了输在哪），不看字段名。

## 3. 近作对照

写视觉方向的候选 0 之前，先跑 `node <film-story>/scripts/siblings.mjs --film <slug>`。它会列出仓库里其他片子（排除以 `_` 开头的夹具）的画幅，以及各自 style_guide 里选定的视觉方向（取不到就写"未声明"），并把每支片子的代表帧拼成 `films/<slug>/out/siblings.png`（依次尝试 `out/*-poster.png`、成片中的一帧、现场渲染 `scene.html` 的一帧；都取不到的会在图上标出）。**要打开那张图看**：文字是作者的声明，图才是实际做出来的样子。

style_guide 里写一节「近作对照」：点名可能撞脸的片子，每支一行，写它的签名特征和本片与它的关系。关系要么是**拉开**（写明哪几个维度不同），要么是**有意重复**（写明原因：系列片、频道统一长相、brief 要求、机制决定）。仓库里没有别的片子就写"仓库里没有其他片子"。**重复是可以的，前提是有意识地重复。**

## 4. 什么时候可以跳过

跳过要写理由，写在原本该写候选的那一节：一行包含"跳过"并带上理由（不能只写一个空标签），再加一行"选定：…"。这几种情况门都认可。

- **视觉方向**：可以跳过的情况有 brief 指定了长相（写出原话，仍要做近作对照）；系列片或改版（写"沿用自 <slug>"，近作对照里写成有意重复）；采用外部设计 skill（§0）；事后补记（本步骤出现之前就定稿的片子，只写当时实际选定的方向，**不补写当年没想过的候选**）。不能跳过的情况：觉得"一看就知道它该长什么样"。
- **讲法**：可以跳过的情况有 brief 规定了内容顺序（仍要用两刀检验，没通过就告诉用户）；系列片统一结构（写"沿用自 <slug>"）；片子短到只放得下一个事件（三句旁白以内，写候选 0 和一句理由）。不能跳过的情况："讲清楚一个东西"这类题目。

## 5. 门：`check_shotlist.py` 查什么

**只有 film.json 的 `checks` 声明了 `divergence` 时才检查**（这是流程留痕，不是技术约束；`new-film.mjs --recipe explainer` 会声明它）。声明后，`check_shotlist.py --film <slug>` 在对账之后会多查一段"发散留痕"（`--plan` / `--verdict` 的输出不受影响）；只声明了 `divergence`、没声明 `shotlist` 的片子只查这一段，不要求有 narration.json。原则是**格式宽容，实质严格**：

| 查 | 怎么认（格式宽容） | 实质（严格） | 不满足 |
|---|---|---|---|
| 视觉方向 | style_guide 里标题含「视觉方向 / 视觉概念 / 长相」的一节；候选可以是节内带编号（0 / A / B / 一 / 二…）的 `###` 标题、`**粗体行**` 或 `- **列表项**` | 至少 2 个候选；至少一个标了"选定"；每个落选的候选都写了输在哪（输在 / 代价 / 理由 / 因为 / 死于 …后面有内容）。或者：一条带理由的跳过声明加一行"选定：…" | 失败 |
| 近作对照 | 标题、粗体行或行首含「近作 / 拉开 / 前两支 / 其他片子」，范围到下一个标题为止 | 点名至少一支仓库里真实存在的其他片子；或写"仓库里没有其他片子"；或一条带理由的跳过声明 | 失败 |
| 讲法 | mechanism.md 里标题含「讲法 / 脚本结构」的一节 | 同视觉方向，另外要求候选 0（本题默认讲法）必须存在 | 节存在但不满足：失败。整节都没有：**只警告** |

门**不检查**候选是否真的不同、选得好不好：判据靠人，留痕靠门。设计由来见仓库 `docs/verified/film-story.md` 第二部分 F 节。
