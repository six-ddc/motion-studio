# 讲法、长相、近作：防默认收敛的比选工具

目录：0. 采用外部设计 skill 的方向 · 1. 讲法 · 2. 视觉方向 · 3. 近作对照 · 4. 什么时候可以跳过 · 5. 可选门：`check_shotlist.py` 查什么

这是防止模型第一反应滑向偷懒默认值的**诊断与比选工具**（正面样板：`films/weiqi-intro/docs/style_guide.md`）。三处最容易不自觉退回默认：**讲法**（顺手写成百科顺序，高潮埋在中段，见 §1）；**长相**（直接写最省事的代码画法，见 §2）；**跨片撞脸**（不看近作就复刻上一支，见 §3）。本方法**不规定选什么，只帮你看清自己在选什么、放弃什么**。

## 0. 采用外部设计 skill 的方向

片子可以整体采用一个外部设计 skill（frontend-design、canvas-design、algorithmic-art、theme-factory……）的方向，连同它的取舍一起采用。做法是在本片 `style_guide.md` 的「视觉方向」里写"跳过发散：采用 <skill 名> 的 <哪部分>"，再写一行"选定：…"，开启了 `divergence` 门时也会按 §4 认可。接入它的技术部分时要遵守 film-core 的 `references/kernel.md`（例如 CSS 动效要声明 `USES_WAAPI` 并在 seek 里设置 `currentTime`；字体随片打包）。可参考的外部能力列在 film-core 的 `references/style-menu.md`。

## 1. 讲法：脚本结构的比选

当题目容易写成平铺直叙的说明书时，在动笔写台词前先比选 2–3 种不同骨架的讲法（可把第一反应的默认顺序记作候选 0 作对照，钩子与留存手法见 `references/creator-playbook.md`）。下面的类表用于启发不同切入点，不是固定菜单：

| 类 | 骨架 | 核心发力点落在 |
|---|---|---|
| 顺序 / 清单 | 定义、背景、步骤依次展开 | 结构清晰、适合收藏查阅；代价是缺乏悬念顶点，前 3 秒容易划走 |
| 问题 / 悬念 | 先抛一个反直觉现象或具体追问，层层剥开 | 解开谜底的那一下；设问必须足够具体 |
| 反转 / 破误区 | 先立起受众深信的常识或习惯做法，再用证据推翻 | 认知翻转的那一刻；极具转发与评论张力 |
| 跟随视角 | 跟着一个具体对象走完一程（一笔钱、一颗子、一个请求包） | 它遭遇生死拐点的那一刻；代入感强 |
| 终局前置（倒叙） | 第 0 秒先亮最反常的结局或崩溃态，再回溯成因 | 开场即抓人；篇幅太短时首尾呼应略显紧促 |
| 痛点—爽点转化 | 具象摩擦 → 旧法瓶颈 → 新范式实证 → 低门槛下一步（CTA） | 前后效率反差揭晓的那一下；适合产品种草与营销片 |
| 加码 / 对照 | 同一条规则逐层加压直到质变，或有/无两种情形同屏分岔 | 质变或分岔发生的那一刻 |
| 预测互动 | 先给初始条件让观众押注结果，再跑出实测答案 | 揭晓瞬间；开头规则交代不宜超过 4 秒 |

**两个诊断问题**：
1. **最核心的那一下落在哪？** 对叙事与认知反转片，把最陡的转折推向高潮并在闭环后利落收尾，比在中段讲完再拖一段重复总结更有力；只有面向"收藏当工具查"的干货清单片，才值得付尾部结构化复盘的代价。
2. **观众看完愿意替你传播哪句话？** 写下观众看完最可能复述或转发的那句判断（社交货币），检查整条讲法是否在用画面证据把它托起来；如果不看片子也能背出这句话（如百科首句），说明脚本只是在陈列常识。

落选讲法里的好点子可以**吸收**进选定方案（例如借用倒叙的画面当开场前 3 秒钩子）。

## 2. 视觉方向：长相的比选

**时机**：机制（和讲法）选定之后、排分镜之前，因为关键帧剪影描述依赖长相。结果写在 style_guide.md 顶部的「视觉方向」，其余各节都从它推出。

长相有这几个维度（用于查重）：**调子**（光、明暗、冷暖）、**材质**（平涂、写实、纸墨、像素、实物微距）、**镜头**（远近、角度、谁在看）、**字的身份**（UI 层、字幕条、印在物体上、字即物体）、**色**（用几种、哪种承载机制变量）。只在"色"上不同，就是换皮；真正不同的长相至少差两个维度。

**候选 0 是默认长相**，两个来源都要写：这个机制最省事的画法，以及**上一支片子的长相**（先跑 §3 的 `siblings.mjs` 才写得出来）。每个候选写五样：**名字**（两到四个字，起不出名字说明是效果拼盘）、**宣言**（这个长相对主题持什么看法）、**核心手法**（用哪些能力实现）、**最难忘的那一个东西**、**输在哪**（落选时写）或**代价**（选定时写）。

判据：
1. **机制读得出来吗？** 核心变量在这个长相里看不看得见、数不数得清，这是硬性的一刀。
2. **最难忘的那个东西是不是承重的那个？** 如果它是状态变量，观众记住它就记住了道理；如果它是装饰，观众记住的只是效果。
3. **故意，不是用力**：每个选择都有一个指回机制或 brief 的"因为"；效果更多不等于更不同。
4. **和近作的距离**（§3）。
5. **代价**：实现成本、小字可读性、形似风险。

**在像素上判，比在文字上判可靠。** 上面五条里，1、2、5 都是"看了才知道"的事；候选只停留在文字时，挑的其实是哪段描述写得好。活下来的两三个候选各画一帧再挑（风格帧比稿），审美的来源写进「参考锚」，做法和代价见 `lookdev.md` §1–2。

写法照 `assets/style_guide.md` 模板（在 `### 0 · <名字>（默认长相）` 下写宣言、核心手法、最难忘的那一个东西、结果）。门只看实质（至少 2 个候选、标出了选定、落选的写了输在哪），不看字段名。

## 3. 近作对照

写视觉方向的候选 0 之前，先跑 `node <film-story>/scripts/siblings.mjs --film <slug>`。它会列出仓库里其他片子（排除以 `_` 开头的夹具）的画幅，以及各自 style_guide 里选定的视觉方向（取不到就写"未声明"），并把每支片子的代表帧拼成 `films/<slug>/out/siblings.png`（依次尝试 `out/*-poster.png`、成片中的一帧、现场渲染 `scene.html` 的一帧；都取不到的会在图上标出）。**要打开那张图看**：文字是作者的声明，图才是实际做出来的样子。

style_guide 里写一节「近作对照」：点名可能撞脸的片子，每支一行，写它的签名特征和本片与它的关系。关系要么是**拉开**（写明哪几个维度不同），要么是**有意重复**（写明原因：系列片、频道统一长相、brief 要求、机制决定）。仓库里没有别的片子就写"仓库里没有其他片子"。**重复是可以的，前提是有意识地重复。**

## 4. 什么时候可以跳过

跳过要写理由，写在原本该写候选的那一节：一行包含"跳过"并带上理由（不能只写一个空标签），再加一行"选定：…"。这几种情况门都认可。

- **视觉方向**：可以跳过的情况有 brief 指定了长相（写出原话，仍要做近作对照）；系列片或改版（写"沿用自 <slug>"，近作对照里写成有意重复）；采用外部设计 skill（§0）；事后补记（本步骤出现之前就定稿的片子，只写当时实际选定的方向，**不补写当年没想过的候选**）。不能跳过的情况：觉得"一看就知道它该长什么样"。
- **讲法**：可以跳过的情况有 brief 规定了内容顺序（仍要用两刀检验，没通过就告诉用户）；系列片统一结构（写"沿用自 <slug>"）；片子短到只放得下一个事件（三句旁白以内，写候选 0 和一句理由）。不能跳过的情况："讲清楚一个东西"这类题目。

## 5. 可选门：`check_shotlist.py` 查什么

**只有 film.json 的 `checks` 显式声明了 `divergence` 时才检查**（这是可选的防同质化流程留痕，不是硬性技术约束；需要强约束多方案比选时在 `film.json` 加上 `"divergence"`）。声明后，`check_shotlist.py --film <slug>` 在对账之后会多查一段"发散留痕"（`--plan` / `--verdict` 的输出不受影响）；只声明了 `divergence`、没声明 `shotlist` 的片子只查这一段，不要求有 narration.json。原则是**格式宽容，实质严格**：

| 查 | 怎么认（格式宽容） | 实质（严格） | 不满足 |
|---|---|---|---|
| 视觉方向 | style_guide 里标题含「视觉方向 / 视觉概念 / 长相」的一节；候选可以是节内带编号（0 / A / B / 一 / 二…）的 `###` 标题、`**粗体行**` 或 `- **列表项**` | 至少 2 个候选；至少一个标了"选定"；每个落选的候选都写了输在哪（输在 / 代价 / 理由 / 因为 / 死于 …后面有内容）。或者：一条带理由的跳过声明加一行"选定：…" | 失败 |
| 近作对照 | 标题、粗体行或行首含「近作 / 拉开 / 前两支 / 其他片子」，范围到下一个标题为止 | 点名至少一支仓库里真实存在的其他片子；或写"仓库里没有其他片子"；或一条带理由的跳过声明 | 失败 |
| 讲法 | mechanism.md 里标题含「讲法 / 脚本结构 / 叙事结构」的一节 | 同视觉方向（≥2 个候选并标明选定与落选理由，或带理由跳过 + 选定） | 节存在但不满足：失败。整节都没有：**只警告** |

门**不检查**候选是否真的不同、选得好不好：判据靠人，留痕靠门。设计由来见仓库 `docs/verified/film-story.md` 第二部分 F 节。
