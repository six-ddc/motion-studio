# 事实核查细则

目录：1. 单条事实的核查步骤 · 2. 来源分级与"独立" · 3. 常见的记忆错误类型 · 4. 争议与精度上限 · 5. 解释性建构 · 6. 代码里的数字

## 1. 单条事实的核查步骤

1. **先写记忆值**（写进 memory-snapshot.md，SKILL.md 第 0 步），必须在第一次搜索之前完成。
2. **搜正面**：用说法本身的关键词搜（中文主题中英文各搜一次，两边给的数常常不同）。
3. **搜反面**：加上"争议""另说""误""实为""myth""actually"再搜一次。只搜正面，会得到一堆互相转抄的印证。
4. **打开原页**拿到原文句子（WebFetch 的 prompt 写"逐字摘出"）。搜索摘要、AI 综述和百科转述都不算原文。
5. **既核数值，也核归属**：数值对了但归属错了（是首界额还是第二界的定额），片子照样是错的。
6. **核单位和口径**：缗/贯、铁钱/铜钱、发布日/上市日、宣布/实施、名义/实际。
7. **写进 facts.md**：来源行（作者、刊物、日期、URL、原文句）、记忆值对照、状态。

## 2. 来源分级与"独立"

| 级 | 例 | 能单独支撑"已核"吗 |
|---|---|---|
| 一手 | 原始史料、官方发布/新闻稿、规格书、法规原文、论文的数据表 | 能（写明"一手"） |
| 署名二手 | 学者署名文章、权威报刊专栏、专著 | 需要两个独立来源 |
| 百科 | Wikipedia、百度百科 | 不能，只能当线索 |
| 转载/自媒体/AI 综述 | 公众号、内容农场、搜索摘要 | 不计入 |

**独立**指两个来源不是互相转抄的（看措辞是否雷同、谁更早、是否互相引用）。两篇文章都引用同一篇文章，只算一个来源。**数字不一致时**，不取平均，也不取"看起来对的"那个。先查口径；口径相同仍不一致，就判断是不是转录错误（比如恰好差 1000），并在详情段写明"未采信及原因"；判断不了就标为争议。

## 3. 常见的记忆错误类型

常见的有：制度细节被后期版本覆盖（记成"三年一界"，起初其实是两年）；数值对、归属错（把首界额和第二界定额混淆）；不知道还存在第二种说法（1105 / 1107）；"世界第一"不带限定（吉尼斯算的是更早的私交子）；精度错（"约 28%"实为 28.65%，而且是铁钱）；地点张冠李戴；日期归属错（把发表年当成实验年）。

记错并且差点说出口的那句话要登记成 `否决`，匹配词就写那句错话。除了数字和年份，最该警惕的是**"最早/第一/唯一"**这类断言和**因果链**：它们听起来像事实，实际上是解释。

## 4. 争议与精度上限

满足以下任一条件就标 `争议`：两个可信来源给出不同的值、日期或归属；学界对因果解释有公开分歧；"最早/第一"类断言有已知反例。详情段必须包含：两条 `来源:`（一说和另一说）；`分歧:`，用一句话说清分歧在哪（值？口径？定义？）；`片中措辞:`，写本片怎么说，以及为什么这个说法对两边都站得住（或者采信哪一说、在哪里交代）。

措辞策略按优先级从高到低：**退粒度**（用"八十多年后"代替"1105 年"）；**加限定**（"最早由官府发行的"）；**写明归属**（"据《宋史》"，但在短片里很占时长）；**采信一说，并在画外交代**（在片尾字幕或简介里写来源）。不可接受的做法：选一说当唯一事实；两说取中间值。

**精度上限（不是争议）**：一手来源可靠、没有人反对，但**达不到片子想要的精度**（论文只给出"开始后 3 分钟的快照里已经成形"，片子却想说"三分钟就堵了"）。这种情况这样处理：
- 状态按来源本身定（一手来源就是 `已核`），详情段加 `精度上限:`，说清来源说到了哪一位、没说什么。
- `片中措辞:` 退到来源撑得住的粒度（"没过几分钟"）。
- **匹配词只写片中措辞允许的说法**（`几分钟`），不写超出精度的说法（`三分钟`），否则超精度的那句会被对账放行。想说却不能说的那句话，单独登记一条 `否决`，防止它被写回旁白。

## 5. 解释性建构

**什么算建构**：把一个**没有公认测量方法**的量变成数值（国运、影响力、热度、信用、紧张度）。判别方法是问：**能找到一张别人测出来的时间序列吗？** 能找到，那就是数据，按数字核查；找不到，就是建构。

```markdown
### C01 信用曲线（解释性建构）
- 性质: 作者解释。没有任何史料给出"交子信用 = 0.7"这种量
- 锚点: F02, F04, F09
  - 1024：官方发行、本钱 28.7% → 相对高点（不是 1.00）
  - ~1204：市价 100-400 文 / 面值 1000 文 → 低点区间
  - 中间形状无据，只用单调下降连接
- 依据: 为什么锚点能代表这个量
- 呈现: 浓淡表达，不画坐标轴、不标刻度、不在曲线上标年份数值；旁白不念推出的数
```

- 锚点是**可核对的事件或测量**（户口、税收、发行额、市价、版图、战争起止），每个都要登记为有出处的事实（脚本会检查）；一个锚点只提供**方向或相对位置**。
- 锚点越少，曲线越朴素（两个锚点就是一条单调线）；每个拐点都是一个判断，没有锚点就不该有拐点。精度只配用"高/中/低"，写成 `0.46` 就暗示了一种并不存在的测量精度。
- 呈现时用浓淡、重量、亮度这类无法读出数值的量；真的需要坐标轴，就去找真实的时间序列。反例是唐片的国运曲线：11 个点，0 个锚点。

## 6. 代码里的数字

最容易漏掉的是 `scene.html` 里的数据数组：曲线点、柱高、地图坐标、计数器终值。factcheck 只扫描旁白和 `--also` 指定的文本，数组要靠人核对：
- 每个数组旁写注释 `// facts: F03` 或 `// facts: C01（建构，归一化）`；在 critique 阶段 grep 数组字面量，逐个确认都能对应到 id。
- 屏幕上会被读出来的数（比如计数器停在 1,256,340）必须是事实条目；只决定形状、不会被读出来的数（比如曲线上的 0.46）挂在建构条目下。
