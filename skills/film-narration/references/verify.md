# `align.py --verify`：模型、归一规则、留白链路

实测见仓库 docs/verified/film-narration.md 第 5、15、16、17 节。

## 模型

默认用 `large-v3-turbo`（`small` 会把普通词听错，导致误判 FAIL）。代价是比 `small` 慢约 2.5 倍，第一次运行要下载约 1.6 GB。turbo 也会听错个别词，所以出现 FAIL 时，先换文件或换模型复验，再人工听，不要直接改稿。

**第一次运行会从 HuggingFace 下载模型**（faster-whisper 的 CTranslate2 权重，turbo 约 1.6 GB，放在 `~/.cache/huggingface/hub`），之后走缓存。
本机存着过期或无权限的 HF token（`~/.cache/huggingface/token` 或 `HF_TOKEN`）时，下载会报 **401**，哪怕这个模型是公开的——
库默认把存着的 token 带上。设 `HF_HUB_DISABLE_IMPLICIT_TOKEN=1` 让它不带：

```bash
HF_HUB_DISABLE_IMPLICIT_TOKEN=1 .venv/bin/python <film-narration>/scripts/align.py --film <slug> --verify
```

模型已缓存、又不想联网检查更新时可加 `HF_HUB_OFFLINE=1`。

## 转写范围：只算旁白区间

Whisper 会在没有人声的地方编字：片尾静音、配乐尾巴上常见「感谢观看」「点赞订阅」「字幕由…提供」。这些字不在脚本里，
全算成"多字"硬错误，准确率就在 97% 阈值上下随机跳（同一个文件两次结论不同）。VAD（`vad_filter`）一直是开的，挡得住纯静音，挡不住配乐。

判定不稳的主因是解码方式：faster-whisper 默认在一段置信度太低时按温度 0.2…1.0 **随机采样**重解，尾部静音和配乐正好触发，
所以同一个文件这次编字、下次不编。实测 reuleaux `out/vo.wav`：默认解码在末字之后 0.8s 里编出「您能放过来。您能放在一起。您的衣服宽度。」；
另一次编出「您打开!您打开!字幕志愿者 杨茜茜」，准确率 94.4%，再一次一个字没编，99.7%。时间戳就挤在末字后一秒内，单靠"按时间剔除"剔不掉。

所以 `--verify` 用贪心解码（`temperature=0`）并关掉 `condition_on_previous_text`（编出来的字不再当下一段的上下文、越编越长）。
同一段旁白后面接 14 秒配乐，这样转写一个字也不编，而且快约一倍；代价是转写基本不带标点（比对前本来就去标点）。
`--from` 反推不受影响，仍用默认解码（行文本要给字幕用，要标点）。

在此之上再限定转写范围。`--verify` 有 narration.json 时：

1. 旁白区间 = narration.json 第一个字的起点到最后一个字的终点，加上期望偏移（成片 = `narrationOffset`，`out/vo.wav` = 0），前后各放 `--window-margin` 秒（默认 1.0）。
2. 送给 Whisper 的音频只截到区间末尾——后面的配乐尾巴根本不转写。
3. 转写出的字按中点再筛一遍，区间外的（含片头配乐上的）列在「范围外剔除」里，不计准确率、不参与漂移。

代价：旁白整体错位超过余量时，错位出去的那截字会被当成"范围外"剔掉、在比对里表现为漏字（准确率下降，退出码 1，而不是漂移的退出码 2）。
剔掉的字超过脚本 5% 时会提示这种可能；`--window-margin -1` 关掉范围限制、整段转写，排查用。

## 不给 Whisper 看脚本

把脚本正文当作 prompt 传给 Whisper，会让它退化成只输出最后一句，还会诱导它"听出"期望的结果，系统性地少报错误。
现在只给一句不含内容的文体提示（简体中文）。用 `--hint-file` 提供领域词表时，会剔除脚本里出现过的词，输出中标注「结果偏乐观」。
`--from` 从录音反推时间戳不属于校验，可以用 `--hint` 提供原稿。

## 两种归一

规则写在 `align.py` 的「数字归一」注释里，`--selftest` 中有正例和反例。

1. **标点**：先做 NFKC，再去掉所有 Unicode 标点和空白（Whisper 会输出 U+FE50「﹐」这类字符，不归一的话会被算成多出来的字）。
2. **数字按数值比较**：每段数字（中文或阿拉伯数字，包括 `4.4万`、`百分之五十`、`三点五`、`二零二四`）作为一个整体。数值相等算念对（二十二 = 22，一万二 = 12000）；
   数值不同一律算硬错误（二十二念成三十二、44 念成 4.4）；两边都是中文、数值相同但写法不同（两、二）时归入「要人听」。
   **量词和单位不做归一**（二十二辆与 22米 仍然是硬错误）。解析不了的串（「二三十」「千万」）退回逐字比较，不从分母中剔除。
   中文数字的解析结果会通过 `--selftest` 与 film-story 的 `factcheck.mjs` 交叉校验（装了 film-story 才比）。
   「三百五万」这类省略到万位的写法有歧义（可能是 350 万，也可能是 305 万），「三百五十万」没有歧义。

## 自动挑文件

只**正向匹配** `final.mp4` / `final-<9x16|1x1|16x9>.mp4`（`mux.sh` 同样只认 `silent-<格式>.mp4`）。原因是 `out/` 里可能有其他 skill 生成的派生文件
（如 film-critique 的 `*-loop.mp4`），选错了文件就会把别处的问题报成片子的问题。转写前先比较时长，和 narration.json 相差 1.5 倍以上时退出码为 3。其他文件用 `--verify <路径>` 指定。

## 留白链路

如果片头留白只写在了分镜里，而 mux 没有加延迟，那么成片音轨和 narration.json 用的都是旁白时间，测出的漂移约等于 0，可画面已经整体平移了，时间轴本身察觉不到留白的存在。
所以期望值取 narration.json 加上 `narrationOffset`（mux 漏加延迟时会测出负漂移，退出码为 2）；画面这一环依靠 narration.js 读取同一个字段，再加上 `mux.sh` / `--verify` 的链路检查（退出码为 4）。
