# 配乐：先定曲再挂事件，声音和画面一样审

本页说明 `music.py`（合成）、`beats.py`（测量）、`audiocheck.py`（质量门）的流程、代价与测量口径。字段见 `schemas.md` 的 out/music.json 一节。三者都是可选能力：不用就不存在，老片子的结果不受影响。

## 1. 流程：声音是时间线的一部分

1. 旁白先行：`narration.json` 里的句子时刻构成段落的骨架。
2. 定曲：已有曲子就用 `beats.py` 测节拍；没有曲子，先跑 `music.py --style … --dry-run` 看切点在哪、和声在哪条小节线上换，
   不合适就用 `--sections` / `--drop` / `--final` / `--outro` / `--lead` 调整，确认后去掉 `--dry-run` 正式合成。
3. 按"谁主导"把事件挂上去（见 SKILL.md 第七节）。
4. 合流：`mux.sh --music out/music.wav`（配乐长度等于片长，不会被 `-t` 硬切）。
5. 审声音：跑 `audiocheck`。数字通过了仍然要人听一遍，频谱质心合格不等于"好听"。

旁白重新合成后，段落时刻会变。`music.json` 记录了 `narration_sha256`，对不上时就重跑 `music.py`，再重跑挂在它上面的 `sfx.mjs`。

## 2. music.py 的风格预设与代价

预设只是编制组合，不代表审美推荐。本片选哪种、为什么选，写进 `docs/style_guide.md`。`--style` 没有默认值。

| 预设 | 编制 | 代价 |
|---|---|---|
| `chip` 120 bpm | 脉冲波十六分音符琶音、三角波贝斯、噪声鼓、铃声高声部 | 一听就是游戏或复古风；琶音很密，旁白多的段落要靠闪避让出空间 |
| `pluck` 112 bpm | 加法合成的拨弦（起音亮、尾音暗）、反拍和弦、拍手、沙锤、带泵感的铺底 | 偏广告和科技风；高频成分多，和明亮的音效叠在一起时会争抢起音 |
| `ambient` 84 bpm | 去掉低频的失谐和声铺底、空气感底噪、稀疏的铃音、轻木块 | 推进感弱；事件适合挂在和声变化和铃音上，挂在鼓点上会找不到落点 |

三种预设共用一套骨架。下面每一条都可以不要，代价写在各条后面：

- **第 0 秒就有声音**：2–8 kHz 的空气底噪和铺底从第 0 帧开始响。起因是用户反馈"开场无声，人声进来很突兀"。代价是没法做"从静默开始"的开场。
- **低频克制**：铺底和声放在 C5 以上，贝斯在 175–262 Hz，总线加 2 阶 70 Hz 高通。起因是 tencent-5y 成片里 400 Hz 以下的能量占 81.6%，用户嫌闷。
  代价是没有厚重的低音，在大屏或耳机上听着偏薄；需要厚重感就在片内改，`audiocheck` 会给出实测占比。
- **噪声一律带通**：一阶差分白噪声的能量集中在 10–24 kHz（听起来是嘶声，而不是明亮），所以镲、沙锤和底噪都设了频率上下限。
- **峰值因数压到 16 dB**（前瞻限幅）：切点上镲和底鼓叠在一起时，峰值会比整体高 30 dB，mux 拉响度之后 AAC 会过冲。代价是冲击点略钝。
- **drop 对齐小节线**。
- **段落切点等于首句开口时刻减 0.35 s**（`--lead`）：过门在人声进来之前收住。和声在离切点最近的小节线上换，可能比切点早或晚半小节以内。
- **尾段鼓组退出并接终和弦**：段落数不少于 3 时，最后一段只保留铺底和高声部；终和弦默认在最后一句开口时响起，余音延续到片尾，最后 0.25 s 淡出到 0。

确定性方面，所有随机取舍都来自 `--seed`（默认 1），同样的输入和参数会得到逐字节相同的输出（两次 md5 相同）。不确定的是音色本身没有经过系统的人耳评审；`ambient` 的"温暖"只是因为低频少、铺底慢，并没有混响。

## 3. audiocheck：每项测的量 vs 你可能以为它测的量

| 项 | 判红（括号内为判黄） | 实际测的量 | 测不出的东西 | 阈值来历 |
|---|---|---|---|---|
| open | 前 0.5 s RMS 低于 -45 dBFS（第 0 帧无声判黄） | 前 `openSec` 秒的数字 RMS（解码后的混音） | 感知响度，以及开场是否合适：一层底噪就能通过 | -45 dBFS 约等于安静房间里刚好听得见；用户反馈过开场无声 |
| tone | 音效轨 400 Hz 以下占比超过 80%，或质心低于 500 Hz（超过 70% 或低于 800 Hz 判黄） | 功率谱质心、400 Hz 以下与 2.5 kHz 以上的功率占比（4096 点、半重叠，低于 -60 dBFS 的帧不计） | 声音亮不亮、好不好听：一声低频撞击就能把占比拉满 | tencent-5y v1 成片为 81.6% / 质心 492 Hz（嫌闷）；v2 为 57.7% / 2304 Hz（通过）。本门复测 v2 得到 57.7% / 2304 Hz，口径一致 |
| tail | 合流记录里配乐比画面短，或片尾超过 1 s 数字静音（配乐比画面长且结尾没收住判黄） | 最后一个不低于 -60 dBFS 的 50 ms 窗口距画面结束有多远；合流记录里配乐文件时长与画面时长的对比 | 结尾收得好不好：刻意做的静音定格也会被报出来 | mux 曾经用 `amix duration=first` 截掉了配乐尾巴（demo-tls 片尾有 0.91 s 数字静音） |
| peak | 成片 true peak 超过 -1.0 dBTP（超过 -1.5 判黄） | loudnorm 口径的 true peak（两位小数，与 mux.sh 成片门口径相同） | 平台转码之后的峰值 | -1.0 dBTP 是常见发布规范的天花板，-1.5 是本套件的目标 |

阈值在声明里修改：`{"audiocheck": {"openSec": 0.5, "openDb": -45, "lowWarn": 0.7, "lowFail": 0.8, "centroidWarn": 800, "centroidFail": 500, "tailSec": 1}}`。

判级规则：音效轨的 tone 可以判红。混音的 tone 只在**没有人声**时判级（没有 narration.json，或 `out/vo.wav` 是静音占位），有人声时只报数字，
因为人声的基频和第一共振峰本来就在 400 Hz 附近。配乐轨的 tone 最多判黄，因为贝斯本来就在低频。没有配乐记录时，tail 对片尾静音只判黄。

**真峰与 `--limit` 的冲突**：`mux.sh --limit auto` 能把峰值压下去，但会损伤人声细节。ghost-jam 实测中，它让 `align.py --verify` 从 98.9% 降到 96.7%（阈值 97%）。
所以修真峰时先降 `--lufs`；旁白片加了 `--limit` 之后必须重跑 `--verify`。这一门和 film-critique 的 `truepeak` 测的是同一个数，两边都声明时会报两次。
