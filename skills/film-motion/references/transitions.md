文中数字来自一支 14.4 s、12 个镜头、11 个转场的测试片（1920×1080，SwiftShader），测量条件见仓库 docs/verified/film-motion.md §MG。

## 0. 先讲代价

下表不是禁令，是每种转场用法都要付的代价：

| 用法 | 观众读到的是什么 | 什么时候值得 |
|---|---|---|
| 每个剪辑点都用不同的花式转场 | 一本转场样品册：观众在看转场而不是内容；也和模型生成片的典型长相重合度最高，观众会据此给片子归类 | 几乎只在"本片就是在展示转场"时 |
| 整片硬切，只在一处用大转场 | 那一处被放大成一个事件，其余部分显得笃定 | 片子有一个关键转折（揭晓、规则对上、时间跳跃） |
| 所有转场都用同一种 | 统一、安静，也可能单调；转场退化成标点 | 讲解片、长片、信息密集段落 |
| 转场的方向或形状与画内运动一致（推移方向 = 镜头运动方向，iris 从主体出发） | 转场被看成"世界的一部分"，而不是剪辑软件的特效 | 几乎总是值得；方向冲突的代价是观众要多花一点时间理解画面 |

## 1. 时间轴与舞台

**时间轴**：剪辑点 `cut` 是绝对秒数（直接写 `vo.at('字')`），转场窗口为 `[cut − align·dur, cut + (1−align)·dur)`。
`align = 0.5` 骑在剪辑点上，`1` 表示念到这个字时转场完成，`0` 表示从这个字开始。窗口内两个镜头都在画，各自按局部时间推进
（Remotion `TransitionSeries` 的语义：转场吃掉两侧的重叠，不冻结任何一侧）。镜头的局部时间从它**第一帧可见**时算起。
film-core 的 `sequence` 已实现这套语义并做了校验；自己写时，以下情况应当抛错而不是悄悄修正：剪辑点不严格递增、窗口重叠、窗口越出片长、`cut` 不是有限数（说明 `vo.at` 没找到字）。
旁白重录后剪辑点自动跟着动，两个转场挤到一起时重叠校验会当场报错。

**舞台**（每帧怎么合成）：

```
frame(t):
  找到 t 所在的镜头/窗口
  不在窗口里 → 镜头 paint(主ctx, lt) 直接画，零额外开销
  在窗口里   → pe = ease((t − w0)/dur)
              paintA → 离屏层 LA；paintB → 离屏层 LB
              按转场 kind 把 LA、LB 合成到主画布
```

- 每个镜头的 paint 必须**铺满不透明底**：转场是两帧之间的合成，透明区域会露出另一帧或黑色，亮度图溶解的乘法合成也会算错。
- 锚点/命名元素要经过舞台登记：转场里镜头画在离屏层上，层在屏幕上被平移/缩放过，只有舞台知道这个变换；镜头自己直接登记会记成"没转场时的位置"。
  两侧都有同名元素时取占优的一侧（pe < 0.5 取 A）。
- 实测不在窗口时镜头帧 0.2–0.7 ms，与不用舞台相同；转场帧多画一个镜头再加合成。

## 2. 转场：原理与代价表

耗时为 1920×1080 SwiftShader。「绘制」= 页面内 seek 加强制光栅化的中位数；「seek+截图」= 走 render 同一路径（CDP）的中位数/最大值。
对照：单镜头帧绘制约 0.2–3 ms，seek+截图约 32 ms。标 ~ 的是按同构代码路径估计的。

| 转场 | 原理（pe 为缓动后进度） | 绘制 ms | seek+截图 ms | 读起来 | 什么时候值得 | 廉价感从哪来 |
|---|---|---|---|---|---|---|
| 硬切 | pe 越过切点的那一刻换 | ≈0 | ≈32 | 没有过程，全靠前后两帧的关系 | 跟节拍、信息密集、匹配剪辑 | 硬切本身不廉价；廉价感来自前后两帧没有关系 |
| 叠化 | 画 A，再以 alpha = pe 画 B | ~3 | ~35 | 时间流逝、柔和 | 段落之间、回忆、慢节奏 | 中段两幅都半透明，内容多时糊成一片；处处叠化，片子没有骨架 |
| 经由颜色（dip） | 前半 A → 纯色，后半纯色 → B，可留纯色停顿 | ~3 | ~35 | 停顿、分章 | 章节分隔、时间跳跃 | 反复用纯黑纯白会被读成 PPT |
| 直线擦除 | 遮罩层画半平面（沿方向投影 < 前沿），软边用渐变；`destination-in` 抠 B 盖在 A 上 | 10.2 | 51 | 有方向的替换 | 方向和画内运动一致时 | 软边太宽就是更差的叠化；方向与画内运动冲突 |
| iris 划像 | 遮罩画圆，半径从 0 到能盖住最远屏幕角的距离；圆心取主体锚点 | 5.4 | 29 | 从某一点打开新世界 | **从主体出发**时很强 | 从画面中心无缘无故打开，像老式幻灯片 |
| 时钟擦 | 遮罩画扇形，角度 = 2π·pe | ~5 | ~30 | 时间、表盘、扫描 | 题材与时间、雷达有关 | 和题材无关时最像模板 |
| 方框擦 | 遮罩画从焦点框插值到全屏的矩形 | ~5 | ~30 | 窗口放大 | UI、画中画 | 同 iris |
| 百叶 | N 条沿方向生长的条，各条错开起点 | 5.5 | 34 | 机械感 | 节奏型、图形化设计 | 条数多加交错大，是最典型的"转场预设" |
| 自定义遮罩 | 遮罩是任意 `mask(ctx, q)`（字形、手绘） | 取决于遮罩 | — | 任意形状 | 遮罩本身有含义时 | — |
| 亮度图溶解 | 灰度图 v(x)；遮罩 m = sat((pe·(1+s) − v)/s)，s = 软边宽；结果 A·(1−m) + B·m。可在 m(1−m) 处加一道烧边色 | 49.7 | 108 / 152 | 溶解、烧穿、颗粒 | 材质感强的片子（胶片、纸、火） | **粗颗粒 + 宽软边 + 亮烧边会变成满屏黑白斑块**；细颗粒、窄软边、淡烧边读作材质。粗颗粒值得用：本片本身是低保真/故障美学，且只用一次 |
| 推移 | A 平移 D·pe，B 从 −D·(1−pe) 跟进；parallax < 1 让 A 走得慢 | 12.8 | 52 | 空间连续：两镜头并排在同一世界 | 镜头之间有空间关系 | 方向随意；parallax 太小像幻灯片 |
| 覆盖/揭开 | 一侧不动，另一侧滑入盖上或滑走露出，可压暗被盖一侧 | ~10 | ~45 | 层叠：新卡片盖上来 | 卡片式、列表式信息 | 同推移 |
| 缩放叠化 | A 放大淡出、B 从倍数缩回 1 淡入；倍数在 log 空间插值 | ~12 | ~45 | 冲击或后退 | 节拍重音 | 没有目标的放大就是"弹出"，很快就腻 |
| 穿越缩放 | 见下方伪代码：相机钻进 A 里的一个元素，B 画在那个元素"里面" | 14.4 | 40 / 67 | **钻进某个东西**，它的内部就是下一镜 | 下一镜确实"在"那个东西里（窗口、屏幕、眼睛） | 门框内外没有关系时只是花招 |
| 甩镜 | 两镜头沿方向高速推移 + 沿速度方向拖影（§5） | 99.5 | 133 / 144 | 能量感 | 动作片、节奏片、两处同时发生的事 | 最贵；每个剪辑点都甩就成了 MV 预设 |
| 故障切 | 时间量化成"故障帧"k = ⌊t·rate⌋；每帧切 N 条横带，带高、错位、取 A 还是 B（概率 pe）都来自 `hash01(seed, k, i)`；可选 RGB 分离 | 41.0 | 76 / 91 | 数字故障、信号中断 | 题材与数字、网络、错误有关 | 和题材无关纯属装饰；RGB 分离大显得廉价 |
| 漏光 | 叠化 + 钟形强度 sin(π·p)^c：把画面自身的廉价模糊加回去（过曝）+ 几团径向渐变光斑以 `screen` 叠加，光斑路径来自种子 | 33.6 | 132 / 354 | 胶片漏光、温度感 | 回忆、温暖、胶片质感 | 过曝太强整帧发白（第一版 0.7 就是这样）；354 ms 最大值来自首帧创建模糊层 |
| 匹配剪辑 | §4 | 11.5 | 37 / 65 | 形状或位置的呼应：把两件事说成"同一件事" | 两镜头里确实有能对上的东西 | 对不上硬对（缩放大、形状不像）读作牵强 |
| Magic Move | §3 | 6.1 | 31 / 60 | 同一批东西重新排列，"变化"本身被看见 | 前后两个状态由同一组元素构成 | 同时移动的太多会乱；每页都用就成了 Keynote 默认效果 |

**穿越缩放**（log 空间推进才有等速感）：

```
F = 焦点元素在 A 里的屏幕框；Z = max(W/Fw, H/Fh)（椭圆门框再 ×√2 才盖住四角）
z = Z^pe；s = (z−1)/(Z−1)
焦点中心从 F 的中心平滑移到屏幕中心：c' = lerp(Fc, 屏幕中心, s)
T = 以 Fc 为原点缩放 z 再平移到 c'
画 A（变换 T）；裁剪到 T·门框；B 画在 A 世界里以 Fc 为中心、W/Z × H/Z 的矩形里（变换 T·R）
B 在门框里先淡入一小段（否则 pe=0 时 B 突然出现）
```

**合成开销从哪来**：擦除 = 画 alpha 遮罩 + `destination-in`，约 3 次全屏操作。亮度图溶解在 canvas 2D 里做软阈值要七八次全屏操作加一次滤镜
（`lighter` 叠灰、`difference` 取反、`brightness(k)` 放大斜率、`multiply` 乘遮罩），开烧边再加几次；精度 8 位，软阈值台阶为 k/255（软边 0.05 时每级约 8% alpha），宽软边上可能看到台阶。
故障切每帧 N 次 drawImage 加 RGB 分离 9 次全屏操作。漏光的模糊用"缩到 1/k 再双线性放大"，`ctx.filter = 'blur()'` 在 SwiftShader 下慢得多。在着色器里做亮度图溶解没有 8 位台阶，代价是要引入 film-webfx 的着色器层。

## 3. Magic Move（共享元素转场）

对应 Keynote Magic Move、PPT 平滑切换，原理是在 canvas 里复刻 CSS View Transitions 的分层模型：

1. **捕获**：两个镜头各画一遍，命名元素此时只记录不绘制（名字、屏幕框、当时的 ctx 变换、draw 闭包、props），画出的是不含命名元素的"根"。只出现在一侧的命名元素补画进那一侧的根（跟着根一起进出）。
2. **根过渡**：两个根按另一种转场合成（叠化、推移、擦除……）。View Transitions 默认叠化；选哪种是本片的决定。
3. **共享元素**（两侧同名）按 B 的绘制顺序画在最上层，框从 A 插值到 B：
   - **单次绘制**：`draw(ctx, mix(propsA, propsB, q), 插值后的屏幕框)`。数值线性插值；颜色在 OKLab 里插值（CSS Color 4 渐变与 `color-mix` 的默认空间，sRGB 插值中段会发灰发暗）；其余属性在 q=0.5 切换。位置、大小、颜色、圆角一起变。
   - **FLIP 快照叠化**：旧元素按"旧框 → 当前框"的仿射重放自己的 draw，新元素按"新框 → 当前框"重放，各画进离屏层，再用 `lighter`（plus-lighter）叠化：重合处不透明度 (1−q)+q = 1，不出现半透明凹陷（View Transitions 默认给 old/new 加 plus-lighter 就是这个原因）。重放的是矢量绘制，放大不糊。
4. **锚点**：共享元素登记插值后的框，其余元素按根转场的层变换映射。

可选：路径向一侧拱起（弧线位移）、各元素按名字/下标错开出发（交错）。

**坑与局限**（实测或可从原理直接推出）：
- **只按名字配对**：名字相同就配，哪怕毫不相干；没有按形状或颜色自动匹配。文字按字配对见 film-typography。同名多次登记时取第一次；要一组东西一起动，就登记成一个元素。
- 非等比拉伸（View Transitions 默认）在宽高比变化时会把文字拉扁；等比缩放取几何平均是另一种选择。跨镜头变化的文字走 film-typography 的文字变形过渡。
- 单次绘制路径在屏幕坐标里画：A/B 里元素原本的旋转、缩放会丢，线宽不随缩放变；要旋转就把角度做成一个 prop。FLIP 路径保留各自变换。
- 元素绘制范围超出登记框太多（阴影、描边外扩）时，框外部分跟着缩放但不参与对齐。
- z 序：共享元素统一画在根之上。A 里原本被压住的元素转场时会浮上来（View Transitions 也如此）。
- Magic Move 本身不做形状插值（方块变圆靠圆角 prop）。任意路径之间的变形用 `references/shapes.md` §3：把进度当一个 prop 传进 draw。
- 每个 FLIP 元素需要 3 次全屏离屏操作；collect 两遍本身很便宜（实测整帧 6.1 ms）。

## 4. 匹配剪辑

A 结束时的元素与 B 开始时的同名元素在剪辑点**重合**：

```
meetBox = lerpBox(fa, fb, meet)          // meet=1：A 在切点前推近对准 B；0：B 在切点后从 A 的位置缓回
切点前：A 的变换 = boxToBox(fa, lerpBox(fa, meetBox, qa))
切点后：B 的变换 = boxToBox(fb, lerpBox(meetBox, fb, qb))
两侧变换都夹到"整帧盖满画面"：缩放 ≥ 1，平移限制在不露边的范围（技术约束，否则露黑边）
blend > 0：切点前后一小段叠化（溶解式匹配）
```

代价：需要缩小才能对上时就对不准（盖满约束不允许缩小），这时改由 A 推近（meet = 1）。

## 5. 甩镜与运动模糊：两条路

| 路 | 怎么做 | 代价 | 什么时候用 |
|---|---|---|---|
| 场景内拖影 | 对缓动做数值导数得本帧速度 v；拖影长 = v·行程/dur × shutter/fps；沿方向做对数步长盒式模糊 | 绘制 99.5 ms/帧；静帧、seamcheck、缩小版里都看得到；只模糊转场位移，不模糊画内运动；在 sRGB 里平均 | 希望静帧也有拖影，或只想模糊转场 |
| 渲染器子帧 | film-core `render.mjs --from a --to b --sub 12 --shutter 0.5` 按真实时间累积 | 渲染时间 × sub，只在该区间付；静帧和 seamcheck 看不到 | 定稿；画内也有快速运动 |

**对数步长盒式模糊**：第 k 遍把图和自己平移 step·2^k 的副本各取一半，passes 遍后是 2^passes 个等距抽头铺满拖影长度——64 个抽头只要 6 遍 × 2 次 drawImage。
等间隔叠 N 份在位移远大于物体尺寸时会出现彼此分离的残影边，对数步长能连成一片。平移露出的边要先铺底色，否则拖影边缘半透明。两条路叠加使用会模糊两次。

## 6. 缓动

缓动是 `[0,1] → 值` 的函数；区间进度 = `ease(sat((t − start)/dur))`，dur = 0 是阶跃。没给缓动时应当报错而不是悄悄用 linear——那是在替片子做选择。

几个需要自己写对的：
- **CSS cubic-bezier(x1,y1,x2,y2)**：先由 x 反解贝塞尔参数 u（Newton 迭代，导数太小时退回二分，误差 < 1e-7），再求 y(u)。与浏览器同一条曲线：`ease(0.5) = 0.8024`。
- **steps(n)**：`floor(p·n)/n`（jump-end），逐格、定格动画。
- **预备（anticipate）**：前一段先往反方向退 pull，再用另一条缓动弹出；交界处速度突变是刻意的。
- **弹簧当缓动**：把 film-core `spring({duration, overshoot})` 的停止时长归一到 p=1，p ≥ 1 时精确返回 1，否则末帧停不稳。
- 自定义缓动先**量一遍**：4000 点采样，记最大值 − 1（过冲）、−最小值（预备）、第一次 ≥ 0.5 和 ≥ 0.8 的 p。

实测表（t80 = 第一次走到 80% 行程时的 p；linear 为 0.800；越界的缓动按第一次越过 0.8 算）。每一族 in/out/inOut/outIn 的完整表可用 `node <film-story>/scripts/motionprint.mjs --curves` 输出：

| 缓动 | 过冲 | 预备（先退） | 到一半的 p | t80 | 读起来 |
|---|---|---|---|---|---|
| sine.out / .in / .inOut | 0 | 0 | 0.334 / 0.667 / 0.5 | 0.590 / 0.872 / 0.705 | 最温和，几乎感觉不到缓动 |
| quad.out | 0 | 0 | 0.293 | 0.553 | 轻微 |

| expo.out / .in / .inOut | 0 | 0 | 0.100 / 0.900 / 0.5 | 0.232 / 0.968 / 0.566 | 起步极快、减速很长：数字滚动、甩镜 |
| circ.out | 0 | 0 | 0.134 | 0.400 | 接近 quint，尾巴更硬 |

t80 越小越像"一下到位再慢慢收住"，越大越像"蓄着劲最后才到"。参考片的 t80 用 film-story 的 `motionprint.mjs` 测，比按名字猜准。

## 7. 交错

借 GSAP stagger 的语义：每个单元一个延迟（秒），加载期算一次。

```
pos[i] = 网格位置 (i % cols, ⌊i/cols⌋) | 真实坐标（如字心） | (i, 0)
o = 起点：首 / 尾 / 包围盒中心 / 某个下标 / 归一化点 [fx, fy]
d[i] = |pos[i] − o|（或只取 x、只取 y）；'edges' 取 max(d) − d
随机错峰：d[i] = 按种子随机排序后的名次（seeded(seed)，不能用 Math.random）
total = amount（总跨度）或 each × max(d)
delay[i] = ease(d[i] / max(d)) × total     // ease 让延迟分布前密后疏或前疏后密
```

代价：总时长 = 单元时长 + 最大延迟（给总跨度比给间隔更好控制）；错峰太均匀显得机械，给延迟分布套缓动可以打破。逐字交错超过约 15 个单元时，观众读到一半字还没出完（与 film-typography 手法表是同一个代价）。随机错峰读起来"散"，用在正文上降低可读性。

## 8. 确定性：踩到的坑

1. **以 canvas 为图源做缩放 drawImage 时，`imageSmoothingQuality = 'high'` 会让结果依赖上一帧**（Chromium 156 headless shell，SwiftShader）。
   采样门 1a/1b/2 全过，是门 4（顺序渲染与并行渲染逐帧比较）抓到的；改成 `'medium'` 或 `'low'` 后门 4 不同帧数为 0。采样门抓不到，是因为均匀采样很少让两个相邻帧落在同一个转场窗口里。
   离屏层合成一律用 `'medium'`；场景自己在 seek 里这样设也会出问题。根因没追到 Skia 层（怀疑缓存按源画布对象复用）。
2. **离屏层是复用对象**：每次使用前清空并复位状态（变换、alpha、合成模式、filter）。不清空的层必须保证每次被整张覆盖。正确与否以门 2 和门 4 为准。
3. **缓存只能以参数为键**（噪声图按 map/seed/颗粒/八度），不能以"上一次用到时"为键；第一次用到的那帧多付一次生成时间。
4. **所有"随机"来自 `hash01(seed, 帧号或单元号, …)`**：同 t 同像素，乱序求值一致。故障切把时间量化成故障帧号再哈希，所以快进、倒放、跳帧都给出同一幅。

## 9. 可用的库（如需）

- **GSAP**：建 `gsap.timeline({ paused: true })`，seek 里 `tl.seek(t, false)` 或 `tl.progress(p)`；不要让它的 ticker 推进（`gsap.ticker.sleep()` 或只用 paused 时间轴）。它的 `CustomEase`、stagger 对象语义正是 §6、§7 的来源。
- **bezier-easing**、**d3-ease**：纯函数缓动，直接在 seek 里调用。

## 10. 没解决

- 透视转场（立方体翻转、翻页卷曲）：canvas 2D 只有仿射，需要 film-webfx 的着色器层或 `references/camera3d.md` 的相机；没有实现过。
- Magic Move 不会自动对同名元素做路径变形；亮度图溶解的 8 位台阶在宽软边上可能看得到，没有做抖动。
- 耗时只在 1920×1080 / SwiftShader 上测过；9x16 像素数相同未单独测；真实 GPU 未测。
