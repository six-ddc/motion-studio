# 数据图表动效：随 t 变化的数据

目录：0 分工与约定 · 1 比例尺、刻度、格式的坑 · 2 序列几何的代价 · 3 关键帧插值 · 4 柱状图竞赛 · 5 折线生长 · 6 轴刻度随域变化 · 7 地理 · 8 关系图 · 9 跨引擎一致 · 10 可用的库 · 11 局限

静态的部分（比例尺、刻度、格式、曲线、堆叠、饼图、投影）用成熟的库就够（§10）；本页讲静态图表库没有的部分：**给定 t，直接得到那一帧的数值与位置**。
数字来自一份自实现与夹具实测（仓库 docs/verified/film-motion.md），这里只给结论。图表只出几何与数值，颜色、线宽、字体、留白由本片 style_guide 决定。

## 0. 分工与约定

- **有状态的东西在加载期算完**：柱状图竞赛的交换事件、力导向仿真、折线累计弧长，都在模块顶层建一次，seek 里只查表。
  在 seek 里重建不坏确定性（输出只取决于参数），代价是每帧重付建表时间（见各节数字）。力导向在 seek 里迭代则会被门 2 乱序求值抓到。
- **参数没有中性的默认长相**：band 的留白、饼图起始角、交换时长、淡出宽度、小数位都是设计决定。有默认的只有数学定义本身（log 底 10、SI 词头、万/亿、时间按 UTC）。
- 坐标约定同 canvas：y 向下；角度 0 指 +x、屏幕上顺时针增大（12 点钟是 −π/2）。

## 1. 比例尺、刻度、格式的坑

- **时间轴不读本机时区**：刻度按 UTC 加一个固定偏移（分钟）算。读本机时区的代价是换台机器刻度就挪位，门 1b 抓不到（同一台机器两次一样）。d3-scale 用 `scaleUtc`。
- **面积编码用 sqrt/pow 比例尺**：半径线性编码值时，值翻倍面积变 4 倍，观众按面积读会高估大值。
- **刻度个数是"大约"**：1/2/5×10^k 取整（同 d3），[0, 1234] 要 4 个得到步长 200 的 7 个。刻度值要算成精确十进制（不出 0.30000000000000004）。
- **band 比例尺接受小数下标**：柱状图竞赛的连续名次直接喂进去 `y = start + paddingOuter·step + pos·step`。
- **数字随 t 插值时每帧格式化一次**（纯函数）。代价：位数变化时字符串宽度跳，标签跟条末端走时会抖；要稳就用等宽数字（film-typography）或右对齐。小数位越多，插值中的数字越像在乱跳，观众读不出任何一个值。
- 格式的小陷阱：进位后换词头（999950 → '1.0M' 不是 '1000.0k'；9999.6 → '1万'）；−0.0001 保留两位是 '0.00' 不是 '-0.00'。

## 2. 序列几何的代价

- **monotone 插值**（Fritsch–Carlson）要求 x 严格递增；它保证单调数据画出来也单调、平台段保持水平、不越过相邻点的值域（实测 [0,0,10,10.5,10.5,30,30] 采 32 点/段，0 处不回退、最大值不超过 30）。
  代价是拐点处比 Catmull–Rom 更"硬"；数据有噪声时平滑曲线会让观众以为趋势连续——那是在替数据说话。
- step 表示"两次采样之间值不变"（利率、档位）；画连续量会被读成突变。河流图中线居中，代价是每层没有平直基线，读不出单层绝对值。
  饼图按值排序更好比大小，代价是跨时刻比较时同一扇区会换位置。

## 3. 关键帧插值

```
keys = [{ t, values: {a, b} }, …]   // t 可以直接写旁白时间戳 vo.at('翻倍')
at(t): 找 t 所在段 i；p = ease((t − t_i)/(t_{i+1} − t_i))
       每个键在包含它的前后两帧之间 lerp；某帧缺键时跳过该帧找更外层；首末之外保持边上的值
```

分段缓动会让值在每个关键帧处减速，数据点多时读起来"一顿一顿"；线性插值没有这个问题但起止生硬。

## 4. 柱状图竞赛

**名次怎么连续**：名次由当前插值值实时决定。加载期按小步长（如 1/240 s）扫描，每当某一名的名次变化，二分出值相等的时刻 t_e，记下交换事件 (key, t_e, from, to)。seek 里：

```
pos[j] = 初始名次[j] + Σ_{该 key 的事件 e} (e.to − e.from) · swapEase(sat((t − e.t)/d + align))
alpha[j] = sat((top − pos[j]) / fade)          // 越过第 top 名时连续淡出，pos 也继续往下走
画：按 pos 排序，y = band(pos)，宽 = x(value)；轴域 [0, max(values(t))] 随 t 连续伸缩
```

- 交换点位于窗口的 align 处（默认 0.5）。两条交换的位置之和恒定，在窗口中点正好擦肩。
  实测（smoothstep、d = 0.8、30 fps）：相邻两帧位置差最大 0.0624 名次，上界 1.5/(d·fps) = 0.0625；所有条目的 pos 之和逐帧不变。
- 另一种做法：只在关键帧上排名、整段 lerp。交换跨整段慢慢完成，代价是中途名次与长度对不上（短条暂时排在长条上面）。
- 排名要是确定性的全序：值降序，平局按首次出现顺序。
- **代价：交换密集时可读性**。20 条正弦数据 30 s 扫出 1084 次交换，平均每秒 36 次，观众跟不上任何一条。缓解各有代价：加大 d（更柔，但名次滞后于值更久）、关键帧更稀（数据失真）、减小 top（看到的少）。
- 建表开销：20 条 × 30 s × 240 Hz 扫描 45–67 ms（Chromium / Node，加载期一次）；每帧求值约 6–8 µs。
- 缺数据时必须显式给填充值，否则报错并点名哪一帧哪一名。不默认补 0，是因为"没有数据"和"值为 0"在故事里意思不同。
- 扫描分辨率之内的连续两次交换会并成一次；同一名次同时被多次交换时位置是各次过渡的线性叠加。

## 5. 折线生长

加载期算累计弧长。按 p 截断到某段某处，返回截断后的点列、末端点、末段朝向（镜头和标签可以跟末端）。

- **按 x 推进**（时间轴图）：末端 x 匀速，陡坡段笔尖变快（同样 x 位移对应更长的弧）。
- **按弧长推进**（路线、轨迹）：笔尖匀速，代价是时间轴上的日期变成非匀速。看观众该读的是时间还是形状。
- 任意 SVG 路径的描边生长见 `references/shapes.md` §2。

## 6. 轴刻度随域变化

域随 t 连续变化时，刻度要连续进出而不是按档跳变：

```
lg = log10(域跨度 / n)             // 理想步长的对数
对每档 step ∈ {1,2,5}×10^k：权重 w = 三角窗(lg 到该档对数位置的距离, 宽 blend)
刻度 v 的 alpha = Σ 含 v 的各档权重   // 两档共有的刻度（20 档与 50 档里的 100）权重和恒为 1，始终不透明
             × 边缘淡入 sat((到域端的像素距离) / edge)；域端点上的刻度（如 0）恒为 1
pos = scale(v)
```

实测域 10 倍连续增长、600 帧：相邻帧 alpha 最大变化 0.080，位置最大变化 3.2 px，任何时刻至少 2 个全不透明刻度。
blend 越小换档越干脆但越像跳变；越大同时可见的刻度越多、标签越容易挤。只对 linear / pow 做过；log 与时间轴的换档会跳变（时间刻度可按单位自己做淡化）。

## 7. 地理

不内置地图数据：GeoJSON 由片子自带（来源与授权归 film-assets）。

- **rotate 语义同 d3**：把 (lon, lat) 放到画面中心写 `rotate: [−lon, −lat]`。地球自转就是让 rotate[0] 随 t 变、每帧重投影：2000 点的环在正射投影（含裁剪）下 0.6–1.8 ms，墨卡托 0.3–0.8 ms。
- **正射投影的背面**：背面点不画；多边形按地平线切开，背面那段沿地平线圆补弧重新闭合。边要按大圆**细分**（如每 2°）：不细分时长边在球面上是弦，会穿进球体内侧，裁剪点也不准。
- **墨卡托高纬变形**：实测 60°N 的 1°×1° 格子投影面积是赤道的 2.03 倍，而球面上只有 0.49 倍——放大约 4 倍（1/cos²φ）。比较国家大小、讲人口密度时，这个放大会被观众当成事实；
  用 Albers 等积（实测格子面积比与球面比相差 < 0.2%）或等距圆柱换正确面积，代价是形状变形。墨卡托在 ±85.0511° 截断。
- **跨日界线**：圆柱投影里跨 ±180° 的环不折回而是继续往外展开；画法是裁到世界矩形，平移 ±周期再画一遍。绕极点的环（南极洲）沿极纬补边闭合。
- **大圆航线**：球面线性插值 slerp 得航线上的点，按进度截断再投影，末端就是飞机位置。北京—伦敦中点纬度高于两端（实测 8142 km，中点约 62.5°N），在墨卡托上是弧线，观众可能读成"绕路"，要不要解释由片子决定。

## 8. 关系图

力导向是有状态仿真，不能在 seek 里迭代。加载期按种子跑完并每隔几步记录一次位置，seek 里按迭代步插值：

```
加载期：G = 仿真(nodes, links, seed, iterations)，每 record 步存一份位置
seek：k = map(p) · iterations；在相邻两份记录之间 lerp → 等比缩放居中到画框
```

- 语义照 d3-force（速度 Verlet、alpha 从 1 衰减到 alphaMin 恰好用完 iterations 步、连线强度 1/min(度)）。种子只决定初始叶序螺旋的起始角和重合点的微扰；同种子两次逐位相同。
- **耗时**（300 步，精确两两斥力 O(n²)，Node / Chromium）：n=50 约 2–3 ms，n=200 约 28–40 ms，n=500 约 150–230 ms，n=1000 约 580–870 ms。
  几百个节点在页面加载时跑完即可；上千个会拖慢每个渲染 worker 的启动（并行渲染时各跑一遍），这时在 Node 里离线算好写成 JSON 随片带（需要 §9 的逐位一致）。
- **收敛**：末步平均位移 < 0.05（实测 60 节点树 300 步）。迭代太少，布局还在"呼吸"就停了，展开动画的最后一帧会显得没站稳。
- **展开节奏**：早期迭代变化剧烈，线性映射 t → 步数会前快后慢；要匀速感就给 p 一条先慢后快的映射，代价是开头几帧节点挤在一起读不出结构。内存 = 记录帧数 × 2n 个双精度。
- 没有 Barnes–Hut 近似时 n 上千只能离线算；简化的碰撞（只推开速度）在节点大小差异很大时会重叠。

## 9. 跨引擎一致

ECMAScript 不要求 `Math.sin/cos/atan2/log/exp/pow` 正确舍入。实测 Node 22.23 与 Chromium 156 的 V8 在 4000 个输入上有 2.5–17% 差 1 ULP，连 `10 ** 整数` 都有 3% 不同；力导向 300 步后差异放大到 1e-13。

只在"Node 里离线算的数要和浏览器里画的逐位相同"时才需要处理：自写只用四则运算和 sqrt（IEEE 规定正确舍入）的超越函数（多项式系数照 fdlibm，对照 Math 误差 ≤ 2 ULP），代价是 sin 约慢 1.4–1.8 倍（10 万次 2.2 ms vs 1.2–1.6 ms）。
单纯画图用 Math 也满足 seek 契约（同一浏览器内确定）。

## 10. 可用的库（如需）

- **d3-scale / d3-array**：比例尺、`ticks`、`nice`、`bin`。纯函数，seek 里直接调；时间轴用 `scaleUtc`。
- **d3-shape**：`line().curve(curveMonotoneX)`、`area`、`stack`、`pie`、`arc`，传 canvas ctx 直接画。
- **d3-geo**：投影、`geoPath(projection, ctx)`、`geoInterpolate`（大圆）；`clipAngle(90)` 处理正射背面。每帧按 t 设 `rotate` 再画。
- **d3-force**：`forceSimulation(...).stop()` 后手动 `tick()` N 次——加载期跑完并记录位置，**不要**让它自带的定时器跑。它内部用 `Math.random` 的地方（重合点抖动）要通过 `randomSource(seeded(seed))` 换成种子随机。
- **d3-interpolate**、**d3-format**：数值/颜色插值与格式化；格式化带本地化时显式给 locale，不要依赖系统。

## 11. 局限

刻度连续换档只做了 linear / pow。球面裁剪按"走地平线的短弧"补边：包住整个可见半球边缘的多边形（整片海洋）会补错方向；Albers 不裁背面经线，只适合区域图。
