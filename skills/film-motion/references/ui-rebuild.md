# 从截图重建产品界面

产品 UI 片有两条路：一是把**真实截图裁切后做成动画**，二是**照着截图用 HTML/canvas 重建界面**，再由 `seek(t)` 驱动。
怎么选、各自的代价见 film-story skill 的「产品 UI 类主题」一节；本页讲第二条路的做法（实测记录在仓库 `docs/verified/film-story.md` §2g）。
配套工具有两件：运行时 `uirebuild.js`（纯函数，复刻页用 `import './runtime/uirebuild.js'` 引入，交付时随片冻结），以及 `../assets/ui-rebuild/compare.html`
（逐状态对照页，属于开发期工具，用的时候拷进片子目录，不进入成片）。两者都不带任何外观设定，颜色、字体、尺寸都由复刻页自己从截图里量出来。

## 1. 参考帧：在截图自己的像素坐标里搭

- 截图是 2x（Retina）的，就把**截图像素 ÷ 2** 作为参考帧（1280×82 的截图对应 640×41 的参考帧）。复刻页的根节点就取这个尺寸，每个元素按量到的位置**绝对定位**。
- 坐标从截图上量，不靠目测：扫描非背景像素所在的 x 区间和 y 范围，并取点读颜色（解析 PNG 可以借用 film-core `lib/pngmix.mjs` 的 `decodePng`）。量到的数集中写成常量表 `M`，并注明是从哪张截图量的。
- 复刻页在画面里整体缩放 `s` 后放到某个位置（`placeReplica({x, y, s})` 给出参考帧到画面的映射），镜头再做变焦 `zoom`。复刻页内部只使用参考帧坐标。
- **CSS 统一收在一个根类名下**（如 `.rb-root .rb-btn`）：代价是类名长一点；不这样做的话，复刻页里的通用类名会和片子自己的样式冲突。

## 2. 文字集中在一张表里

界面上的每个字都从 `STR[lang][key]` 读取，用 `strings(STR, lang, base)` 取字，缺少键时直接抛错（避免 `undefined` 显示到画面上）。换语言只需要换表。

**写死的 left 只对一种语言成立。** 其他语言（或者长度会变化的文字，比如计时器）要按**实测宽度**排版：先写入文字，再读取宽度，最后算出相邻元素的位置。这一步在 `set()` 里完成，读取的是本次刚写进去的布局，不会破坏纯函数性质。

## 3. 界面状态 = `set(state)` 的纯函数

```js
const states = { A: { t: 0, D: 2, loop: true }, B: { t: 1.2667, D: 2, loop: false } };
function set(s) { /* 把所有可变属性从 s 写一遍：文字、位置、显隐、颜色 */ }
window.seek = (t) => set(stateAt(t));          // stateAt 是 t 的纯函数：时间轴 → 界面状态
window.UI = { W, H, states, set };             // compare.html 读这个
```

- **每次调用都把所有可变属性写一遍**。如果只写「变了的」属性，乱序 seek 时就会残留上一个状态，这正是 seamcheck 门 2 能抓到的那类跨帧状态。
- 可以读取布局（`offsetWidth`、`getBoundingClientRect`），前提是读的是本次写进去的内容。界面里的插值（比如滑块拖动）也在 `stateAt(t)` 里计算。
- 自测方法：在同一个页面按 `A B A A B B` 的顺序调用 set 并截图，相同状态的截图必须字节一致；在新页面直接 set(B)，结果也必须和前面的 B 一致。

## 4. 1:1 并排对照

```
compare.html?replica=replica.html&ref=ref-{state}.png[&state=A][&lang=en]
```

每个状态占一行，依次是参考图、复刻页和差异图（`mix-blend-mode: difference`，一致的地方显示为黑色）。复刻页需要提供 `window.UI = { W, H, states, set }` 和可选的 `window.ready`；用 deviceScaleFactor=2 截图，就能与 2x 参考图按同样的像素对照。需要数字结果时，在 Node 里逐像素比较，报告「有差异的像素占比」和「平均差」。

剩下的差异多半来自原生控件（滑块圆点的抗锯齿、复选框的勾、按钮文字的亚像素位置），用 div 画出来的永远会差一点。要做到像素级一致，就在复刻页里也使用原生控件，
代价是原生控件的外观会随浏览器构建版本变化，换一台机器重新渲染可能就不一样了（与 film-core `references/kernel.md` §2 讲的字体问题同理）。

## 5. 高亮框的位置从 DOM 量

框、光标和标注的位置都从复刻页的 DOM 上量，不手工填写（手填的框在换语言或改布局后就对不上了）。

| 量法 | 得到的结果 | 什么时候用 |
|---|---|---|
| `localRect(el, root)`（沿 offsetParent 链累加） | 参考帧坐标，**不包含**任何 transform | 之后再用 `placeReplica().box()` 或镜头变换映射到画面 |
| `getBoundingClientRect()` | 视口坐标，**已经乘上了**复刻页缩放和镜头变焦 | 只在绘制高亮框的那一层没有再套镜头变换时使用；如果把它当成参考帧坐标再映射一次，变换就叠加了两遍（框会跑出画面） |

有两个容易踩的坑：
- **`offsetLeft/Width` 是整数**，误差最多 1 个参考帧像素，放大后会乘以 s×zoom（放大 2.77 倍时约为 3 px）。需要贴边对齐时，用 BCR 除以根节点的缩放比
  （`root.getBoundingClientRect().width / root.offsetWidth`），得到带小数的尺寸；按实测宽度排版也是同样的道理，用整数宽度会在差异图上留下一圈重影。
- `display:none` 的元素量出来是 0；字体还没加载完时，量到的是回退字体的宽度。应当在 `window.ready`（等待 `document.fonts.ready`）之后再量，在加载期一次量完并存表，seek 里只查表。

## 6. 可读性是算术

**屏幕字号 = 原字号 × 复刻缩放 s × 镜头变焦 zoom**（`screenPx(fontPx, s, zoom)`）；反过来，`zoomFor(targetPx, fontPx, s) = targetPx / (fontPx × s)`。
例如一个 13 px 的标签，复刻页在 1080 宽的画面里放成 1000 宽（s = 1.5625），屏幕上只有 20.3 px；要达到 36 px，需要变焦 1.772。

目标字号由片子自己决定（写在 style_guide 里，或采用 film-critique 可读性检查的阈值），这里不给具体数值。这个算术的用处是**在分镜阶段就能知道全景镜头里的界面能不能看清**。
把整个窗口放进画面时，多数 UI 文字只有十几像素，旁白点名的控件要么推镜头放大，要么接受「这一镜只交代关系，不要求看清文字」。

## 7. 显示的内容只能来自产品真实输出

复刻页上的任何文字都能随意改，所以事实边界要自己把关：界面上的数据、文件名、数字和生成结果，都要从产品**真实运行产出的东西**里读取
（用脚本从产品产出的文件生成数据表，不要手工输入）。这些内容在 film-story 的事实台账里登记为 `类型=界面`，来源写参考截图和产出文件。账号名、工作区名这类不想公开的信息，复刻页里可以不画；这属于删减，而不是编造。

复刻页以外的外观（配色、镜头语法、高亮框画成什么样子）由每支片子自己决定，写在 style_guide 里。
