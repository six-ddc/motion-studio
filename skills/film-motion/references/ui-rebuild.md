# 从截图重建产品界面

目录：1 参考帧 · 2 文字表 · 3 界面状态是纯函数 · 4 并排对照 · 5 高亮框的位置从 DOM 量 · 6 可读性是算术 · 7 内容只能来自产品真实输出

产品 UI 片有两条路：**把真实截图裁切后做成动画**，或**照着截图用 HTML/canvas 重建界面**再由 `seek(t)` 驱动。怎么选见 film-story 的「产品 UI 类主题」；
本页讲第二条路（实测记录在仓库 `docs/verified/film-story.md` §2g）。外观（颜色、字体、尺寸）全部从截图量出来，这里不给任何设定。

## 1. 参考帧：在截图自己的像素坐标里搭

- 截图是 2x（Retina）的，就把**截图像素 ÷ 2** 当参考帧（1280×82 的截图 → 640×41）。复刻页根节点取这个尺寸，每个元素按量到的位置**绝对定位**。
- 坐标从截图上量，不靠目测：扫描非背景像素的 x 区间与 y 范围，取点读颜色（解码 PNG 可借 film-core `lib/pngmix.mjs` 的 `decodePng`）。量到的数集中写成常量表，注明量自哪张截图。
- 复刻页整体缩放 s 后放到画面 (x, y)：参考帧点 → 画面点 = `(x + lx·s, y + ly·s)`；镜头再做变焦。复刻页内部只用参考帧坐标。
- **CSS 收在一个根类名下**（如 `.rb-root .rb-btn`）：代价是类名长一点；不这样做，复刻页里的通用类名会和片子自己的样式冲突。

## 2. 文字集中在一张表里

界面上的每个字从 `STR[lang][key]` 读，缺键时回落到基准语言，再缺就抛错（不让 `undefined` 上屏）。换语言只换表。

**写死的 left 只对一种语言成立。** 其他语言（或长度会变的文字，比如计时器）按**实测宽度**排版：先写入文字，再读宽度，再算相邻元素的位置。
这一步在 `set()` 里做，读的是本次刚写进去的布局，不破坏纯函数性质。

## 3. 界面状态 = `set(state)` 的纯函数

```js
const states = { A: { t: 0, D: 2, loop: true }, B: { t: 1.2667, D: 2, loop: false } };
function set(s) { /* 把所有可变属性从 s 写一遍：文字、位置、显隐、颜色 */ }
window.seek = (t) => set(stateAt(t));          // stateAt 是 t 的纯函数：时间轴 → 界面状态
window.UI = { W, H, states, set };             // 对照页读这个
```

- **每次调用都把所有可变属性写一遍**。只写"变了的"属性，乱序 seek 时就会残留上一个状态——正是 seamcheck 门 2 抓的那类跨帧状态。
- 可以读布局（`offsetWidth`、`getBoundingClientRect`），前提是读的是本次写进去的内容。界面里的插值（滑块拖动）也在 `stateAt(t)` 里算。
- 自测：同一页面按 `A B A A B B` 调 set 并截图，相同状态的截图必须字节一致；新页面直接 set(B) 也必须和前面的 B 一致。

## 4. 1:1 并排对照

开发期做一个对照页（不进成片）：每个状态一行，依次是参考截图、复刻页（iframe，调 `UI.set(state)`）、差异图（两者叠放加 `mix-blend-mode: difference`，一致处为黑）。
用 deviceScaleFactor = 2 截图就能和 2x 参考图逐像素对照；要数字就在 Node 里逐像素比较，报"有差异的像素占比"和"平均差"。

剩下的差异多半来自原生控件（滑块圆点的抗锯齿、复选框的勾、按钮文字的亚像素位置），用 div 画的永远差一点。要像素级一致就在复刻页里也用原生控件，
代价是原生控件外观随浏览器构建版本变化，换台机器重渲可能不一样（与 `<film-core>/references/kernel.md` 讲的字体问题同理）。

## 5. 高亮框的位置从 DOM 量

框、光标、标注的位置都从复刻页 DOM 上量，不手填（手填的框换语言或改布局后就对不上）。

| 量法 | 得到 | 什么时候用 |
|---|---|---|
| 沿 offsetParent 链累加 offsetLeft/Top（直到根节点） | 参考帧坐标，**不含**任何 transform | 再经"复刻缩放 + 镜头变换"映射到画面 |
| `getBoundingClientRect()` | 视口坐标，**已乘上**复刻缩放和镜头变焦 | 只在画高亮框那一层没有再套镜头变换时用；当成参考帧坐标再映射一次，变换就叠加了两遍（框跑出画面） |

两个坑：
- **offsetLeft/Width 是整数**，误差最多 1 个参考帧像素，放大后乘以 s×zoom（放大 2.77 倍时约 3 px）。要贴边对齐就用 BCR 除以根节点缩放比
  （`root.getBoundingClientRect().width / root.offsetWidth`）得带小数的尺寸；按实测宽度排版同理，用整数宽度会在差异图上留一圈重影。
  offset 链要求根节点有 position 且中间节点没有自带 transform。
- `display:none` 的元素量出来是 0；字体没加载完时量到的是回退字体的宽度。在 `document.fonts.ready` 之后、加载期一次量完存表，seek 里只查表。

## 6. 可读性是算术

**屏幕字号 = 原字号 × 复刻缩放 s × 镜头变焦 zoom**；反过来，需要的变焦 = 目标字号 / (原字号 × s)。
例：13 px 的标签，复刻页在 1080 宽画面里放成 1000 宽（s = 1.5625），屏幕上只有 20.3 px；要 36 px 需要变焦 1.772。

目标字号由片子自己定（写在 style_guide，或采用 film-critique 可读性检查的阈值）。这个算术的用处是**在分镜阶段就知道全景镜头里的界面能不能看清**：
把整个窗口放进画面时，多数 UI 文字只有十几像素，旁白点名的控件要么推镜头放大，要么接受"这一镜只交代关系，不要求看清文字"。

## 7. 显示的内容只能来自产品真实输出

复刻页上的字都能随意改，所以事实边界要自己把关：界面上的数据、文件名、数字、生成结果都从产品**真实运行产出的东西**里读（用脚本从产出文件生成数据表，不手输）。
这些内容在 film-story 的事实台账里登记为 `类型=界面`，来源写参考截图和产出文件。账号名、工作区名这类不想公开的信息可以不画——那是删减，不是编造。
