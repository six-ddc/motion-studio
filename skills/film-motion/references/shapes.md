# 矢量形状层（`assets/runtime/shapes.js`）

目录：0 数据形状 · 1 路径解析与采样 · 2 描边生长 trim · 3 变形 morph · 4 沿路径运动 along · 5 生成器与画法 · 6 实测数字 · 7 已知局限

零依赖、纯函数，浏览器和 Node 都能 import（Node 里不需要 `registerRuntimeResolver()`）。采样器和 morph 的配对、对齐都在加载时建一次，seek 里只查表。
这里没有颜色、线宽、线帽、缓动：样式归调用方的 ctx，进度曲线由调用方先套（`M(EASE.cubic.inOut(q))`）。实测记录在仓库 docs/verified/film-motion.md「shapes.js」一节。

## 0. 数据形状

`Poly = { pts: [[x, y], …], closed }`，`Shape = Poly[]`（一个子路径一个 Poly）。凡是接收"路径"的函数都接受：d 字符串、点数组（开放折线）、Poly、Shape、`pathSampler` 的返回值。
要画就 `c.beginPath(); tracePath(c, shape); c.stroke()`（或 `fill('nonzero' | 'evenodd')`）；要 Path2D 就给 `{ as: 'path2d' }` 或 `toPath2D(shape)`（Node 没有 Path2D，会抛错）。

## 1. 路径解析与采样

`parsePath(d, { tolerance })` 支持 `M L H V C S Q T A Z` 的绝对和相对写法、隐式 L、`S/T` 反射控制点、Z 之后不带 M 的续画、粘连数字（`1.5.5`、`-1-2e1`）、弧标志位不带分隔符（`a50 50 0 01100 0`）。
曲线按 `tolerance`（px，默认 0.25，精度参数）压平成折线：Bézier 用 Wang 公式定段数，弧按弦高定段数。

`pathSampler(path) → { length, shape, subpaths, at(s), slice(a, b) }`：`s` 是全部子路径首尾相接的累计弧长（子路径之间的空跳不算长度），越界夹到两端；`at` 返回 `{ x, y, angle }`，angle 是所在段的切线方向。
d 字符串按值缓存（最多 64 条）；数组每次重建，所以加载时建好采样器再传进 seek。它与 film-typography `pathSampler` 的返回形状相同，可以直接交给 `drawOnPath`。

**代价**：压平是折线近似，弧长比真值略短，相对误差约 `tolerance / (3r)`（r 为曲率半径）：r=100 时 0.08%，r=50 时 0.17%（实测 0.16%）；`tolerance: 0.01` 时 r=100 的圆周误差 0.02 px。点数随 1/√tolerance 增长，r=300 的圆在 0.25 下是 78 个点。

## 2. 描边生长 `trim(path, start, end, offset, { each, as })`

语义同 AE Trim Paths，三个量都是弧长比例：

| 想要 | 写法 | 代价 |
|---|---|---|
| 从头描出来 | `trim(P, 0, k)` | 匀速按弧长走，弯多的地方看起来更慢；要按"视觉时间"走，先把 k 过一道缓动 |
| 两端同时收（满 → 空） | `trim(P, k/2, 1 - k/2)` | 收到最后剩一个点，`round` 线帽会留一个圆点；要干净消失就让 k 走到 1 |
| 循环跑动的光段 | `trim(P, 0, 0.2, t * 速度)` | 开放路径绕回时拆成两段（首尾各一截）；闭合路径绕过起点时接成一条，不留线帽缝 |
| 多个子路径一起描 | 默认（`each: false`）按全部子路径首尾相接的总长算比例 | 短的子路径一闪就过、长的拖很久；`each: true` 让每个子路径按同样比例各自走，代价是它们速度不同 |

`start = end` 返回空数组；`|end − start| ≥ 1` 返回整条路径（闭合的保持闭合）。描边端点和 `along(P, end + offset)` 是同一个点（夹具 strip.html 第 5 行可以对照看）。

## 3. 变形 `morph(a, b, opts) → m(p)`

做法（flubber 那一类方法的自实现，没有引入依赖）：

1. **重采样**：每对子路径按弧长等距取 N 个点。转角大于约 15° 的原顶点按转角从大到小各吸附一个最近的采样点，所以多边形的角在 p→0⁺ 时不会被削掉（实测偏差 1e-7 px 量级）。
2. **统一绕向**（`winding: 'match'`）：两边有向面积符号相反就把 b 反过来。不反的代价是中间态翻折穿过自身。
3. **对齐起点**（`align: 'rotate'`）：在 N 个旋转里挑逐点位移平方和最小的那个，O(N²)，只在加载时做。`'none'` 保留各自起点（形状会拧过去）；整数手工指定偏移。
   开放路径改为比较正向与反向；一开一闭时把闭合的那条在最佳起点剪开，中间态是开放折线，代价是剪开处有一道缝。
4. **配对**（多子路径）：`pair: 'auto'` 按「质心距离² + 面积平方根之差²」贪心配对，孔洞只和孔洞配（孔洞 = 与最大子路径绕向相反的闭合子路径）；`'order'` 按下标；`[[i, j], …]` 手工指定。贪心不保证全局最优，复杂的情况手工给。
5. **孤儿**：子路径数量不同时**必须**给 `orphans`，不给就抛错，因为两种处理读起来完全不同：
   - `'self'`：没配上的就地缩到自己的质心 / 从自己的质心长出来（线性插值到同一点 = 绕这点均匀缩放）。读作"消失 / 出现"。
   - `'nearest'`：缩进 / 长自对面离它最近的已配对子路径的质心。读作"合并 / 分裂"，代价是孤儿在中途和那个子路径重叠，fill 时重叠处按填充规则叠加。
6. **插值**：逐点线性插值。p ≤ 0 返回 a 原样，p ≥ 1 返回 b 原样（孤儿不会在端点留下退化的点）。

`samples` 不给时按较长那条的弧长每 4 px 一个点，夹在 [32, 1000]；`m.pairs` 列出每对的下标、点数、旋转偏移、是否反转和平均每点位移²（cost），用来判断配对合不合理。
`selfCrossings(shape)` 数中间态里不相邻的段真相交了几次，O(N²)，给调参和测试用，别放进 seek。

**什么时候值得**：形状之间有"是同一个东西"的关系（图标变图标、数据点变成形状、logo 演绎）。差异很大的形状逐点直线插值，中段会显得"揉"成一团；
想要的是"拆开再拼"时，trim 出场加 trim 入场往往更好读。距离很远的两个形状变形时位移被平移主导，看起来是"边飞边变"，想先飞后变就把平移拆出来自己做。

## 4. 沿路径运动 `along(path, p, { orient, lookahead, wrap })`

返回 `{ x, y, angle }`。`p` 是弧长比例；只有一个闭合子路径时默认绕回（p 可以一直涨，循环片的周期就是 p 走 1 的时间），否则夹在 [0, 1]。
`orient`：`true` 取切线方向，`false` 恒为 0，数字表示切线再加这么多弧度（素材画成朝上时给 `Math.PI / 2`）。
`lookahead`（px）用 [s − L/2, s + L/2] 两点连线定朝向：折线拐角处朝向不再突跳（直角处给出 45°），代价是急弯里物体看起来"切内道"。
匀速按弧长走，弯道不减速；要物理感就让 p 过缓动或用 film-physics。多子路径时 p 跨子路径会瞬移。

## 5. 生成器与画法

`circle(cx, cy, r)` `ellipse(cx, cy, rx, ry)` `roundRect(x, y, w, h, r | [tl, tr, br, bl])` `polygon(cx, cy, r, n, rotation)` `star(cx, cy, r1, r2, n, rotation)` 返回 d 字符串，
全部从 +x 方向（或左上圆角之后）起、屏幕坐标下顺时针。返回字符串而不是点，是为了同一份几何也能塞进 SVG，并且走同一套压平精度。

## 6. 实测数字

Node 22，Apple Silicon，`hrtime` 计时（浏览器里没单独测；浏览器端只确认了夹具过门 1a/1b/2/4）：

| 操作 | 数字 |
|---|---|
| `pathSampler(circle r=300)` 建表 | 0.031 ms，78 个点 |
| `trim(采样器, 0, k, 0.1)` | 0.003–0.007 ms/次 |
| `morph(圆 r=300, 七角星)` 建表，N = 64 / 256 / 1000 | 0.20 / 0.38 / 2.39 ms（对齐是 O(N²)） |
| `m(p)`，N = 64 / 256 / 1000 | 0.0012 / 0.0020 / 0.0078 ms/次 |
| 方 → 五角星，19 个中间态自交 | 对齐后 0；`align:'none', winding:'keep'` 对照 13，平均位移² 27351 vs 4588 |

## 7. 已知局限

自交计数取 39 个中间态（p = k/40）：

| 情形 | 中间态自交 | 说明 |
|---|---|---|
| 凸 ↔ 凸、星 ↔ 星（五角 → 八角，N=64 或 283） | 0/39 | 按弧长对齐足够 |
| 凹形（C 形）→ 圆 | 23/39 帧，每帧最多 1 处 | 开口两侧的点要穿过开口，直线插值必然穿插 |
| 细长蛇形 → 圆 | 15/39 帧，最多 2 处 | 同上，形状差异越大越明显 |
| 8 字（本身自交）→ 圆 | 17/39 帧 | 自交路径的有向面积和绕向没有意义，winding 统一可能挑错方向 |

- 中间态打结时用 `fill('nonzero')` 和 `'evenodd'` 画出来不一样，打结的地方会出现空洞或重叠；描边则直接看到交叉线。补救依次是：手工给 `pair`/`align` 偏移、加 samples（对上表无效，打结来自几何不是采样）、把变形拆成两段经过一个中间形状。
- 孔洞靠绕向识别，不检查包含关系：两个分开的、绕向相反的形状会被当成"外框 + 孔"。
- 没有做 flubber 的三角剖分式（`separate`/`combine`）变形，也没有按形状特征点（角对角）配对。
- 弧长参数化和 SVG/浏览器 `getTotalLength()` 有压平误差级别的差（见 §1），需要和 DOM SVG 精确对齐的场合把 tolerance 调小。
