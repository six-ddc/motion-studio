# 透视斜看一个平面

目录：1 约定与公式 · 2 着色器侧：精确反投影 · 3 正交（纵向压扁）vs 透视 · 4 压扁扫描 tiltcheck · 5 手法：提前跟拍、甩镜先定落点 · 6 可用的库

canvas 2D 只有仿射变换，画不出透视。斜着看棋盘、桌面、地面时，写一个针孔相机：JS 侧投影平面上的点（棋子、影子、标签），
着色器侧按像素反投影回平面画平面本身，两边用同一组公式——只有共用一个投影，画面上的东西才"贴"在同一个面上。
下面的公式提炼自本仓库样例 `films/weiqi-intro`，与该片原实现逐点相差 2.3e-13 px（记录在仓库 docs/verified/film-motion.md §14）。

## 1. 约定与公式

| 量 | 含义 |
|---|---|
| 世界坐标 | x 向右，y 朝向观众（正俯视时就是画面向下），z 垂直平面向上。平面为 z = 0（或 z = h） |
| e（elevation） | 视线与平面的夹角，π/2 为正俯视（此时 z=0 平面上透视量精确为 0，退化成等比缩放） |
| d（distance） | 相机到注视点的距离（世界单位）。越小透视越强，→ ∞ 就是正交 |
| S | 注视点处 1 世界单位 = S 像素 |
| look / screen | 注视的世界点 (lx, ly)，以及它在画面上的像素位置 (px, py) |
| yaw | 绕 z 轴的旋转，正值 = 画面里的世界逆时针转 |

这些都是镜头决策，没有默认值。每帧按 t 算好参数再新建相机，它不存任何跨帧状态，所以运镜就是"参数随 t 的曲线"（可用 film-core 的 `follow`/`camera` 给 e、look 做弹簧）。

```
project(x, y, z):
  (u, v) = 绕 z 转 yaw 后的 (x − lx, y − ly)
  depth = d − v·cos e − z·sin e        // ≤ 0 表示在相机后面
  k = d / depth                        // 该点的局部放大率；半径、线宽、字号乘 S·k
  X = px + S·u·k
  Y = py + S·(v·sin e − z·cos e)·k

地平线（z=0）：Y_h = py − S·d·sin e / cos e    // 画天空/雾的分界用它，不要另估
视场角 → 距离：d = (H/2) / (S·tan(fovY/2))
```

平面上的小圆近似投成椭圆：半径 `r·S·k`，纵向再乘 `sin e`。

## 2. 着色器侧：精确反投影

反投影只需解一个一次分式，所以着色器里得到的是 project 的**精确逆**：

```
unproject(X, Y, h):
  Xp = (X − px)/S，Yp = (Y − py)/S
  den = d·sin e + Yp·cos e；den ≤ 0 → 在地平线以上，视线碰不到平面（返回 null / vec2(1e9)）
  v = (Yp·(d − h·sin e) + h·cos e·d) / den
  depth = d − v·cos e − h·sin e；depth ≤ 0 → null
  u = Xp·depth / d
  (x, y) = (lx, ly) + 反转 yaw 后的 (u, v)
```

着色器里先把 `v_uv` 翻成左上原点的像素坐标（WebGL 的 uv 原点在左下），再反投影得到世界坐标去取棋盘格、木纹。参数用三个 vec4 uniform 传（S, sin e, cos e, d / px, py, lx, ly / cos yaw, sin yaw）。

**远处细线抗锯齿**：一个像素在平面上覆盖的宽度 fp（世界单位）= 相邻像素反投影点之间的距离。线的覆盖率 `cov = clamp((hw − dist)/fp + 0.5, 0, 1)`；
线宽 hw 再加 `0.5·fp` 可以保证远处的线不断开。不这样做，远处的格线会时有时无地闪。

## 3. 正交（纵向压扁）vs 透视

`ctx.setTransform(S, 0, 0, S·sin e, …)` 是 d → ∞ 的极限。代价是平行线不收拢、远边和近边一样宽；眼睛正是靠线条收拢判断平面是斜放的，
没有收拢，**斜放的正方形看上去就是长方形**；压扁方向上的线宽也一起变细。两种情况值得付这个代价：

1. **刻意的平面风格**（图解、等轴测、信息图）：正交保留沿每个轴的比例，可以直接测量。在 style_guide 的 critique 块写 `"ortho_ok": "<理由>"`，压扁扫描就不再提示。
2. **两者差别小于一个像素**：对平面的角点分别做透视投影与"同 S、纵向乘 sin e"的压扁投影，取最大像素差。19 道棋盘（18×18 格、S=49 px/格、d=30 格）实测：

| 俯角 | 远边/近边宽度比 | 透视与压扁的最大差 |
|---|---|---|
| 90° | 1.000 | 0 px |
| 85° | 0.949 | 16.7 px |
| 60° | 0.739 | 103 px |
| 35° | 0.606 | 166 px |
| 35°，d=200 | 0.929 | 19.5 px |

"俯角接近 90° 就差不多"只在很窄的范围内成立，85° 时已经差 16 px。判断依据是算出来的数，不是对角度的感觉。

## 4. 压扁扫描 tiltcheck

`scripts/tiltcheck.mjs`（逻辑在 `scripts/lib/tiltscan.mjs`）。用法见 SKILL.md §5。

这项检查**不能做成判失败的门**，原因是结构性的：斜放正方形的正交像和正俯视长方形的像**逐像素相同**，东西本来是不是方的只有作者知道；
而非等比变换有大量正当用途（挤压拉伸、等轴测、压窄的字、拉伸贴图）。

它做的是指出可疑时段：seek 期间拦截 2D 绘制（路径、矩形、文字、`drawImage`、`fill/stroke(Path2D)`），按**变换矩阵**分组记屏幕外包框；
某组外包框 ≥ 画布 10% 且奇异值比 σ2/σ1 < 0.9（压扁超过 10%）就提示。真透视画法不可能用一个仿射变换画出一整块平面，所以透视片在这里自然是空的；
一群各自挤压的小球各有各的矩阵，每组都小，也不会被提示。两个阈值决定检测灵敏度，与审美无关。

**盲区**：着色器里做的压扁；加载时预渲进离屏 canvas 的压扁（只拦 seek 期间）；`ellipse()` 的 rx ≠ ry（透视下圆本来就投成椭圆，不算）；CSS transform 压扁的 DOM。
它检测的是"有一大块内容在非等比仿射下画出来"，不是"这支片子没有透视"：真透视片里另有一大块刻意压扁的图解层照样会被提示；把压扁做在着色器里的片子照样能通过。所以它是 LOOK 级。

## 5. 手法：提前跟拍、甩镜先定落点

相机参数每帧按 t 计算，怎么跟拍完全取决于曲线怎么写。两种可选写法：

- **提前约 0.1 s 跟拍**：look 取主体在 t + 0.1 时的位置，配一条两头缓的曲线，画面先一步让出空间，主体看起来是"走进"取景框。
  代价是主体急停或急转时相机会先动，像能预知动作；拍机械运动，或想要"被追着拍"的紧张感时，零提前或滞后更合适。主体越快，观众能察觉到的提前量越小。
- **甩镜前先把落点设为关键帧**：落点的 look / screen 对齐到锚点，再从起点插值过去。落点成为可复现、可核对的值（shotlist 里可以写断言），中间拖影怎么画都不会让终点偏移。
  代价是多一个要维护的关键帧；手持感或漫游式镜头本来不需要确定的落点。

## 6. 可用的库（如需）

- **three.js**：真三维场景用 `PerspectiveCamera`，按帧契约改造的做法（关掉渲染循环、seek 里设相机参数后 `renderer.render`）见 film-webfx。
  和本页的二维相机对齐时：竖直视场角 `fov = 2·atan((H/2)/(S·d))`，相机位置 = 注视点 + d·(0, cos e, sin e)（再绕 z 转 yaw），`lookAt` 注视点，再按 screen 偏移设 `setViewOffset`。
- 只是把一张平面图片透视贴上去：CSS `perspective` + `rotateX` 在 DOM 层可用，代价是和 canvas 里画的标注不共用一个投影，要自己保证对齐。
