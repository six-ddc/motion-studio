# 模型：程序化硬表面与 GLB 资产

目录：1 选路 · 2 度量：量，不靠记 · 3 程序化硬表面（拆件、倒角、扫掠、车床、装配合批、贴花） · 4 GLB 进片子 · 5 评审 · 6 LOD · 7 没测到的

片子里要出现**一个具体的、观众认得出的东西**（一部手机、一枚棋子、一台机器）时，难点不在 three 这一侧，而在"这个模型像不像它"。形状对不对以实物为准，做成什么风格由本片 style_guide 决定。

## 1. 选路

| 路 | 适合 | 代价 |
|---|---|---|
| **程序化**（加载期用 BufferGeometry / ExtrudeGeometry / LatheGeometry 或自写顶点） | 规则硬表面：棋子、卡片、设备、建筑、载具、机械；要按参数变形的东西 | 要写、要量截面与法线；连续曲面（手机边框、车身）可以做但成本明显高。好处：无额外资产文件，加载期构造天然确定 |
| **现成 GLB**（素材站、厂商发布、开源仓库） | 复杂但不要求精确的道具；人物、动物、布褶这类有机体 | 面数和材质常不合用；**外形常常只是"像"而不是"就是"**，按 §2 核对 |
| **Blender（Agent 经 MCP 桥建模）** | 观众认得、细节也要像的主体 | 慢，来回几轮是常态。只让 Blender 建**几何和材质槽**；动画、灯光、镜头留在 three 里按 t 求值（Blender 的动画和节点材质导不出来，或导出后不是 t 的纯函数） |

判断：主体会被推近、观众会拿它和实物比较时，§2 和 §5 必须做；远景道具用现成 GLB 或程序化即可。Blender MCP 的环境问题（外部经验，本仓库没复测）：沙盒里启动的 Blender 不开放端口，要在沙盒外启动；默认立方体会被一起导出；导出前把材质槽设为数据级。

## 2. 度量：量，不靠记

凭记忆建出来的模型会长成"上一个模型"的样子。
1. 找**接近正交投影**的官方图（正视/背视静帧、技术图纸、说明书尺寸图）：同一条边在图两端量出的像素宽度相差不到 1%。透视明显的宣传图不能量。
2. 用一个**已知尺寸**定比例尺：规格里的机身宽（mm）÷ 图上像素数。例：图上 507 px、规格 71.5 mm → 7.09 px/mm，12.4 px 就是 1.75 mm。
3. 逐项量：孔和镜头的圆心与直径、圆角、各部件到边缘的距离、分缝位置。0.1 mm 级差异在推近的镜头里看得出。
4. 颜色也量：从官方配色静帧取色（避开高光和阴影区），记 sRGB 值。
5. 写进片子 `docs/`（如 `docs/model-measure.md`：用了哪张图、比例尺怎么来、每项多少），建模时引用。

代价：每个主体半小时到一小时。值得付的情况：主体占画面三分之一以上，或是观众每天拿在手里的东西。

## 3. 程序化硬表面

**拆件**：先用参考图和一个真实尺寸定比例、做剪影，再把主体拆到每件能选一个基元：盒体、剖面挤出、扫掠、车床体、管线。按**运动关系**建层级和枢轴，而不是按颜色。流程：拆件 → 造型/倒角 → 装配 → 米制 UV → 材质 → 顶点风化（three-world.md §4）→ 静态合批 → 统一光照。
按镜头距离分配预算：改变剪影、接到掠射光、会被推近的细节值得用几何；小铭文、污点、远景孔槽交给贴花/法线。真布尔代价高时可以改剖面设计、分件留缝或内衬暗面；近景透视会揭穿假孔，届时值得做真洞。

**基元的原理与坑**：

| 基元 | 原理 | 坑 |
|---|---|---|
| 倒角盒 | 六面各自分段，再把顶点投影到"内缩盒 + 半径"的圆角表面，法线取投影方向 → 法线连续 | 分段少时圆角有棱；更多分段增加顶点 |
| 剖面扫掠 | 闭合二维剖面沿一串截面中心移动，每个截面给局部坐标架 (u, v) | 默认坐标架（如 Frenet）在急转、竖直切换处会翻转扭曲，复杂路径显式给 u/v（或用平行传输架）；保证侧面和封口恒朝外，与剖面绕向和坐标架手性无关 |
| 车床体 | `[半径, 高度]` 轮廓绕 Y 轴旋转；封口由零半径端点表达 | U 取各半径处的圆周弧长、V 取轮廓弧长；强烈变径的锥面纹理会扇形变形 |
| 挤出 | 二维多边形三角化 + Z 向拉伸，可带倒角 | 凹多边形要正确三角化；只在侧面内焊接平均法线，封口保持平面；要保留的硬边拆成不同几何 |
| 管线 | Catmull-Rom 路径 + 圆截面扫掠 | 细管离镜头远时闪，降细节或按像素覆盖补偿 |

**截面扫掠 vs n-gon + 倒角**：n-gon 加倒角修改器加平滑着色快，但导出后大 n-gon 被三角化成扇形，插值法线产生明暗条纹；圆弧圆角在直边交界处曲率跳变，掠射光下能看出"折痕"。主体会被推近、材质有反射（金属、玻璃、清漆）时，用**一条截面沿超椭圆圆角路径扫掠**（`|x/a|ⁿ + |y/b|ⁿ = 1`，n≈3，曲率连续），法线解析计算，开孔做真孔——反射会放大每一处法线错误。

**装配与静态合批**：零件 = (几何, 材质, 位置, 旋转, 枢轴)；可动件标记出来保留独立节点。重复件（螺栓圈、导轨齿、散热片）共享几何和材质引用。加载期把静态网格**按材质对象身份**合并：draw call 大降、非索引顶点数上升（实测：45 个 mesh 合成 6 个，三角形 19986 不变，顶点 13065 → 58578；SwiftShader 整帧 57.0 → 35.2 ms，GPU 1.7 → 1.6 ms）。
- 合批后从结果里按名字找可动节点再动画，不要继续动画合批前的引用（那已经不在场景里了）。蒙皮、实例、形变网格留在可动子树。
- 镜像变换会翻三角形绕向，合批时要翻回。
- 舞台每帧复位变换和材质值，但不替模型改顶点缓冲区。

**贴花与表面细节**：带透明贴图的平面 + `polygonOffset` + `depthWrite:false`，防共面闪烁；roughness 要显式（印刷纸、漆、金属箔的高光完全不同）；强弯曲面拆小贴花。磨损用种子化的 `destination-out` 在加载期擦划痕和斑点。模板字（桥缝）先等随片字体加载完再画，系统字体会被字体来源门判红。

**参考结构**（拆解游戏源码得到的两个例子，尺寸是其代码里的值，不宣称符合真实产品）：
- 近景步枪：上下机匣、握把、护木、瞄具外框都是剖面挤出；顶导轨是截面扫掠 + 49 个 10 mm 节距的齿；枪管是 20 段车床体；弹匣、枪机按枢轴独立运动；铭文是投影贴花；按 7 种材质与可动块合并。
- 四足机械体：root → body → neck/head、turret/gun，四腿各三节，是刚体层级装配而非蒙皮；散热器 10 片薄盒（节距 28 mm）；按 shell/metal/glow/lens 分组合批。
可迁移的方法：用真实零件的功能组织形体，用倒角承接高光，用少数材质组统一表面，用枢轴隔离运动。

加载期耗时很小（倒角盒 384 顶点 0.17 ms、管道 585 顶点 0.29 ms）。没有真布尔、曲率连续 CAD 曲面、自动 LOD、骨骼蒙皮、自动 UV 展开；相机近到能读出法线误差时，显式截面或外部资产更值得。

## 4. GLB 进片子

片子必须自包含（film-assets）：

| 方式 | 怎么做 | 代价 |
|---|---|---|
| 随片 assets | `films/<slug>/assets/models/x.glb`，在 `ready` 里 fetch，`GLTFLoader.parse(arrayBuffer, …)` | 必须经 http 打开（渲染器的静态服务器满足） |
| base64 内联 | `assets/models/x.glb.js` 内容为 `window.X_GLB = '<base64>'`，ready 里解码再 parse | 可从 `file://` 打开；体积 ×4/3，整串进 JS 堆；几 MB 以内可以 |

- **加载必须在 `window.ready` 里等完**（kernel.md 门 1b）：`parse` 是回调式，包成 Promise。加载完再 `S.freeze()`，模型节点才进复位快照。
- GLTFLoader 不随片：从同一版本 three 包拷进片子，import map 指向 three-film，拷完 grep 一遍 `setTimeout`（three.md §1）。
- Draco / KTX2 / meshopt 要额外的解码器（wasm、worker）；解码是确定的，但解码器文件要随片放进 `assets/` 并登记。
- 骨骼动画用 `mixer.setTime(t)`，不用 `update(delta)`。

## 5. 评审：悬空、黑底、只用环境光

查形体时先拿掉布景：模型悬空在纯黑底上，只用一张环境贴图（PMREM）照明，不加主光、不加地面（主光和地面阴影会掩盖或制造形体问题）。静帧取正面、背面、45° 侧面，以及贴近边缘的掠射角（圆角和倒角在掠射下最容易露馅）。形体确认后再放进本片布景和灯光。这些静帧只用于评审，不进成片。

## 6. LOD（可选）

同一模型出现成百上千次（阵列、群体）时：
- 建 2–3 级（hero 全细节只给最近几个、mid、lo 几百到一两千三角形），每级一个 InstancedMesh。
- **每次 seek 都按到相机的距离重新分级**：相机和物体位置都由 t 算出，分级也是 t 的纯函数。阈值按本片实测（在哪个距离上 lo 和 hero 的截图分辨不出）。
- 同一级各材质部件共享一个 instanceMatrix 属性，一个实例每帧只写一次矩阵；颜色差异走 `instanceColor`。
- 复位管不到 instanceMatrix：每帧把 `count` 和所有在用的矩阵写满。
- three 视锥剔除用基础几何的包围盒，实例分散时会误剔：`frustumCulled = false`，自己按投影剔除。
- 软件渲染下面数直接等于成本：先测目标面数下的单帧耗时再决定。

## 7. 没测到的

- 本仓库没经 Blender MCP 建过模型；没有在 seamcheck 下跑过带 GLB 的片子（"加载完再 freeze、把 parse 包进 ready"是由帧契约推出来的）。
- Draco / KTX2 解码器在 SwiftShader 下的耗时和确定性；万级实例在 SwiftShader 下的耗时。
- LOD 切换那一帧会不会跳（hero 和 mid 形体不同）没有门能查，只能靠人看，或在切换距离上做淡入淡出。
