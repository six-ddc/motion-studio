# 模型资产：获取 → 度量 → 评审 → 内联

本页是 SKILL.md 第 7 节的补充。片子里要出现**一个具体的、观众认得出的东西**（一部手机、一枚棋子、一台机器）时，难点不在 three 这一侧，而在于「这个模型像不像它」。本页只讲做法和代价，不涉及审美：形状对不对以实物本身为准，做成什么风格由本片 style_guide 决定。思路借鉴自 onetake 的 3D 笔记（来历见仓库 docs/verified/film-webfx.md 末节）。

## 1. 获取

| 路 | 适合 | 代价 |
|---|---|---|
| **程序化**（加载期用 BufferGeometry / ExtrudeGeometry / LatheGeometry 或自己写顶点） | 规则形体：棋子、棋盘、卡片、柱体、截面恒定的条带；以及需要按参数变形的东西 | 要花写代码的时间；复杂曲面（手机边框、汽车）写不出来。好处是没有资产文件、没有许可问题，天然确定 |
| **现成 GLB**（素材站、厂商发布、开源仓库） | 复杂但不要求精确的道具 | 要查授权（见第 4 节末尾）；面数和材质经常不合用；**外形常常只是「像」而不是「就是」**，要用第 2 节的量法核对一遍 |
| **Blender（由 Agent 经 MCP 桥建模）** | 观众认得、细节也要像的主体 | 慢，来回几轮是常态。只让 Blender 建**几何和材质槽**，动画、灯光、镜头留在 three 里按 t 求值（Blender 的动画和节点材质导不出来，或者导出后不是 t 的纯函数） |

判断方法：主体会被镜头推近、观众会拿它和实物比较时，第 2、5 节必须做；只是远景道具时，用现成 GLB 或程序化建模即可。Blender MCP 的环境问题（onetake 实测，本仓库没有复测）：在沙盒里启动的 Blender 不开放端口，需要在沙盒外启动；默认的立方体会被一起导出；导出前要把材质槽设为数据级，导出后再恢复可见性。

## 2. 度量：量，不靠记

凭记忆建出来的模型，会长成「上一个模型」的样子。做法如下：
1. 找**接近正交投影**的官方产品图（正视或背视静帧、技术图纸、说明书尺寸图）：同一条边在图两端量出的像素宽度相差不到 1%。透视明显的宣传图不能用来量。
2. 用一个**已知尺寸**定比例尺：用规格里的机身宽度或高度（mm）除以图上的像素数。例如图上机身宽 507 px、规格为 71.5 mm，得到 7.09 px/mm，图上的 12.4 px 就对应 1.75 mm。
3. 逐项测量：孔和镜头的圆心与直径、圆角、各部件到边缘的距离、分缝位置。精度到 0.1 mm 的差异在推近的镜头里是看得出来的。
4. 颜色也要量：从官方配色静帧里取色（避开高光区和阴影区），记录 sRGB 值。
5. 量到的数写进 `docs/`（如 `docs/model-measure.md`，记录用了哪张图、比例尺怎么来的、每一项是多少），建模时引用它。

代价是每个主体要花半小时到一小时。值得付的情况是：主体占画面三分之一以上，或者是观众每天都拿在手里的东西。

## 3. 评审：悬空、黑底、只用环境光

检查形体对不对时，先把布景拿掉：让模型悬空在纯黑底上，只用一张环境贴图（PMREM）照明，不加主光，也不加地面（主光和地面阴影会掩盖形体问题，或者制造出不存在的问题）。形体确认无误后，再放进本片的布景和灯光里。评审静帧取正面、背面、45° 侧面，以及贴近边缘的掠射角（圆角和倒角在掠射角下最容易露出问题）；这些静帧只用于评审，不进入成片。

## 4. 内联：GLB 进片子

片子必须自包含（film-assets 第 1 条）：

| 方式 | 怎么做 | 代价 |
|---|---|---|
| **随片 assets** | 放在 `films/<slug>/assets/models/x.glb`，在 `ready` 里 `fetch`，再调用 `GLTFLoader.parse(arrayBuffer, …)` | 必须通过 http 打开（渲染器的静态服务器满足这一点）；文件本身要登记进台账 |
| **base64 内联** | 生成 `assets/models/x.glb.js`，内容为 `window.X_GLB = '<base64>'`；在 `ready` 里解码成 `Uint8Array` 再 `parse` | 可以直接从 `file://` 打开；**体积变为原来的 4/3**，整个字符串都进入 JS 堆。几 MB 以内可以这样做，几十 MB 就不适合内联了 |

确定性要点：
- **加载必须在 `window.ready` 里等待完成**（kernel.md 门 1b）：`parse` 是回调式接口，要包成 Promise 放进 ready。加载完成后再调用 `S.freeze()`，模型节点也会进入复位快照。
- `GLTFLoader` 不在 three-film 里：按 three.md §1「插件」一段的做法，从**同一版本**的包里拷进 `runtime/`，用 import map 指向 three-film，拷完再 grep 一遍 `setTimeout`。
- Draco / KTX2 / meshopt 压缩需要额外的解码器（wasm、worker）。解码过程是确定的，但又多了一份需要随片打包、登记入账的东西；如果要压缩，解码器文件要和模型一起放进 `assets/`。

许可：模型要登记进 `assets/LICENSES.md`（film-assets 台账里的「3D 模型」一类，记录来源、许可、是否可以再分发、是否含有商标外形）。自己建的模型也要记一行（来源写「自建」，并注明参考了哪些官方图；参考图本身不进仓库）。

## 5. 截面扫掠 vs n-gon + 倒角

| 做法 | 代价 | 什么时候值得 |
|---|---|---|
| n-gon 加倒角修改器加平滑着色 | 快（几分钟）。导出 glTF 后，大的 n-gon 被三角化成扇形，插值法线会产生明暗条纹；圆角处曲率不连续，在掠射光下能看出「折痕」，看起来像一张卡片 | 远景、尺寸小、哑光材质；或者镜头从不掠过它的边缘 |
| **一条截面轮廓**（玻璃边、胶圈、唇边、中框、背面翻边）沿超椭圆圆角路径（如 n≈3）扫掠，法线用解析方式计算；开孔是真正的开孔，镜头组用旋转体叠加 | 慢（要写扫掠脚本、测量截面）；面数高，需要配合第 6 节的 LOD | 主体、会被推近、材质有反射（金属、玻璃、清漆）：反射会放大每一处法线错误 |

超椭圆圆角（|x/a|ⁿ + |y/b|ⁿ = 1）的曲率是连续的；圆弧圆角在直边和圆弧的交界处曲率会跳变，反射高光在那里会「断」一下。

## 6. LOD 分级（可选）

同一个模型出现成百上千次（阵列、群体）时：
- 建 2–3 级：`hero`（全部细节，只给离相机最近的几个）、`mid`、`lo`（几百到一两千个三角形），每一级各自是一个 InstancedMesh。
- **每次 seek 都按「到相机的距离」重新分级**：相机和物体的位置都由 t 算出，所以分级也是 t 的纯函数。距离阈值按本片的模型和镜头实测确定（在哪个距离上 lo 和 hero 的截图分辨不出差别）。
- 同一级里各个材质部件共享同一个 `InstancedBufferAttribute` 作为 instanceMatrix，这样一个实例每帧只写一次矩阵；颜色差异通过 `instanceColor` 或自定义属性实现。
- 舞台复位管不到 `instanceMatrix`（见 three.md §2）：每帧都要把 `count` 和所有在用的矩阵写满。
- three 的视锥剔除使用基础几何的包围盒，实例分布得很分散时会被误剔除：设置 `frustumCulled = false`，自己按投影结果剔除。
- 软件渲染下，面数直接等于成本：先用 `dev/film-webfx/bench3d.mjs` 测出目标面数下的单帧耗时，再决定要不要做 LOD。

## 7. 没测到的

- 本仓库没有经 Blender MCP 建过模型；GLTFLoader 没有 vendor 进来，也没有在 seamcheck 下跑过任何一支带 GLB 的片子（「加载完再 freeze、把 parse 包进 ready」是根据 three-film 的契约推出来的）。
- Draco / KTX2 解码器在 SwiftShader 下的耗时和确定性没有测过；onetake 的万级实例是在 GPU 后端上跑的，SwiftShader 下没有测过。
- LOD 切换的那一帧会不会「跳」（hero 和 mid 的形体不同）没有门可以检查，只能靠人看，或者在切换距离上做淡入淡出。
