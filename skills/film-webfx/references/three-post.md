# 三维 HDR 后期：原理、难点、代价

目录：1 链的结构与 seek 下的难点 · 2 各效果的原理与坑 · 3 显示端（色调映射、调色、FXAA、颗粒、抖动） · 4 离线曝光 · 5 代价与局限

这里的效果都需要深度或 HDR，所以在三维路线里做；只吃一张画面的后期（色差、半调、LUT……）原理见 `post.md`，同样适用于三维的最后一遍。
自写后期挂到舞台上的方式见 three.md §2。数值全部由本片 style_guide 决定。

## 1. 链的结构与 seek 下的难点

一种经过实测的结构（单个 WebGL2 context，render target 串联，不经 2D 中转）：

```
场景 → rtScene（HalfFloat 线性 HDR；可选 MSAA；要深度时带 DepthTexture）
  ├ [AO / 阴影步进体积雾]（读深度，半分辨率）
  ├ 泛光 / 景深 / 径向光柱（各自的子链）
  └ 合成一遍：故障位移 → 色差 → 叠泛光/光柱/拉丝/眩光 → 曝光 + 色调映射 → 调色 → sRGB → 暗角 → 扫描线
      → [FXAA / 锐化 / 颗粒 / 去色带抖动] → 预乘 alpha 输出
```

在 `seek(t)` 下难在：
- **结构 vs 风格参数分开**：启用哪些效果、几级、几步、什么分辨率在加载期定，着色器只编译一次（SwiftShader 下编译几十到几百 ms，别在 seek 里改结构）。阈值、强度、半径、颗粒量等风格参数**每帧全量传**，缺了抛错——既不沿用上一帧，也不取"好看的默认"。
- **强度为 0 跳过子链**：省下景深这类大头，但合成时那一项要绑黑纹理或权重恰为 0；读到残留的旧 RT 就是跨帧状态。
- **官方 EffectComposer 构造时建 Clock，pmndrs EffectPass 内部累积 time**：要么拆出各 pass 自己串，要么把它们的时间改成从 t 传（three.md §1）。
- **renderer 状态泄漏**：每个 pass 改了 render target、viewport、scissor、`toneMappingExposure`、`autoClear`，用完要还原；否则下一次 seek（或乱序时的另一帧）从不同起点开始。最后一遍渲染到屏幕时 three 才做色调映射，渲到 RT 时不做。
- **半精度溢出**：场景里超过 65504 的像素在 HalfFloat 里是 Inf（SwiftShader 下直接 NaN），模糊会把一个坏像素扩成一片黑块。每条子链的入口把 Inf 钳到 65504、NaN 置 0。

## 2. 各效果的原理与坑

**泛光**两种做法：
- **阈值相加**：软膝提取 `max(0, L−thresh+knee)²/(4knee)` 平滑过渡，13 tap 下采样 × N 级，3×3 帐篷上采样逐级加回（Jimenez 2014 / UnrealBloomPass / pmndrs MipmapBlur），`src + strength·bloom`。代价：强度高时整体发白。
- **能量混合**：不设阈值，下采样链逐级 mix 上采样，最终 `mix(col, bloom, strength)`。代价：原亮点失去部分峰值。Karis 平均（按 `1/(1+luma)` 加权第一级）压萤火虫闪烁，但也压低稀疏的极亮点。
- 泛光恢复不了被截成 1 的亮部信息：高光要先在 HDR 场景里成立（自发光 > 1、光源强度够），再谈泛光。

**景深**：CoC = `blur · |1 − focus/z|`（像素），单遍螺旋采样聚集（Gustafsson 2018），采样数 ≈ (maxBlur·分辨率)² / (2·step)；maxBlur 16、半分辨率约 64 次，每次两次纹理读取。近处大模糊要能"盖"到焦内物体上（按散射半径比较而不是只看中心像素的 CoC），否则前景虚化边缘是硬的。焦点距离写成 t 的函数就是拉焦。

**径向光柱（god rays）**：亮部提取到 1/4 分辨率，朝光源屏幕位置做径向模糊（GPU Gems 3 第 13 章）：沿 `uv → lightUV` 取 N 步，权重按 decay^i 衰减。光源在相机后面时不画；光源出画时按距离淡出，否则一出画就跳变。

**屏幕空间 AO**：读深度重建视空间位置，在半球内取 N 个样本比较深度。只见屏幕内深度；轮廓有光环、透明物体缺遮挡；缩半分辨率丢细接触，加大容差会跨边缘漏遮蔽。按亮度退让（亮处少压）只是环境光近似，分不开直射/自发光/间接光。

**阴影步进体积雾**：沿视线步进，每步查太阳的**当帧**阴影图，`acc += T·source·(1−e^{−σ·ds})`，`T *= e^{−σ·ds}`。密度 `σ·(b + (1−b)·e^{−max(y−y0,0)/H})`（高度衰减）；相位函数用双瓣 Henyey–Greenstein（前向 + 宽瓣混合，两个 g 在 (−1,1)）。步进起点用 IGN（`fract(52.98·fract(dot(px, (0.0671, 0.00584))))`，屏幕坐标的纯函数）抖动，把条带换成细噪——**不能用随帧变化的随机**，否则时间上闪烁且不可重复。超出步进距离的远景用高度密度的解析积分延续。局限：只支持透视相机 + 一个平行光的深度阴影；阴影视锥外按受光算；步数低出条带。

**眩光（lens flare）**：太阳投影到屏幕，沿"太阳 → 画面中心"连线放几个幽灵（ghost）、一圈光晕（halo）。可见性：每帧对太阳周围 3×3 深度采样，深度达到远平面才算可见；画外样本按可见计，整体按太阳出画的 NDC 距离线性淡出。天空里的日盘要 `depthWrite:false`，否则自己的深度挡住眩光。无帧间平滑，遮挡边界可能跳变；加大采样半径更柔，代价是细遮挡物被淡化。

**变形镜头拉丝、镜头脏污**：拉丝从泛光的某一级取样再横向长核模糊，细光源会变宽；脏污是加载期按固定种子生成的软圆斑纹理，乘泛光再叠加。

## 3. 显示端

- **色调映射**：ACES、AgX、Neutral 等曲线在线性 HDR 上做；两条曲线可按比例混合。之后在显示线性域调色（暗/亮部乘色、S 曲线对比、抬黑、按亮度调饱和度），最后精确分段 sRGB 编码。
- **FXAA**：在编码域按亮度边缘方向取样（亮度可以存在中间 RT 的 alpha）；不能恢复亚像素几何——细几何的锯齿要么 MSAA（贵，见 three.md §7）要么加粗几何。
- **退让式锐化**：四邻域反锐化，强边缘按阈值退让，避免光环。
- **颗粒**：两个独立均匀 hash 之差（三角分布），按 `floor(t·fps)` 播种；按暗部加权更像胶片。
- **去色带抖动**：`±amount/255` 的噪声，与帧号无关。H.264 yuv420 会吃掉细颗粒和小抖动，判断效果要看编码后的成片。
- 色差、颗粒会吃细边：本仓库样例 xa-agent 在 chroma 1.5、grain 0.05 时细环边缘发虚，降到 0.6 / 0.025 后改善（同时开了 MSAA，两项没拆开测）。看全分辨率静帧判断。

## 4. 离线曝光

需要适应亮暗场时，**不在 seek 里累积平均亮度**（那是跨帧状态）。做法：
1. 在开发脚本里按固定间隔（如 4 fps）逐个 seek，读回每帧曝光前 HDR 的对数平均亮度（逐级 4×4 盒子降到长边 ≤ 64，可中心加权、钳上下限防纯黑/纯白镜头）。
2. 存成片内 JSON，正式页面在 `ready` 里读。
3. 加载期一次完成：查表线性插值 + 对数亮度域的因果指数平滑（时间常数 τ），`exposure = (key / avg)^power`，power < 1 保留场景亮暗差。
4. seek 里只查表。表是 t 的纯函数，乱序调用结果不变。

## 5. 代价与局限

逐项增量见 three.md §7。下面是更长链的整帧数字（1080×1920、本仓库简单柱廊/四球场景，预热后 7 次读回阻塞计时中位数，ms/帧）：

| 配置 | SwiftShader，AO/雾半分辨率 | SwiftShader，AO/雾全分辨率 | Metal，半 / 全 |
|---|---:|---:|---:|
| 仅显示链（映射 + 调色 + 收尾） | 35.3 | 36.4 | 1.8 / 2.0 |
| 加能量混合泛光 | 90.1 | — | 2.1 / — |
| 加 AO 16 采样 | 86.4 | 142.0 | 2.8 / 3.1 |
| 加体积雾 24 步 | 125.8 | 238.1 | 2.1 / 3.6 |
| 全开 | 269.7 | 447.9 | 5.0 / 6.4 |

- 前景层（深度被压到 [0, ε] 永远在最前的物体，如手持道具）会被后期读成贴脸近处：景深整块糊掉、AO/雾按极近距离算。后期里按同一个 ε 把它排除。
- 时间运动模糊由 film-core 的子帧平均完成，这里不重复做相机速度模糊。没有 TAA、SSR、自动曝光积分：它们都依赖历史帧。
- 后期 RT 开 MSAA 并带深度纹理时，景深边缘是否正确没验证。
- 可用的库（如需）：three examples/jsm 的 UnrealBloomPass、BokehPass、SSAOPass/GTAOPass、OutputPass（拆出来自己串）；pmndrs `postprocessing`（Bloom、DepthOfField、GodRays、SMAA、ToneMapping，把时间改成从 t 传）；`n8ao`（SSAO）。都没在本仓库 seamcheck 下复测。
