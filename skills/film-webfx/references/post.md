# 后期、风格化与调色（2D / 全屏着色器路线）

目录：1 共同约定 · 2 一遍完成的逐像素后期（色差、颗粒、晕影、色调映射、镜头畸变） · 3 多遍：泛光、halation、变形镜头拉丝、模糊与景深 · 4 风格化（半调、抖动、像素化、Sobel、Kuwahara、ASCII） · 5 调色（lift/gamma/gain、3D LUT） · 6 对细线与小字的影响 · 7 没做的

这是一张能力菜单，不是推荐：用不用、取什么值由本片 `docs/style_guide.md` 决定。三维场景的 HDR 后期（深度景深、AO、体积光、眩光、曝光）在 `three-post.md`。
耗时：SwiftShader、16 线程，单次 render，输入是一张静态纹理（不含 2D 画面上传的约 2 ms），本仓库实测；格式 `1080×1920 / 540×960`。

## 1. 共同约定

- 单遍用 `webfx.js` 的 `createShaderLayer`（或 fxchain 的 `createPass`：同形接口、缺 uniform 抛错），两遍以上用 `createChain`（fxchain.md）。
- 输入是**预乘色**（2D canvas 上传后就是），输出也要预乘。做曲线、乘色之前 `rgb /= max(a,1e-5)`，做完乘回。
- 逐帧变化的噪声只按帧号播种：`u_frame = Math.round(t*fps)`。颗粒取 24、12 还是逐帧换，是风格选择。
- **合进一遍**：每个全屏 pass 在 SwiftShader 下至少有几 ms 固定成本。色差、颗粒、晕影、扫描线、色调映射、调色写进同一个着色器，只付一次全屏（三维路线实测：五样合一 +18.7 ms，分开做要多约 45 ms）。
- 降分辨率（`scale:0.5`）成本约 1/4，但风格化的颗粒（网点、抖动格、像素格、字形）以**本层像素**计，放大后跟着变大、边缘被双线性糊掉；要锐利格子，用全分辨率或 `drawTo(ctx,{smoothing:false})`。

## 2. 一遍完成的逐像素后期

| 效果 | 原理 | 代价 |
|---|---|---:|
| 色差 / RGB 分离 | R、B 沿径向反向偏移采样：`d=(uv−.5)·amt`，R 取 `uv+d`、B 取 `uv−d`，G 不动 | 7.1 ms（3 次采样） |
| 颗粒 | `hash12(gl_FragCoord.xy + 17·u_frame + u_seed) − .5`，加到颜色上；按亮度加权（暗部多/少）更像胶片；两个均匀 hash 之差得到三角分布，比单个更柔 | 与色调映射合一遍 6.3 ms |
| 晕影 | `smoothstep(outer, inner, length((uv−.5)·aspect))` 乘上去；在线性域乘才不会把暗角染灰 | T0 |
| 色调映射 | Reinhard `c/(1+c)`、ACES 拟合、AgX；只在输入超出 [0,1]（HDR 目标、叠加泛光后）时才有意义 | T0 |
| 镜头畸变 | 径向多项式 `f = 1 + k1 r² + k2 r⁴`（角上 r=1），`uv' = .5 + (uv−.5)·f/zoom`；k1>0 桶形、<0 枕形；R/B 用 `(1∓disp)·f` 做边缘色散 | 7.9 / 2.1 ms |
| 扫描线、故障切片 | `sin(y·count + phase)`；故障按 `floor(t·rate)` 时间桶 hash 出哪些横切片错位 | T0 |

- 故障的"时间桶"是 t 的函数，每帧内容由桶号决定，可以乱序求值；这和"按秒分桶的纹理缓存键"（compositing.md §2）不是一回事。
- 镜头畸变的桶形会把边推出画面，`zoom>1` 拉回；出界处给一个明确的边色，别让 CLAMP 拉出条纹。

## 3. 多遍：泛光、halation、变形镜头拉丝、模糊与景深

**积木**：
- **亮部提取**：`c · smoothstep(thresh, thresh+knee, max(r,g,b))`（或亮度）。4.2 ms（半分辨率目标）。
- **降采样**：4 点双线性取样（= 4×4 盒式平均）比直接用低分辨率目标线性取样少闪烁。
- **可分离模糊**：9 tap 二项式一维核，横竖各一遍；`u_dir` 是每 tap 步长。全分辨率一遍 13.7 ms。
- **叠回**：`src + amount·tint·mix(glow, luma(glow), mono)`，在线性域相加。

| 组合 | 接法 | 整条链 |
|---|---|---:|
| 泛光 | 提取(½) → 降采样(¼) → 横模糊 → 竖模糊 → 叠回 | rgba16f 17.7 / 4.9 ms；rgba8 11.0 / 3.2 ms |
| halation（高光外圈红晕） | 同一份提取 → 小半径模糊 → 叠回时 mono=1、偏红 tint、减去 `ring·亮部` 只留外圈 | 结构同泛光，没单独计时 |
| 变形镜头横向拉丝 | 提取到扁目标（如 `scale:[0.5, 1/16]`）→ 只做横向模糊三遍，步长 1 → 3 → 9（每遍覆盖约 9 倍） → 叠回 | 12.7 / 3.6 ms |
| 经 2D 中转的泛光 | 每遍一个 `createShaderLayer`，`drawTo` 进离屏 2D 再上传 | 每次中转约 5 ms；好处是每遍可单独 `pixels()` 检查 |

- 半径靠降采样换：¼ 分辨率上一遍 blur9 步长 2 ≈ 全分辨率 72 px 跨度，成本是全分辨率一遍的 1/16。半径太大、分辨率太低时亮部出方块光斑。
- 多级金字塔（Jimenez 2014 / UnrealBloomPass 的做法：13 tap 下采样 × N 级，3×3 帐篷上采样逐级加回）在大半径下更干净，代价是多几遍。
- HDR 中间目标（rgba16f）每条链多约 7 ms（全分辨率）；值得付的时候是阈值 > 1 或多次叠加会截断时。
- 多个效果共用一份提取（泛光和 halation），省一遍全屏。
- 这些都是加法合成，假定底层不透明；要叠在透明层上，先合到底色再过链。
- **2D 模糊**：`ctx.filter='blur(Npx)'` 在半径 4–48 px 都约 13–16 ms，结果可重复，普通高斯模糊用它最省事。着色器 25 tap 全分辨率 41 ms，¼ 分辨率 2.9 ms。
- 2D 路线的"景深"只能按遮罩分层模糊（前景层、背景层各模糊不同半径再合）；按逐像素深度的景深见 three-post.md。

## 4. 风格化

| 效果 | 原理 | 代价 |
|---|---|---:|
| 半调 | 旋转网格（网角 θ）上每格一个圆点，面积 ∝ 1−亮度，即半径 `∝ sqrt(1−L)`；**查本格加 8 邻格**，暗部大点跨格才不会被截平；点边用 `smoothstep` 羽化 1 px | 27.6 / 7.0 ms（9 次采样） |
| 有序抖动 | 8×8 Bayer 阈值矩阵 `(B(x,y)+.5)/64 − .5` 乘 spread 加到颜色上，再量化到调色板最近色（sRGB 欧氏距离）；可往白噪声混 | 7.5 / 2.0 ms |
| 像素化 | `uv' = (floor((px−origin)/cell)+.5)·cell`；取格心一点或格内 4 点平均 | 8.7 / 2.4 ms |
| Sobel 描边 | 3×3 亮度梯度 `|G|` → `smoothstep(thresh, thresh+soft)` → 线色；取样间距越大线越粗越"晕" | 13.9 / 3.6 ms（9 次采样） |
| Kuwahara（油画感） | 四个象限各算均值与方差，取方差最小的象限均值：平涂、保边 | r=2：60.9 / 15.5 · r=4：156 / 39 · r=6：301 / 73 ms |
| ASCII | 每格取亮度，按墨量从 N 个字形里挑一个；字形可以是着色器里编的点阵（不依赖字体），或随片字体画成的图集再查表 | 6.5 / 1.8 ms（点阵版） |

- **Kuwahara 是成本悬崖**：∝ 4(r+1)²，r=4 全分辨率 156 ms，是截图的 3 倍。写法上每圈同时取 4 个对称点，比在 −r..r 双循环里用四个 if 分象限快约 2 倍。半分辨率往往足够（夹具 360×480 格子 r=4 观感已明显）。
- 抖动的 spread ≈ 调色板相邻色间距时过渡最平滑；小了出色带，大了满屏噪点。
- 像素化取格心一点时，细线按落点整格出现或整格消失，随运动闪烁；取格内平均则糊成带。
- ASCII 用真字体字形要把字画进图集，图集用的字体要随片打包、过字体来源门（kernel.md）。
- 可用的库（如需）：lygia 有 `filter/`（kuwahara、sobel、各种模糊）和 `color/dither`；pmndrs postprocessing 有现成 Effect，但见 three-post.md 关于其内部时间的说明。

## 5. 调色

- **lift / gamma / gain**（在反预乘颜色上）：`c·2^exposure` → `gain·(c + lift·(1−c))` → `c^(1/gamma)` → 按亮度插值调饱和度。恒等值是 lift 0 / gamma 1 / gain 1 / exposure 0 / sat 1——这是数学上的"不变"，不是推荐值。7.4 / 1.9 ms。
- **3D LUT**：WebGL2 用 `sampler3D` 硬件三线性（9.0 / 2.4 ms）；WebGL1 把 n³ 摊成宽 n²、高 n 的 2D 条带，b 方向手工在两片之间插值（7.7 / 2.1 ms）。fxchain.js 导出 `parseCube(text)`（只认 `LUT_3D_SIZE` 与 [0,1] 定义域，其余抛错）和 `cubeCanvas(cube)`（条带画布）。
- 两条路同一 17³ LUT 实测逐通道最大差 1/255、平均 0.073/255。条带只有 8 位：暗部陡曲线会出色阶断层；3D 纹理存 16 位浮点。
- LUT 和 LGG 都假定输入在 [0,1]；接在 HDR 后面先做色调映射，否则 > 1 的部分被截。
- LUT 文件放片子 `assets/`，在 `window.ready` 里 fetch 完再解析；从哪找见 film-assets。

## 6. 对细线与小字的影响（夹具 360×480 格里的 1px / 2px 线）

| 效果 | 细线怎么样 | 代价换算 |
|---|---|---|
| 半调 格宽 9 | 1px 线并进网点，只剩一条略深的点带；小字不可读 | 要保留的字压在半调层之上另画 |
| 抖动 格宽 3 | 1px 线断成虚线，2px 线基本连续 | 线宽 ≥ 抖动格宽才连续 |
| 像素化 格宽 12 | 间距 9px 的六条线并成两条糊带 | 字号要 ≥ 数个格宽 |
| Sobel 描边 | 每条线变成两条边线 | 已经是线稿的内容再描边就是双线 |
| Kuwahara r=4 | 1–2px 线几乎被抹掉 | 宽度 < r 的线和笔画都会消失 |
| 镜头畸变 | 线弯曲，边缘出 R/B 色边 | 小字在画面边缘会发虚发彩 |
| 色差、颗粒 | 把细边拆成错位彩色重影 + 逐像素噪声，经 H.264 读作发虚 | 竖版 1080 宽下细线受影响最大；判断看全分辨率静帧和编码成片 |
| LGG / LUT / 泛光 / 拉丝 | 线保持，只改颜色；泛光会吃掉亮底上的一部分线 | — |

## 7. 没做的

- CMYK 四色分版半调（四个网角各一次）；误差扩散抖动（Floyd–Steinberg 是串行算法，可用蓝噪声纹理替换 Bayer）；各向异性 Kuwahara（沿结构张量的椭圆核，比经典版贵数倍）。
- halation 链没单独计时；Metal 后端下的耗时与像素差没测。
