# 踩过的坑（坑 → 根因 → 对策）

这里收集的是还没有沉淀进各个门判断标准的实战问题。遇到症状先查 `kernel.md` §5；本文针对的是"门失败了或成片看起来不对，但原因不在契约字面上"的那一类情况。
每一条都是代价说明，不是风格规定。

## 光栅与上下文状态（门 1a / 2 / 4 / 5 红，但 seek 里没读时钟也没随机）

| 坑 | 根因 | 对策 |
|---|---|---|
| 棋子等小贴图缩放绘制时，乱序求值会差一个色阶 | 缩小贴图会走 mipmap 或降采样缓存，而缓存建立在第一次绘制它时的尺寸上，所以结果取决于求值历史；上面再叠一层 `multiply` 混合的灯光层，会把这一个色阶放大成可见的色差 | 在加载期按尺寸分档预先烘焙一组 low 贴图（缩小版），seek 里按目标尺寸挑最接近的一档，不现场缩放；暗部改用暖黑色遮罩（普通 alpha 叠色）代替 multiply 灯光层 |
| 线帽、虚线、阴影、`globalAlpha` 时有时无 | `lineCap` / `setLineDash` / `shadowBlur` / 变换等上下文状态从上一帧遗留下来；按顺序渲染时恰好正确，乱序就出错 | seek 开头调用 `ctx.save()`，结尾调用 `ctx.restore()`（或者每帧显式重设用到的全部状态），不依赖"上一帧已经设置过" |
| 离屏层经 `drawImage` 缩放后，像素与上一帧相关 | `imageSmoothingQuality = 'high'` 在 Chromium 里走的是带历史状态的缩放路径 | 改用 `'medium'`（或 `'low'`）；film-motion 转场用的离屏层同理（`kernel.md` §5） |
| DOM + CSS3D 场景，门 1a/2/5 偶尔失败 | Chromium 为变换层选择光栅缩放比例时有滞回：同一个 t，沿用旧节点和新建节点光栅化出来的结果不同 | 每次 seek 克隆一份 `#stage` 模板替换旧节点（freshStage 写法）；纯平面元素不要开启 `preserve-3d`，只在确实需要透视的那一层开启 |

## 加载、浏览器、编码

| 坑 | 根因 | 对策 |
|---|---|---|
| 缺字或字体族名拼错，渲染完才发现用的是回退字体 | `loadFonts(...).catch(() => {})` 把字体保障逻辑抛出的错误吞掉了 | 让错误抛出来，`window.ready` 就应该失败；preflight 的 fonts 项专门检查这种写法 |
| 新安装或新拷贝的浏览器渲染出开头若干白帧，render 仍报 ✓ | 这是旧版 headless shell 首次启动时的已知行为（`browser.mjs` 的注释里有实测记录） | 新浏览器先空跑一次；交付时走 deliver（门 5 会与渲染清单对账） |
| 同样的帧，两台机器编码出的 mp4 字节不同 | x264 的线程数会改变码率控制和切片方式，从而改变输出 | 把线程数固定在 film.json 的 `renderer.x264Threads`，比较像素而不比较 mp4 字节 |
| 手机上传不上去，或者播放出来是旧版的声音 | 上传上限是 30MB；手机只播放默认音轨 | 用 `deliver --phone`（输出 720p，按时长反算码率，并复核文件大小）；对比片用 `deliver --compare <旧.mp4>`，只带新版音轨 |

## 画面内容

| 坑 | 根因 | 对策 |
|---|---|---|
| 画面里的 Lua 片段有语法错误，被懂行的观众截图指出 | 屏幕上的代码被当作"美术素材"，没有人实际运行过 | 标上 `data-code-lang="lua"`，preflight 用 `luac -p` 校验（js 用 `node --check`） |
| 代码缩进全部消失 | 代码行用了 `display:flex`，行首空白变成匿名 flex 项被裁掉 | 代码行改为 `display:block; white-space:pre`；preflight 的 code 项会判为失败 |
| 开场两秒没有声音，观众以为片子坏了 | 旁白从 `narrationOffset` 才开始，在此之前没有任何声音 | 开场用环境声、配乐起头或音效填上，避免第一秒是静音；film-narration 的 audiocheck 能测出开场静音 |
