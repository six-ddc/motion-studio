# 运行时、目录与层间数据

## 1. 片子目录

项目目录**相对于当前工作目录**解析，不绑定任何绝对路径，所以 skill 装在哪里都能用。

```
films/<slug>/
├── film.json          画幅、fps、运动模糊、入口、checks（字段表见 film-json.md）
├── scene.html         程序本体，暴露 window.seek(t)
├── runtime/           片内运行时：片子自己写的模块，以及 deliver 冻结进来的套件运行时（建片时是空的、可以不存在）
├── receipt.json       交付收据（deliver 写；accept 只认它，见 api.md）
├── assets/            本片素材（字体、图、音）
├── docs/              可选：配方写的文档（brief、style_guide……）
└── out/               一切产出：渲染帧、音频、静帧、自检图、成片；out/.render/ 是渲染清单、分片缓存、加载记录
```

**产出一律写进 `out/`，中间产物也写进 `out/`**，不放系统临时目录，方便人事后翻出来看。
其他 skill 的文件（script.json、narration.json、look.json、docs/ 下的各份文档）由各自的 skill 定义，内核不管。

## 2. 运行时：在线挂载、交付冻结

scene.html 里写 `import './runtime/motion.js'`，不需要往片子里拷文件。仓库里唯一的服务器 `lib/serve.mjs` 按下面的顺序解析 `/runtime/<名字>`：

1. 如果 `films/<slug>/runtime/<名字>` 存在，就用它（**片内优先**）；
2. 否则到已安装的 `skills/film-*/assets/runtime/<名字>` 里找。套件运行时采用**扁平命名**，两个 skill 有同名文件时服务器在启动时就报错。

运行时之间互相 `import './motion.js'` 也走同一张挂载表。服务器会记下本次实际发出的每个运行时（名字、来源 skill、sha256），
写到 `out/.render/runtime.json`；render 还会把同一份清单写进渲染清单的 `runtime` 字段，并把它的哈希并入分片缓存键。

| 阶段 | 片子用的运行时 | 代价 |
|---|---|---|
| 制作中（没有收据） | 片内没有同名文件时，用套件的当前版本 | 套件修了 bug 会立刻生效，但套件的改动也会改变这支片子的像素，所以没交付的片子不算"做完" |
| `deliver` 之后 | 冻结在 `runtime/` 里的那一份（片内优先） | 套件升级不会改变它的像素，也不会修掉它的 bug。要拿到修复，需要改片子（或删掉 runtime/ 里对应的文件）再 deliver 一次 |

建片时不拷贝运行时，是因为拷贝必须在建片那一刻猜"会用到哪些运行时"，而且副本从第一天起就不再跟着套件的修复更新。
在线挂载加交付冻结，把"固定版本"推迟到唯一需要它的时刻，也就是片子交付时。

外部 dev server（只会托管片子目录的那种）不认识挂载表，需要先运行 `freeze.mjs --film <slug>`，把用到的运行时冻结进片子再启动。

**每个提供运行时的 skill** 只需要把文件放在自己的 `assets/runtime/` 下（放在顶层、扁平命名、文件名在全套件内唯一），并在 SKILL.md 里写明
`import './runtime/x.js'` 的用法，不需要写任何拷贝说明。

## 3. 浏览器也得钉

像素由 Chromium 的光栅化决定。因此 `package.json` 里 playwright 固定到确切版本（不用 `^`），render 会把渲染时的 Chromium 版本、构建形态和启动参数
记进 `film.json renderer`，启动参数固定为 `--font-render-hinting=none`。整个套件启动浏览器只有 `lib/browser.mjs` 的 `launchBrowser()` 一个入口，
所以渲染、门、静帧、评审都在同一个条件下运行。实测结论如下（数字见 `render.md`「渲染器钉版本」）：

- 在**版本**这个维度上，几个版本的成片逐字节相同，或差异低于可见阈值。固定版本是为了**可复现性和分片缓存**，不是为了视觉保真。
- 在**构建形态**（headless shell 与完整 Chrome）这个维度上，`browser.version()` 返回同一个字符串，但渲染差异肉眼可见。根因是**字体没有随片打包**，
  两种构建回退到了不同的字形；打包字体之后差异降到亚像素级。所以根本解法是打包字体（kernel.md §2），固定构建形态只是绕开症状。
- 没有测过的维度：换到 Linux（FreeType 字体栈）。`--font-render-hinting` 在 macOS 上不起作用，它是为 Linux 预留的保险。
- **后端**这个维度：默认是软件的 SwiftShader；film.json 可以声明 `"backend": "gpu"`，让 WebGL 改走本机硬件 GPU。这样像素跟着显卡和驱动走，指纹里多记 `backend`、`gpu`、`gpuDriver`，变了就告警。声明了 gpu 而本机起不来时报错退出，不退回软件。所有工具读同一个声明，见 `render.md`「渲染后端」。

测量这件事时出错过三次，每次都是测量手段干扰了被测对象：比较的是 PNG 字节而不是像素；`getImageData` 回读改变了后续帧；
测的是渲染管线并不使用的那个二进制。编写门的人要注意：**先确认测的是生产路径上的那个东西，再确认测量手段会不会改变它。**

## 4. 两种"脚本"，不能混

| | 放哪 | 谁执行 | 例子 |
|---|---|---|---|
| **Agent 工具** | `<skill>/scripts/` | 模型通过命令行调用 | `render.mjs` `seamcheck.mjs` |
| **影片运行时** | `<skill>/assets/runtime/` | 浏览器，由 `scene.html` import | `motion.js` `layout.js` `anchors.js` |

Agent 工具必须满足以下要求（共享实现全部在 `film-core/lib/`，见 api.md）：
- 能从任意 cwd 调用，路径靠 `import.meta.url` / `__file__` 自行解析。films/ 的位置按优先级取 `--films-dir`、`$FILMS_DIR`，都没有时从 cwd 向上查找。
- 统一使用 `--film <slug>` 接口；只有一支片子时可以省略。
- 命令行解析走 `lib/cli.mjs`（Python 走 `lib/film.py` 的 `parser()`）：`--help` 返回 exit 0；遇到未知参数、缺值、多余的位置参数时返回 exit 2。
- 失败时 **exit code 非 0，并在 stderr 里说清原因**。缺少前置条件时直接报错，不要猜。
- 启动服务器只用 `lib/serve.mjs`，启动浏览器只用 `lib/browser.mjs`；跨能力调用用 `capability(name)`，不写指向其他 skill 目录的相对路径。

运行时里不能出现 Node API（它运行在浏览器里），也不能出现 `Math.random` / `Date.now` / `setTimeout`（kernel.md §2）；随机数一律用 `rand.js`。

## 5. 层与层之间暴露的数据：时间、状态、空间

动画层产出的是"某个东西在某一刻画在屏幕的哪个位置"，字幕、特效、音效、评审、分镜断言都要在那个位置或那个时刻做事、做判断。
**场景是这些数据的唯一产出方**，其他层只读取，不各自重新推算。数据分三条通道，各自回答一个问题：

| 通道 | 回答的问题 | 数据形状 | 由谁产出 |
|---|---|---|---|
| **时间** | 某件事**什么时候**发生 | `vo.at('字')`、`vo.span(id)`（film-narration 运行时）、`window.MARKS = [{label,start,end,load,word}]`；可选 `window.events()` → `[{t,kind,anchor?,v?}]` | 场景根据 narration.json 或自己的时间轴计算 |
| **状态** | 任一时刻机制**处于什么状态** | `window.probe(t)` → `{曲线名: 数}` | 场景，与 seek 共用同一个取状态函数，**不绘制** |
| **空间** | 某个有名字的东西**画在屏幕哪里** | `window.anchors(t)` → `{ t, items: { 名: {x,y,w,h,cx,cy,n,…} } }` | 场景**在绘制路径上**登记（`runtime/anchors.js`） |

消费方（评审的遮挡门和出画门、分镜断言、音效的声像、motionprint 等）各自在自己的 skill 里写明读取哪条通道。渲染器不读这三条通道。

## 6. 空间锚点（`runtime/anchors.js`）的语义（硬约束）

1. **在绘制路径上当场登记，不另外计算一遍。** 在绘制某个物体的那一行顺带调用 `A.ctxRect('黄车', ctx, x, y, w, h)`
   （用 ctx 的**当前变换**映射局部矩形，绘制时用的就是这个变换），或者调用 `A.box(name, 屏幕像素框)`。
   不要写"根据状态重新推算屏幕坐标"的函数，因为自己重算又自洽的断言只能验证它自己（实测：probe 报告 0 盏灯，而画面上有 140 个红像素）。
2. **同名多次登记时取外包框。** 一辆车分三笔画，登记出来是一个框；"灯团"是所有亮灯车辆的外包框。哪些物体算成员由场景按自己的阈值决定，
   这个阈值和它绘制时用的阈值是同一个常量。
3. **坐标归一化到画面宽高（x/W, y/H），不裁剪。** 出画的部分表现为 <0 或 >1，出画门要靠它判断"切掉了多少"。换画幅、截图缩放都不影响结果。
4. **是 t 的纯函数。** `install(draw)` 在每次 seek 开始时清空登记表、结束时封表；在 seek 之外登记或读取会直接抛错。
   同一帧里后绘制的层可以用 `A.get(name)` 读取先绘制的层登记的框，这属于同一帧内的数据传递，不是跨帧状态。
5. **只暴露数据，不负责布局。** 没有"避让""默认位置""吸附"之类的功能。字幕放在哪、特效贴在哪由每支片的 style_guide 决定；
   契约只保证"各层看到的是同一个位置"。

锚点用独立的 `window.anchors(t)`，而不是作为 `probe(t)` 的保留键，原因有三点：probe 的定义是"不绘制"，而锚点按第 1 条必须出自绘制；
遮挡门要求锚点"和截到的像素、和拦截到的文字出自同一次绘制"，`anchors(t)` 本身就是一次 seek；两者的命名空间也不同（曲线名与物体名）。
代价是 `anchors(t)` 要做一次完整绘制，比 probe 贵，但比截图便宜一个数量级（1920×1080 下实测约 16ms/帧，截图加数像素约 158ms/帧）。

**已知盲区**：锚点只说明"画在哪"，不说明"看不看得见"（被遮住或 alpha 为 0 时框照样存在，要判断可见性需要用像素断言）；
如果登记在错误的那一笔上，所有锚点门都会照常通过；顺序与倒序比对抓不到会饱和的累积泄漏；
舞台 canvas 没有铺满画面时，锚点（按 canvas 归一化）和文字框（按视口归一化）不在同一个坐标系里。
