# 三条策略：实现说明

目录：1 为什么缓存不违反契约 · 2 闭式解的通用技巧 · 3 定步重放 · 4 预烘焙 · 5 混用

选型判据和实测代价表在 SKILL.md；各效果的公式在 `effects.md`；浏览器内多种规模的实测见仓库 docs/verified/film-physics.md §3。

## 1. 为什么缓存不违反契约

契约禁止的是"会影响输出的跨帧状态"，判断标准来自外部观测：同一个 t 求两次结果一致，乱序求值与顺序求值结果相同。
定步重放的 `stateAt(t)` 在**定义上**等于 `stepⁿ(init())`，n = round(t·fps)·substeps。只要缓存和检查点只是对这个定义的忠实加速（恢复出来的状态与"从头一步步走到这里"逐位相同），输出就仍是 t 的函数。
有三类错误会破坏这种等价，physcheck 都能检出：检查点存引用而不是副本（A）、在 state 之外用顺序推进的随机数（B）、往回 seek 时不回退状态（C）。

## 2. 闭式解的通用技巧

闭式解 = 每个量写成 `(t, 只读参数) → 值`，没有循环变量跨帧携带。几条反复用到的技巧：

- **计数器式随机**：第 i 个体的第 k 个属性取 `hash01(seed, i, k)`，与之前求值过多少个数无关。只算当前在场的体，开销 O(在场数)；顺序推进的随机数要从第 0 个抽起，seek 到 t 是 O(总发射数)。
- **事件也是参数**：命中时刻、出生时刻都是加载期就确定的数组，或由闭式公式直接解出（触地时刻是二次方程的根）。屏震、闪白、压扁都是"对事件求和/取最大"的函数。
- **几何级数定位**：重复过程（弹跳、周期性发射）如果每轮时长构成等比/等差数列，用对数或除法 O(1) 算出"当前是第几轮"，不逐轮累加。
- **循环**：属性按 `i mod N` 取（N = rate·L 必须是整数），t+L 时刻的在场集合就是 t 时刻集合整体平移 N 个下标，年龄和属性都相同，两帧逐像素相同。预热（片头就是稳态）允许负下标。
- **固定迭代次数**：需要数值求解时（开普勒方程、反函数），迭代次数写死，不用"误差小于 ε 就停"——后者在不同 t 上走的步数不同不算错，但写死更容易保证跨环境一致。
- **位移场代替力场**：没有闭式积分的力（湍流、涡流）可以改成"位置 = 闭式主运动 + 噪声位移(年龄)"，代价是只能摆动，做不出累积漂移和卷曲；真要平流走 ②。

## 3. 定步重放（`assets/runtime/replay.js`）

```
stateAt(t):
  n = round(t·fps)·substeps
  if n < curN: k = floor(n/every)·every; cur = clone(cps[k]); curN = k
  while curN < n: step(cur, dt, curN); curN++; if curN % every == 0: cps[curN] = clone(cur)
  return cur
```
- 检查点只在第一次顺序经过时保存，所以不超过已到达最大步数的每个 every 整数倍都有检查点。开销：顺序每帧 O(substeps)，回退 O(every)，冷启动 O(n)。内存 = 检查点数 × state 大小（300 球约 4×300×8 B，约 10 KB/个）。
- substeps：碰撞或约束越硬，步长越细。刚体圆和布料 4（dt=1/240），boids 1 就够。**改 substeps 会改变结果**（离散化变了），定稿后再改要重看。
- 事件（碰撞时刻）要存进 state（定长环形缓冲，`eventRing`），才能随检查点一起回退。
- t 是仿真时间，fps 是仿真时间里的查询栅格。影片时间与仿真时间不同时调用 `stateAt(S(t))`，检查点不用改，见 `timemap.md`。
- "开关"类一次性事件必须在 state 里或由步号判断（`t >= p.t && t < p.t + p.dur`，t = 步号 × dt）。闭包里的 `fired` 标志在回退到置位前的检查点时不会复位：乱序和倒序都判红；冷启动一旦跑过扰动时刻，整支片子里扰动都不会再发生。
- 写 state 时优先用 typed array：`clone` 就是几个 `slice()`，便宜且不会漏字段。对象数组 + 深拷贝最容易漏掉某个嵌套字段。

## 4. 预烘焙（`scripts/bake.mjs` + `assets/runtime/baked.js`）

- 文件格式：`<name>.json` 是文件头（sim、opts、fps、substeps、frames、n、fields），`<name>.bin` 是 Float32，帧优先排列：`data[(f·fields + k)·n + i]`。
- `loadBake` 校验数据长度，不符抛错。`frame(t)` 返回零拷贝 subarray；`lerp(t)` 帧间插值。
- 文件大小 = (D·fps+1) × fields × n × 4 字节。超过几十 MB 时三条出路：只存可见的体、降为 Int16 定点（1/16 像素精度足够）、拆成分段文件。本运行时没实现这些压缩。
- 也可以不用 bake.mjs：任何能产出"帧 × 体 × 字段"数组的离线过程（Python、Blender 导出、另一个引擎）都能写成同一格式，`loadBake` 只认文件。

## 5. 混用

一个场景可以同时用三条。例如主体 200 个碰撞块用 ③，背景 5000 粒尘埃用 ①，屏震用 ① 的事件求和函数；命中时刻可以从 ③ 一起导出（`pack` 里多加一个事件字段），也可以在烘焙脚本里另存一份 JSON 作为事件表。
