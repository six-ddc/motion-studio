运行时代码在 `assets/runtime/chain.js`（`sims.js` 也转出了 `chain`，所以可以用 `bake.mjs --sim chain`）。本页的数字来自测试夹具 `_test-physics/chain-regimes.mjs`（原始输出在 `out/chain-regimes.txt`，来历见仓库 docs/verified/film-physics.md §6）。

## 1. 什么时候该用、什么时候不该

一串单元排成一列，**每个单元只看前面那一个**，按间距调整自己的速度。刹车、起步、拥挤这类信号会**逆着运动方向**往后传，传递过程中被放大或衰减。

| 现象 | 用什么 | 为什么 |
|---|---|---|
| 幽灵堵车、走走停停、红绿灯起步波、队伍一截一截地往前挪、列车或货运车厢的松紧波 | `chain()` | 波速和振幅是**涌现**出来的，取决于参数，必须算出来 |
| 多米诺式逐个点亮、人浪、接力、固定延迟的传递 | **策略 ① 闭式解**：第 i 个在 `t0 + i·δ` 时触发 | 延迟是常数时没有动力学可言，写仿真只是白白付出 O(t) 的代价 |
| 二维人群、会绕行、会超车换道 | `boids` 或自己写 | 一维链假设单元的先后顺序永远不变 |
| 单元之间会碰撞反弹 | `balls` / rapier | 链里的"安全项"作用是防止碰撞，而不是碰撞后反弹 |

## 2. 模型与参数

采用最优速度模型（OVM，Bando 等 1995）：

```
dv_i/dt = a·( V(h_i) − v_i )          h_i = x_{i+1} − x_i（车头到车头）
V(h) = V0(h) − V0(hs)，V0(h) = (vmax/2)·(1 + tanh((h − hc)/w))，hs = unitLen + stopGap
```
可选的**运动学安全项**（`safety`，默认开启）：当单元正在逼近前一个单元（v_i > v_{i+1}）时，减速度至少取"恰好在前者的速度上停住"所需的值 `(v_i² − v_{i+1}²) / (2·(净距 − safeGap))`。

| 参数 | 物理含义 | 单位 |
|---|---|---|
| `h0`（环形时等于 L/n） | 平衡状态下的车头间距，即密度的倒数 | 长度 |
| `hs = unitLen + stopGap` | 停住时的车头间距 | 长度 |
| `V(h)` | 间距为 h 时想开多快；`vCruise = V(h0)`，`vFree = V(∞)` | 速度 |
| `a` | 敏感度，等于松弛时间的倒数 | 1/秒 |
| `V'(h0)` | 在平衡点上，间距每增加 1 个单位，期望速度增加多少 | 1/秒 |
| `safety / safeGap / safeOnset` | 防止单元互相穿过；`safeOnset` > 0 表示所需减速度超过这个值时安全项才介入 | — / 长度 / 加速度 |
| `perturb` | `[{unit, t, dur, decel}]`：从仿真时刻 t 起持续 dur 秒，该单元至少以 decel 减速 | — |
| `leader` | 直路上最前面那个单元的"虚拟前车" `(tSim) => ({x, v}) | null`，必须是仿真时间的纯函数 | — |
| `noise / seed` | 每一步给每个单元加的加速度噪声 `noise·(2·hash01(seed, 步号, i) − 1)` | 加速度 |

`hc`、`w` 没有直接的物理含义，手动扫参的代价是几十组试错。可以改用 `chainDesign({ h0 或 L/n, unitLen, stopGap, vCruise, vFree, a, kappa })` 按物理量反解出它们，它会同时返回线性稳定性分析结果。

**单位**：模型对长度和速度的整体缩放严格不变（米制和 ×100 的像素制算出的成堵时间在 0.1 s 内相同），但 `safeGap`、`minDen`、`stopV` 本身是长度或速度，换单位时要一起换。

## 3. 两个无量纲数：一个管"堵不堵"，一个管"撞不撞"

```
κ  = 2·V'(h0) / a            失稳裕度
A* = a·(h0 − hs) / V(h0)      余量比 = 富余净距 / 一个松弛时间里开过的距离
```
`chain().analysis` / `chainDesign().analysis` 会给出 `kappa`、`slack`（即 A*）、`growth`、`efold`。

**会不会堵由 κ 决定，线性理论给出的是精确结论**：κ > 1 时均匀流失稳。`growth` 是特征方程 `σ² + aσ = aV'(e^{iθ} − 1)` 在环上所有模态 θ_k = 2πk/n 中最大的实部，`efold = 1/growth` 是扰动放大到 e 倍所需的时间。实测结果（关闭安全项）：

- κ < 1 时，扰动全部衰减，180 秒内从未成堵。
- κ 刚超过 1 时，理论上失稳，但 efold 长达几百秒（κ=1.1 时为 211–422 s），在片子的时长里等于不会堵。
- 成堵时间（速度极差达到 V(h0) 的一半）约为 **0.7–2 倍 efold**。

**会不会撞由 A\* 决定，边界来自实测**：纯 OVM（`safety:false`）失稳之后，**A* ≤ 1.15 时全部相撞**（单元穿过前一个单元），**A* ≥ 1.38 时全部不撞**，两者之间没有样本（共 40 组：4 种几何加上像素单位，κ = 2/3）。直观理解是：一个松弛时间里开过的距离比富余的净距还长，单元就来不及反应。

**安全项的代价**：开启后永远不会相撞（下表中开启时的最小净距 ≥ 1.15 m），但它本质上是一个速度差阻尼项，**会把失稳门槛往上推**：a=1 时要 κ ≈ 4 才会堵，a=2 时 κ=1.6 已经不堵。线性理论只对 `safety:false` 成立；遇到"κ > 1 却不堵"，多半是因为安全项开着。

- a=1 时 `chainDesign` 会拒绝 κ < 1.25（在这组几何下，tanh 形的 V 在 h0 处的斜率不可能低于 0.625/s）。报错信息会给出下限，并提示该调整哪个量（加大 a、拉开 h0−hs、让 vCruise 更接近 vFree）。
- `safeOnset: 1`（所需减速度超过 1 m/s² 时才介入）是一个中间档：a=1、κ=2 也能成堵（成堵 23.9 s），但最小净距只剩 0.14 m（见 `chain-regimes.txt` 中的 `on@1` 行）。
- 堵速：真实环形道路实验的量级是 −15～−20 km/h，a 越大，堵团往后移动得越快。`analysis.waveSpeed` 是**线性**长波波速，而成堵之后堵团的速度是非线性的，两者相差 2–3 倍，需要用 `chainProbe` 实测。

## 5. 默认值与两组实测可用的配方

| 配方 | 写法 | 实测结果（基准同上，从扰动后起算） |
|---|---|---|
| **默认** | `chain({ perturb })` | 成堵 9.5 s，首停 23.7 s，最小净距 1.15 m，堵速 −17.4 km/h。A*=0.75，依靠安全项避免相撞 |
| 纯 OVM，可用线性理论预测 | `chain({ ...chainDesign({ a: 2, kappa: 2 }).params, safety: false, perturb })` | 成堵 7.5 s，首停 25.1 s，最小净距 0.76 m，堵速 −19.7 km/h。A*=1.48 |

`chainDesign()` 不传参数时，使用默认几何加 a=1、κ=4（和默认 `chain()` 的 V 只差在 vFree 精确取 11.1）。

## 6. 设计流程

1. **定几何和速度**：h0（或 L、n）、unitLen、stopGap、vCruise、vFree。这些值来自 facts.md，而不是靠调参得到。
2. **定 a，算出 A\***：A* ≥ 1.4 时可以关闭安全项，线性理论的预测就是准的；A* < 1.4 时必须开启安全项，κ 按第 4 节的表格选取。
3. **定 κ**：按"片子允许多久之后成堵"来选。关闭安全项时，成堵时间约为 0.7–2 倍 efold；开启安全项时查表。
4. **无头试跑**：`chainProbe(opts, { T })` 返回 `crashed / minGap / firstJam / firstStop / jamSpeed`，22 个单元跑 180 s 约需 50 ms。结果不满足要求时，回到第 2 或第 3 步只调整一个量，不去动 hc/w。
5. **把事件对齐到旁白**：用 `timemap.js` 的 `fitRate` 让 `firstStop` 落在旁白锚点上，见 `references/timemap.md` §5。
6. **声明断言**：在 `window.PHYS.claims` 里写上"不撞""锚点前没停""锚点后停过"，由 physcheck 的 F 组对照真实画面验证（`references/timemap.md` §6）。

## 7. 排队 / 直路

- `ring: false`：x 不取模，0 号单元在最后，n−1 号在最前；最前面的单元跟随 `leader(tSim)`（返回 null 表示前方没有车，按 V(∞) 行驶）。
- `start: 'queue'`：单元首尾相接、静止排列（间距为 hs），开始时 `stopped` 全部为 1。
- 红灯：停止线在 X 处时写 `leader: (t) => (t < tGreen ? { x: X + unitLen, v: 0 } : null)`。默认参数下 12 辆车排队，绿灯亮后每辆比前一辆晚 **1.15 s** 起步（第一辆晚 0.97 s），起步波以约 13.5 km/h 的速度往后传，最小净距 0.50 m（等于 stopGap）。
- 直路上的均匀流扰动：κ=4、a=2 时，40 辆车里扰动越往后传越大（各处的最低速从最前往后依次为 5.95、4.27、1.55、0.49、0.25 m/s，大约从第 20 辆开始被逼停）；κ=1.5 时扰动不放大（从第 5 辆起最低速稳定在 7.1–7.5 m/s）。对应的命令在夹具 `chain-regimes.mjs` 的末段。

## 8. 代价

| | 数字（Node，`dev/film-physics/bench.mjs --sim chain`，dt=1/240，检查点间隔 1 s） |
|---|---|
| 每步耗时 | n=300 时 0.031 ms；1000 时 0.052 ms；3000 时 0.154 ms |
| 检查点 | 每个约 n × 33 B（300 个单元约 9.7 KiB，3000 个约 96.7 KiB） |
| 最坏情况的乱序 seek | 等于走完 1 仿真秒的步数：n=300 时 7.5 ms，3000 时 37 ms |
| 浏览器（physcheck，22 个单元加绘制，8 s 的片子压进 31.8 仿真秒） | 顺序渲染 0.15 ms/帧，乱序平均 1.19 ms、最大 5.6 ms，冷启动 seek(8) 10.3 ms |

时间加速 W 倍时，顺序渲染每帧要走 W 倍的步数，冷启动要走 S(t) 对应的步数，见 `references/timemap.md` §4。
